# 规格说明

## 背景

AI 路由网关的账号池当前使用底边框 tabs 展示分组，分组管理位于 tabs 右侧独立齿轮；批量禁用和批量删除位于选择工具条；添加入口使用“添加第三方账号”文案，且空分组时移动到空状态中；账号卡片同时提供卡片主体点击和独立编辑图标；搜索框高度和边框样式与启动台不一致。本次调整统一这些入口与现有 SSH 隧道、启动台的交互模式。

## 目标

- [ ] 账号池分组展示和管理入口与 SSH 隧道顶部分组保持一致。
- [ ] 账号批量操作收敛到统一的“更多操作”下拉菜单。
- [ ] “添加账号”与“更多操作”形成稳定的右侧操作区。
- [ ] 移除重复的卡片编辑图标，保留卡片主体进入编辑详情。
- [ ] 搜索输入框样式与启动台搜索保持一致。

## 非目标

- 不改变账号分组、批量禁用、批量删除、单账号移动、启停和删除的后端语义。
- 不新增 OAuth 写入能力，不调整账号类型选择和账号详情表单流程。
- 不修改 Rust、SQLite、Tauri command 或 typed IPC 契约。
- 不调整 AI 路由网关首页、网关密钥、请求日志和设置页签。
- 不抽取跨页面通用组件，不引入新的 UI 依赖。

## 用户场景

### 场景 1：切换和管理账号分组

- 前置条件：账号池已加载至少一个分组。
- 操作：用户通过顶部分组控件切换分组，或打开“更多操作”并选择“管理分组”。
- 预期结果：分组控件呈现 SSH 隧道同款 segmented control；当前组激活态明确；管理分组对话框继续支持新建、重命名、删除和默认组保护。
- 异常结果：分组命令失败时保留输入和当前可用状态，并展示原始命令错误。

### 场景 2：批量操作当前可见账号

- 前置条件：当前分组存在账号，用户可按搜索条件筛选并勾选账号。
- 操作：用户打开“更多操作”，选择“批量禁用”或“批量删除”。
- 预期结果：批量操作只提交当前分组、当前搜索结果中的已选账号；成功后清空选择；删除继续经过确认和确认令牌。
- 异常结果：未选择账号时批量菜单项禁用；命令失败时保留选择并展示错误；取消删除时不请求确认令牌。

### 场景 3：添加账号

- 前置条件：用户位于账号池列表视图，当前分组可以为空。
- 操作：用户点击右侧最末端的“添加账号”。
- 预期结果：打开现有账号类型选择对话框，后续 OAuth/API Key 分流保持不变。
- 异常结果：取消、关闭或按 Escape 后不创建账号，返回当前列表视图。

### 场景 4：打开账号详情

- 前置条件：当前分组存在账号卡片。
- 操作：用户点击账号卡片主要内容区域。
- 预期结果：按持久化 `account_type` 进入对应编辑详情；卡片不再显示独立编辑图标。
- 异常结果：卡片上的选择、移动、启停和删除控件不会误触发详情跳转。

### 场景 5：搜索当前分组账号

- 前置条件：当前分组存在零个或多个账号。
- 操作：用户在搜索框输入名称、地址、认证方式、协议、备注、标签或模型映射信息。
- 预期结果：仅过滤当前分组账号，搜索框外观与启动台一致。
- 异常结果：无匹配结果时展示现有搜索空状态，不泄露其他分组账号。

## 功能需求

### REQ-001：统一分组展示

- 描述：账号池分组切换控件采用 SSH 隧道顶部分组的黑白 segmented control 视觉、间距和激活态；默认组仍固定首位。
- 输入：`GatewayBootstrap.groups`、当前 `activeGroupId`。
- 输出：可横向容纳多个分组的分组切换控件和正确激活态。
- 约束：切组后继续清理不再可见的账号选择；分组缺失时回退默认组。

### REQ-002：统一更多操作菜单

- 描述：移除分组区域独立管理齿轮及选择工具条中的批量按钮，新增始终显示的“更多操作”下拉，依次承载“批量禁用”“批量删除”和“管理分组”。
- 输入：菜单开关状态、当前可见已选账号 ID、`busy` 状态。
- 输出：带正确禁用态的下拉菜单；点击外部或按 Escape 可关闭。
- 约束：未选择账号时两个批量项禁用，“管理分组”仍可用；批量操作执行前关闭菜单；破坏性操作保留现有确认流程。

### REQ-003：保持批量选择与操作语义

- 描述：保留“全选当前可见账号”和已选数量展示，批量禁用/删除只作用于当前分组、当前搜索结果中的已选账号。
- 输入：当前分组账号、搜索结果、选择集合。
- 输出：正确的账号 ID 集合及操作后选择状态。
- 约束：成功后清空选择；失败后保留选择；取消删除时不得请求或提交确认令牌。

### REQ-004：稳定右侧操作区和添加入口

- 描述：搜索框位于操作行左侧；“更多操作”和“添加账号”位于同一右侧操作区；“添加账号”替换“添加第三方账号”文案并始终位于最右。
- 输入：列表视图状态，与当前分组是否为空无关。
- 输出：始终可见的“更多操作”和“添加账号”按钮。
- 约束：窄屏允许整行换行，但两个操作按钮保持相邻且“添加账号”仍为操作区最后一项；移除空状态中的重复添加按钮。

### REQ-005：移除账号卡片编辑图标

- 描述：删除账号卡片独立编辑图标按钮，保留卡片主要内容点击进入编辑详情。
- 输入：账号 ID 和持久化 `account_type`。
- 输出：API Key 或 OAuth 对应详情视图。
- 约束：保留移动、启停、删除和选择控件；这些控件不得触发详情跳转。

### REQ-006：对齐启动台搜索样式

- 描述：账号池搜索输入复用启动台搜索的 Search 图标布局和输入样式。
- 输入：搜索文本。
- 输出：使用 `h-10`、`border-input`、`bg-background`、`pl-9`、`pr-3`、`py-2`、`text-sm` 的输入框，并保持现有过滤结果。
- 约束：保留可访问名称“搜索账号”和现有占位文案；不改变搜索字段集合。

### REQ-007：同步国际化和回归测试

- 描述：同步中英文“添加账号”“更多操作”及必要菜单文案，并更新账号池交互测试。
- 输入：现有 i18n 资源和 Vitest 测试夹具。
- 输出：中英文界面文案一致，测试覆盖新布局和交互。
- 约束：不删除仍被其他功能使用的翻译键；测试不得依赖后端真实环境。

## 验收标准

### AC-001：分组控件对齐 SSH 隧道

- Given：账号池包含默认组和自定义组。
- When：用户进入账号池并切换分组。
- Then：默认组位于首位，分组控件呈现 SSH 隧道同款 segmented control，激活态正确，列表只显示当前组账号且失效选择被清除。
- 验证命令或证据：`npm run test -- src/components/AiRoutingGateway/AiRoutingGateway.test.tsx`

### AC-002：更多操作菜单行为正确

- Given：用户位于账号池列表视图。
- When：用户点击“更多操作”、点击菜单外部或按 Escape。
- Then：菜单正确开关；菜单包含“批量禁用”“批量删除”“管理分组”；无选择时批量项禁用而管理分组可用。
- 验证命令或证据：账号池组件测试断言菜单项、禁用态、外部点击和 Escape。

### AC-003：批量禁用保持可见集合边界

- Given：当前分组账号经过搜索过滤且用户选择一个或多个可见账号。
- When：用户从“更多操作”执行“批量禁用”。
- Then：仅提交当前可见已选账号 ID；成功后清空选择；失败后保留选择并展示错误。
- 验证命令或证据：现有批量禁用 Vitest 用例迁移到下拉交互后通过。

### AC-004：批量删除保持确认边界

- Given：当前分组存在已选可见账号。
- When：用户从“更多操作”执行“批量删除”。
- Then：取消时不请求确认令牌；确认时令牌与当前可见已选集合绑定；成功后清空选择。
- 验证命令或证据：现有批量删除取消、成功和失败 Vitest 用例迁移后通过。

### AC-005：分组管理功能不回归

- Given：账号池存在默认组和自定义组。
- When：用户从“更多操作”打开“管理分组”并执行新建、重命名或删除。
- Then：现有命令参数、默认组保护、删除迁移、错误保留输入和回退行为保持不变。
- 验证命令或证据：现有分组管理 Vitest 用例改用新入口后通过。

### AC-006：添加账号始终位于最右

- Given：当前分组有账号、无账号或搜索无结果。
- When：用户查看账号池列表操作行。
- Then：“更多操作”和“添加账号”始终显示在右侧操作区，“添加账号”为最后一项且点击后打开现有账号类型选择；空状态不出现重复入口。
- 验证命令或证据：组件测试分别覆盖非空分组、空分组和筛选空状态。

### AC-007：卡片详情入口去重

- Given：账号池同时存在 API Key 和 OAuth 账号。
- When：用户查看卡片并点击其主要内容。
- Then：不存在名为“编辑”的图标按钮；两类账号分别进入正确详情；卡片其他操作继续可用。
- 验证命令或证据：更新“卡片主体和编辑按钮”测试为仅验证卡片主体与其他操作。

### AC-008：搜索样式和行为一致

- Given：账号池当前分组包含多个账号。
- When：用户查看并输入搜索条件。
- Then：输入框类名与启动台搜索基准一致，仍只过滤当前分组且无跨组泄露。
- 验证命令或证据：组件测试断言样式类和现有搜索结果。

### AC-009：质量门禁通过

- Given：实现及测试已完成。
- When：执行前端质量检查。
- Then：账号池定向测试、完整测试、lint 和 build 全部通过。
- 验证命令或证据：`npm run test -- src/components/AiRoutingGateway/AiRoutingGateway.test.tsx`、`npm run test`、`npm run lint`、`npm run build`

## 数据与接口

- 数据结构、接口、兼容字段和错误码：不新增或修改数据结构、Tauri command、typed IPC facade、错误码和确认令牌协议；继续使用现有 `GatewayBootstrap`、账号批量命令与分组命令。

## 兼容约束

- 现有行为必须保持：默认组首位、切组和刷新回退、当前可见选择边界、批量成功/失败状态、删除确认令牌、分组管理语义、账号类型分流、卡片移动/启停/删除、搜索字段集合。
- 迁移兼容窗口：无数据迁移；界面在同一版本内直接替换旧入口。

## 安全约束

- 权限边界：不扩大 OAuth release gate，不新增凭据或账号写入入口。
- 敏感数据处理：不读取、展示或记录账号凭据；API Key 处理保持现有详情页约束。
- 路径和输入校验：继续由现有前端状态和后端命令校验分组名、账号集合及确认令牌。

## 错误与边界

- 非法输入：无选择时禁止批量命令；空分组名和默认组重命名/删除继续由现有逻辑阻止。
- 空数据：空分组、搜索无结果时保留稳定操作行和对应空状态。
- 超时或外部依赖失败：命令失败展示原始或现有格式化错误，不用刷新失败覆盖原始错误。
- 重试和幂等：失败后保留可重试状态；`busy` 期间禁用会重复提交的菜单项和按钮。

## 迁移发布回滚

- 发布步骤：作为常规前端变更随应用版本发布。
- 迁移步骤：无数据或接口迁移。
- 回滚触发条件和操作：若菜单无法访问关键操作、批量集合越界或详情入口失效，回滚本次前端与测试提交；无需回滚数据库或后端。
