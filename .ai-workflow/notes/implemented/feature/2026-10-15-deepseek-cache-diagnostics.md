# Agent Note: Native DeepSeek Cache Accounting, a Content-Free Observer and a Bounded Comparison

Status: implemented

English | [中文](2026-10-15-deepseek-cache-diagnostics.zh.md)

## Problem

DeepSeek's native Chat Completions response reports an inclusive `prompt_tokens` together with a native cached subset in `prompt_cache_hit_tokens` and an optional `prompt_cache_miss_tokens`. `canonical_usage_from_value` recognized nested OpenAI cache details and Anthropic split tiers but did not consume the native fields, so a native-only response with inclusive input `100`, hit `98` and miss `2` was stored as `100` ordinary input tokens, `0` cache-read tokens, a `0%` cache hit rate and an input-tier charge, even though the equivalent nested shape was already understood. That gap left the gateway unable to account for reported cache hits without also confirming that the forwarding path preserved the conversation payload and did not itself introduce a cache loss. A reported symptom — a conversation whose reported cache-read count collapsed while its input kept growing — still needed a content-free way to tell whether an earlier message, tool or isolation field had changed, and a bounded way to compare the gateway against the direct upstream before attributing the effect.

## Decision

`canonical_usage_from_value` in `src-tauri/src/ai_gateway/usage_log.rs` now also normalizes the native DeepSeek cache fields into the existing four exclusive tiers, reusing the checked canonical decomposition instead of adding a parallel code path. A present native value must be a non-negative integer or the already supported integer-string form; `null` and an absent key mean absent, and an explicit `0` is present. The legitimate shapes and their normalization are:

| Native and nested shape | Detection | Normalization |
| --- | --- | --- |
| Native-only | present `prompt_cache_hit_tokens`, no nested cache details | the native hit becomes the cache-read tier |
| Consistent dual | native hit and nested `cached_tokens` both present and equal | the hit is counted once |
| Nested-only | only nested `cached_tokens` | the pre-existing nested normalization is unchanged |

A present native miss must equal the reported inclusive input minus the selected cache hit, so a miss-only response never invents a cached count. A native value that is negative, fractional or malformed, a native/nested hit mismatch, a miss amount inconsistent with `input - hit`, and a native or nested hit that coexists with the independent Anthropic `cache_read_input_tokens` tier all produce the existing conservative fallback: the reported input is billed once as ordinary with no cache tiers and the request stays cache-statistics-ineligible, and no failing shape is repaired by saturating subtraction. `input_tokens` still wins over `prompt_tokens` for the inclusive total, and the output-count validation stays independent of cache validity. The result is identical for a buffered JSON response and for an incrementally observed fragmented SSE stream, missing usage remains `usage_present = false` rather than a fabricated `0%`, and no configuration schema, stored row or price snapshot is changed or backfilled. No public symbol was added for the accounting; the native helpers stay private to `usage_log.rs`.

The same slice characterizes the existing Chat forwarding contract without changing it: model-only rewriting, native messages, ordered tool definitions, `reasoning_content` including empty strings and explicit nulls, tool calls and results, a supplied `user_id`/`metadata` and the recognized session headers survive gateway mapping, and upstream authentication retains its existing treatment. `forwarding.rs` and `selection.rs` needed no fix; a newly discovered defect would have required a bounded follow-up rather than an unapproved edit.

The delivery also adds the standalone on-demand Node tool `tools/diagnose-deepseek-cache.mjs`, which uses built-in modules only and is not installed into the normal gateway runtime. Its `observe --listen <port> --gateway <loopback-url> --model <id>` entry binds `127.0.0.1` and transparently forwards request and response bytes to an explicitly selected loopback gateway; a non-loopback `--gateway` is rejected. It observes only the native `/v1/chat/completions` and `/chat/completions` POST routes for the requested model, selects the first non-empty recognized session identity using the same header precedence as the affinity resolver, keeps exactly one preceding completed sample, and emits one JSONL `observation` event per completed selected request. The event reports `append-only`, `changed` with the first changed JSON path, or an `unavailable` classification (`overlap`, `no-predecessor`, `oversized-metadata` or a parse/encoding failure), plus the upstream `http_status` and the numeric `usage` result; `usage.availability` with its `reason` and `usage.fields.native` / `usage.fields.nested` record which sources were present. Output is a metadata allowlist: bodies, message and tool values, header values, keys, session identities, error text and content hashes are never printed or persisted, and a JSON/character comparison never claims to measure the tokenizer's cache-unit boundary. The tool is an opt-in temporary path only; the operator points one chosen client connection at it and restores the original choice afterwards.

The observer was hardened by the review's aggregate repair without changing its CLI contract or output allowlist. `--gateway` accepts either an `http:` or an `https:` URL and the upstream transport follows the configured protocol, so a synchronous transport-construction failure or an asynchronous TLS handshake failure becomes a bounded `HTTP 502` while the process and its listener stay alive and the client is answered rather than dropped. SSE parsing normalizes `\r\n` and `\r` to `\n` on the accumulated buffer and holds a dangling trailing `\r`, so an event boundary split across chunks still collapses to a real blank line and a split event's `usage` is still parsed, with `SSE_EVENT_LIMIT` and the forwarded bytes unchanged. Overlap is tracked from the moment an equal-session chat request starts rather than when its body ends; the comparison verdict is deferred until every concurrent peer's selected or unselected state is known while forwarding, piping and backpressure are never delayed; overlap is symmetric, so both concurrently selected requests are reported `unavailable`/`overlap`, neither is retained as a predecessor, the next sequential request reports `no-predecessor`, and different sessions, models or routes never contribute a peer. Retained body samples stay bounded to at most one previous request plus the in-flight selected requests; non-selected, aborted and overlapped captures are released.

The same tool's `compare` entry takes no arguments and reads gateway/upstream coordinates and credentials only from the six process environment variables `CACHE_DIAG_GATEWAY_BASE_URL`, `CACHE_DIAG_GATEWAY_MODEL`, `CACHE_DIAG_GATEWAY_KEY`, `CACHE_DIAG_UPSTREAM_BASE_URL`, `CACHE_DIAG_UPSTREAM_MODEL` and `CACHE_DIAG_UPSTREAM_KEY`; credentials never enter arguments or output and no configuration is discovered or mutated. It builds each endpoint from the configured base URL without duplicating a version segment, runs a fixed public 256 KiB prefix with ten append-only bodies per series, `thinking: {"type":"disabled"}` and `max_tokens: 32`, two rounds per path, two unreported warmups and eight measured requests per completed series, and at most 40 model POST attempts with no retry. It emits one `comparison` JSON line with `attempts`, `status` (`completed` / `incomplete`), `comparable` always `false`, `effectiveness` always `unverified`, `target_met`, `cost.availability` `unknown`, the timestamps and per-series `warmup` / `measurement` coverage: `requests` (actual attempts), `valid_usage`, the token sums, `cache_hit_rate` (`null` when the inclusive sum is 0) and the `fields.native` / `fields.nested` counts. A completed run only means a valid measurement series, never that the two paths serve the same account or model. Absent configuration yields `attempts: 0` with `status` `incomplete` and `reason` `missing-config`. Every `compare` POST attempt is bounded by a per-request timeout: a default of `600000` ms that the process environment variable `CACHE_DIAG_COMPARE_REQUEST_TIMEOUT_MS` optionally overrides with a positive integer number of milliseconds (an absent, invalid, zero or negative value falls back to the default without failing the run), and on expiry the attempt resolves through the existing transport outcome exactly like any other transport failure and the socket is destroyed, the attempt still counts in its phase coverage, the series stops, the run reports `status` `incomplete` with `reason` `transport-failure`, later rounds or paths are not attempted and no retry is made, while the bound stays `compare`-only and `observe`, its streaming and forwarding, the six `CACHE_DIAG_*` variables, the fixtures, the 40-attempt cap, the output fields and the metadata allowlist are unchanged.

The behavior tests live in `src-tauri/src/ai_gateway/tests/deepseek_cache.rs`, registered as `mod deepseek_cache;` in `src-tauri/src/ai_gateway/tests.rs`, and in `tools/diagnose-deepseek-cache.test.mjs`. The repair round adds the fragmented nested-only and consistent-dual stream characterizations to the Rust file and the three review-regression cases (https construction/handshake `502`, split CRLF event boundary, transport-start overlap) to the Node file; the repaired suites run at 20 Rust and 41 Node passing tests respectively, with the earlier 18 and 38 recorded as the pre-repair baselines.

## Alternatives considered

- Read the native fields as a second fallback after the independent Anthropic `cache_read_input_tokens` tier: declined because a native hit and that independent read describe the same cached quantity, so combining them would double count, and the shape is conflicting rather than complementary.
- Reuse the generic `token_number` coercion for the native fields: declined because it would silently coerce a negative, fractional or malformed claim into a plausible count instead of marking the accounting invalid.
- Derive a cache-read tier from `input - prompt_cache_miss_tokens` when only the miss is present: declined because that invents a hit the upstream did not report; a miss-only response must not create a cached count.
- Repair an inconsistent miss or an over-large hit with saturating subtraction or clamping: declined because it fabricates an impossible decomposition and can double count or negative-count tokens; the shape stays invalid with a conservative billing fallback.
- Edit `forwarding.rs` or `selection.rs` to chase the suspected cache loss: declined because the characterization showed the existing contract already preserves the payload, so any change would be an unapproved edit outside the delivered evidence.
- Make the observer a permanent gateway feature flag or an installed proxy: declined because this is a temporary, opt-in single-conversation path that must not change the production runtime, persistent configuration or the client installation.
- Serialize overlapping selected requests to obtain a comparable predecessor: declined because it would alter the observed transport and invent a sequence the client did not send; an overlap is reported as comparison-unavailable instead.
- Infer the observer's session identity from request content or a prefix hash: declined for the same reason as the affinity record, because the identity must come from headers the client actually sends, and the tool reports difference paths rather than content hashes.
- Treat a successful `compare` response or a matching model id as proof of account equivalence: declined because the tool cannot attest account identity; equivalence stays an operator-provided, post-run-log-verified precondition.
- Have `compare` self-report a cost or a token estimate: declined because the runner computes no cost and records only the upstream's reported counts; cost is explicitly unknown and tokens are never derived from character counts.

## Consequences

- Newly appended request-log rows use the corrected native accounting; existing rows, historical tokens, amounts and price snapshots are untouched and never backfilled.
- The four exclusive tiers, the stored `usage_semantics`/`usage_present`/`cache_accounting_valid` columns, the shared eligibility predicate and the token-weighted cache-hit rate are unchanged; the native fields only feed the existing cache-read tier.
- The diagnostic tool is temporary and opt-in: it adds no persistent configuration, schema or background service, exiting it restores the operator's connection choice, and a rollback reverts the tool, its tests and the delivered documentation together while preserving all usage rows.
- Only private helpers were added for the accounting, so navigation changed for the tooling/test and documentation paths and their semantics, not for new public symbols.
- The review's aggregate repair changed only the observer's transport handling, split-SSE normalization and overlap tracking; the Step 1 native accounting contract, the four exclusive tiers, the output allowlist and the CLI contract are unchanged.
- The delivered tooling paths `tools/diagnose-deepseek-cache.mjs` and `tools/diagnose-deepseek-cache.test.mjs` are registered in the `cli-matrix-check` tooling navigation entry, `docs/deepseek-cache-diagnostics.md` in the documentation entry, and the tool standard in `MEMORY.md`; `navigation.md` was regenerated from the authoritative JSON.
- Partial supersession: [API Gateway Cache Hit Rate Normalizes Provider Usage Semantics](../bug-fix/2026-09-21-api-gateway-cache-hit-accounting.md) is retained and cross-linked; this record extends its `canonical_usage_from_value` shape table with the native DeepSeek hit/miss fields and adds the content-free observer and the bounded comparison runner, while its four-tier normalization, storage migration, eligibility predicate and coverage contract remain in force.
- No supersession of routing: [Gateway Session Affinity Pins a Session and Model to One Upstream](../architecture/2026-09-20-gateway-session-affinity-routing.md) is retained and cross-linked; this change extends native-field accounting and diagnostics and does not alter the affinity policy, its header precedence, its binding rules or its process-memory-only state.
- Step 3 remains blocked and unverified after two operator-authorized live attempts. Both used a plan-scoped preparation helper (a plan artifact, not a product feature) that read only the `onespace-dev` `.local_key` and `ai_gateway.json` and supplied the six `CACHE_DIAG_*` values to the child in memory; the delivered `compare` entry still reads only its process environment and no configuration was discovered or mutated. The first attempt (`2026-10-15T09:15:18.078Z`–`09:15:21.111Z`, `17:15:18.078`–`17:15:21.111` UTC+08:00) exited nonzero: `attempts: 1`/40, `status: incomplete`, `reason: request-rejected` — the gateway path ended after a single HTTP 429, neither warmup nor measurement produced valid usage, and the upstream path sent no request. The second attempt, run in this follow-up on the merged tool (`2026-10-15T12:16:02.608Z`–`13:27:14.150Z`, `20:16:02.608`–`21:27:14.150` UTC+08:00), exited nonzero: `attempts: 23`, `status: incomplete`, `reason: transport-failure` — the gateway path produced 16/16 measured coverage with a token-weighted rate of ≈93.684% (below the 98% target as measured), and the direct-upstream path stalled on its first measured request and was closed by the upstream after roughly one hour, so it yielded no measurement coverage and there is no two-path comparison. A read-only `onespace-dev` usage check for the first attempt's window and target identity found exactly one row — the rejected attempt (`result: failure`, `status: 429`, `usage_present: 0`, `cache_accounting_valid: 0`, every token tier `0`, `amount 0.0`); a similar read-only check for the second attempt's window found exactly 20 stored successful rows (94364 ordinary input, 843136 cache-read, 640 output) matching the gateway series. A post-run reload of the comparison state after the first attempt failed with a fixed missing-source-key reason, so the credential-unchanged re-check did not complete and no credential-value change is claimed; the gateway additionally set its own runtime quota flag on the target key from the `429`, which is outside this plan's authorization to clear. Neither attempt produced a retry or a provider switch, neither added an extra warmup, and neither ran a live `observe`; both batches are spent, further measurement needs a new explicit authorization and the fixture must not be changed, the `compare` per-request timeout delivered in this same follow-up bounds every attempt (default `600000` ms, overridable by `CACHE_DIAG_COMPARE_REQUEST_TIMEOUT_MS`) and was authored after the second batch without affecting it, and the 98% token-weighted effectiveness target remains unmeasured and is not claimed met, nor is the original production cache problem claimed resolved.
