# Agent Note: Model Pools Use an Explicit Last-Stage Fallback Source

Status: implemented

[English](2026-10-20-model-pool-default-fallback.md) | 中文

## Problem

模型池此前只能在其常规候选之间轮转。当每个常规来源都在冷却、被禁用、缺失、没有可用 key，或在请求中耗尽时，公共别名会返回既有的全部不可用错误，即使运营商还有一个本应用于服务这些请求的真实映射。回落到普通付费默认模型或网关级默认模型被刻意禁止，因为那会静默越过运营商选择的池边界。缺失的决策是一个可选来源：它由运营商显式选择，只在常规阶段耗尽后使用，并且绝不能与健康的常规候选竞争或取代它。

## Decision

- 在既有 schema 3 记录下新增可选的 `ModelPool.fallback: Option<ModelPoolCandidate>`。它携带与常规候选相同的精确来源身份——trim 后的服务商 id、原始本地模型、上游模型与生效协议——复用池自有推理声明，并保留 1 到 100 的候选权重范围、存储默认值为 1。它的权重绝不进入主调度。后备来源绝不复制凭据、端点或同级来源。池仍然需要至少一个常规候选；新引用必须对最新配置可解析，而未改动的已存引用可在其来源消失或被禁用后保留，保持可见为不可用，并可在不替换同级来源的情况下清除。重复常规身份的后备来源、空的常规选择、空白身份或非法协议、推理声明或权重，都会在任何加密配置字节改变之前被原子拒绝。
- 把后备来源作为独立最后阶段路由，而不是另一个常规候选。它会在准入时常规运行时集合已为空或已排除之后到达，并跟随任何被允许的常规探测；在转发期间则在常规有限尝试及其被允许的共享探测之后到达。后备来源获得一轮尝试，使用既有轮内 key 轮换，并为整个请求至多使用一次共享的映射或 key 探测。它不启动额外的延迟重试循环，已耗尽的常规重试等待预算也不能压制它的第一轮。它绝不进入平滑加权轮询、普通会话亲和绑定或池延续偏好。
- 保持健康与已恢复的常规候选优先。兼容且健康的常规候选存在时，后备来源不会被调用；后备来源投递或常规恢复之后，下一个请求会再次让合格的常规候选优先。成功的后备投递会关闭任何陈旧的 primary 偏好，而不是发布后备偏好；成功的常规投递保持既有延续行为。后备来源仍只限当前的启用池别名，因此禁用池、退役别名与原生 Messages 池入口保持既有围栏，普通模型路由绝不使用池后备来源。
- 后备尝试复用真实来源契约：精确解析、启用状态、可用 key、健康与候选冷却（含被允许的恢复探测）、既有协议转换、候选本地推理注入、调用方的有效输出上限，以及既有的候选级、key 级与映射级失败结算。候选冷却所有权仍落在真实来源上。移除或替换后备身份时，只在该身份自有的进程内存冷却上、且仅在配置成功发布后清理；写入失败不清理任何东西。
- 在常规候选加后备来源的已配置并集上分类具体推理偏好，且与临时就绪状态无关，因此仅由后备来源声明的支持仍然可达。同一并集供给后端状态、发现与 OpenCode 载荷以及前端目录辅助函数中的静态目录；常规就绪与候选状态数组仍只含常规候选，后备来源作为独立可选状态报告。`auto` 不注入任何控制，便携 strict 工具校验会像对待 Anthropic 常规候选一样考虑已配置的 Anthropic 后备来源。客户端校验错误或上游 `ReturnToClient` 结果按既有分类结束请求，而不是启动另一个阶段。
- 在三种上游协议上保留两种 OpenAI 入口、流式与非流式。透明后备只可能发生在首个客户端字节之前；输出开始后沿用既有的入站格式错误与关闭行为，不重放也不产生第二个成功终止符。客户端断开取消进行中的尝试或等待，并阻止后续后备尝试、虚假的成功终止行或虚假的健康/偏好成功。每个完成的业务请求仍恰好有一行终止记录：公共别名保持为 `local_model`，而服务商、上游模型、用量、价格与原生推理证据标识实际的后备来源，最后观测到的上游状态（包括网络状态 0）被保留。
- 暴露一个可选的本地化「Default fallback model」选择器，带 none 选项、排除当前常规选择的真实服务商映射、键盘操作与复用的推理编辑器。池卡片显示后备来源的服务商、来源与协议，并独立于常规就绪展示其可用性与原因，包括零个就绪常规候选加一个就绪后备来源的情形。缺失或已禁用的已存引用保持可见、可保留、可清除；未保存的目标与推理草稿在状态或配置刷新以及保存被拒后保留，取消不产生任何变更。每个新标签与校验消息都有英文和中文，且 key 列表同步。
- 保持兼容性。缺失或 null 的后备来源读为无后备来源，无迁移、无读取时配置写入，因此旧池保持既有行为与 schema。旧二进制在保存时可能丢弃未知字段。禁用或退役池别名与普通路由保持既有边界，池保存保留服务商、价格、凭据与同级池。

## Alternatives considered

- 把后备来源追加到常规候选列表并交给加权调度器决定：拒绝，因为它会消耗主权重、顺序与探测额度，并可能让最后手段来源赢下本应由健康常规候选服务的请求。
- 池耗尽时回落到普通付费默认模型或网关级默认模型：拒绝，因为它静默越过运营商选择的池边界，且不是运营商的显式选择。
- 给后备来源新的延迟重试周期或第二轮：拒绝，因为它会超出既有有限重试与等待边界，并重复已有有界尝试策略。
- 在后备来源内存储独立服务商、key 与端点，或借用同级映射：拒绝，因为那会复制凭据并破坏真实映射身份、健康与价格的单一事实来源。
- 把成功的后备来源提升为下一轮偏好或保留后备偏好：拒绝，因为已恢复和健康的常规候选必须重新优先，且后备来源不是主来源。
- 把后备就绪计入常规候选数组或就绪计数：拒绝，因为运营商需要常规池就绪保持仅含常规候选，后备可用性应作为独立可选状态报告。
- 从静态目录或 strict 工具校验中省略仅后备来源的推理支持：拒绝，因为已配置且可达的来源必须被一致广告，且已存 Anthropic 后备来源确实可以服务请求。
- 静默忽略不可用的已存后备来源或推断替代来源：拒绝，因为运营商必须保留或显式清除精确的已存引用，绝不能收到未选中的服务商。

## Consequences

- 池别名现在可以指定一个真实来源作为最后手段，同时其常规候选保持既有加权顺序、有限重试、key 轮换与被允许的探测。后备来源在空的或已排除的常规运行时集合之后、以及请求内耗尽之后服务，只有一轮有界尝试且没有额外延迟重试循环。
- 后备来源不能赢得主调度、普通会话亲和或池延续偏好。后备成功关闭任何陈旧 primary 偏好，而健康或已恢复的常规候选在下一个请求重新优先，成功的常规投递保持既有延续行为。
- 配置在 schema 3 下保持加性：无迁移、无读取时改写，缺失或 null 值读为无，未改动的已存引用在来源移除或禁用后仍可用于查看与清除。新引用是精确的，重复的常规与后备身份被拒绝，且仍要求至少一个常规候选。被移除的后备冷却只在成功发布后清理，因此保存失败既不改变加密字节也不改变自有的运行时状态。
- 可观测性在各界面一致：静态推理目录包含已配置并集而常规状态保持仅含常规候选，后备来源有独立可选状态，发现与 OpenCode 行发布相同的静态支持，未过滤的就绪状态绝不定夺目录。后备尝试在唯一终止行中保留公共别名与真实来源身份，并保留最后上游状态（含网络状态 0）。
- 传输边界不变：两种 OpenAI 入口与三种上游协议都可服务输出前的后备来源，首字节后失败绝不重放，断开不能产生后续尝试、虚假成功、健康或偏好。
- 运营商界面提供独立可选选择器与独立卡片行，保持缺失或已禁用已存引用的可保留与可清除，在刷新与保存被拒后保留草稿，并提供双语、键盘可达的标签。本次变更不强制截图，也不声称截图证据。
- 验证：限定范围的后端套件通过，`model_pools` 46 通过、`model_pool_reasoning` 31 通过、`pool_context_hold` 44 通过、`model_pool_terminal_sync` 17 通过，均无失败；有界网关运行 1050 通过、0 失败，另有 2 个既有忽略用例；清理后重跑 `model_pools` 46 通过且无警告。五文件前端 vitest 运行 315/315 通过，限定范围 eslint 退出 0 并带 3 个既有警告，`npm run build` 退出 0。未演练真实上游推理、真实终端投影或原生 Tauri IPC，也不声称任何截图证据。
