# Agent Note: Model Pools Route One Public Alias Across Explicit Source Candidates

Status: implemented

[English](2026-10-13-free-model-pool.md) | 中文

## Problem

网关此前把每个公共模型 id 只经恰好一条上游映射行暴露。持有多个免费或促销映射的操作者——例如同一服务商的两条映射，或多个账户——无法把它们作为一个公共模型发布：调用方必须知道单条映射的本地模型名，每条映射各自携带自己的健康状态，而某条映射上的模型级限额也没有任何边界把它与其他映射隔开。也没有任何持久化位置能表达“这些精确的来源映射构成一个公共模型、在它们之间轮转，并且在免费来源耗尽后绝不回落到普通付费默认模型”。模型池还可能选中一条存储的 OpenAI 端点与调用方不同的候选，而普通网关只把 OpenAI 请求转发到候选自己的端点并在 OpenAI 与原生 Anthropic Messages 之间转换，因此 Chat Completions 调用方无法被 Responses 候选忠实服务（反之亦然）。本记录覆盖后端路由、存储与校验边界、池专属 OpenAI 协议转换与便携请求契约，以及运营商界面、模型发现与终端载荷集成。

## Decision

- 在不改变 schema 的前提下持久化两个 `#[serde(default)]`、始终序列化的 `GatewayConfig` 字段：`model_pools: Vec<ModelPool>` 与 `model_pool_reserved_models: Vec<String>`。`GATEWAY_CONFIG_SCHEMA_VERSION` 保持 3，不引入迁移，因此在模型池出现之前写入的配置会读为空集合。`ModelPool { id, name, model, enabled, candidates }` 把 `model` 作为公共模型 id 暴露；`ModelPoolCandidate { provider_id, local_model, upstream_model, protocol, weight }` 是对既有服务商映射行的精确引用，`weight` 默认 1、范围 1..=100；`PoolCandidateIdentity { pool_id, provider_id, local_model, upstream_model, protocol }` 是一个已准备候选的仅传输身份。模型池记录绝不复制来源 key 或 endpoint。
- 在新模块 `src-tauri/src/ai_gateway/model_pools.rs` 中承载模型池边界。`plan_pool_request` 在任何普通候选构建之前运行：它把 trim 后的精确别名与当前模型池匹配，退役保留别名一律 fail-closed；禁用的池、对模型池别名的 `AnthropicMessages` 入站请求，或没有任何可用候选与合格探测的池返回标准 `all_providers_unavailable` 502（原生 `/v1/messages` 入口沿用既有 Anthropic 错误信封）。任何普通服务商或默认模型都不得服务当前或退役的模型池别名。
- 对最新配置解析每个候选。只有当候选的服务商存在、其原始 trim 后 `(local_model, upstream_model)` 映射仍以相同生效协议可解析、服务商与映射均已启用且未被自动禁用、候选能服务入站协议，且服务商有可用 key 时，该候选才可用。`prepare_provider` 把真实服务商、密钥池与端点克隆成单映射路由副本，把本地模型改写为池别名，清空 `default_model` 以免任何未选中的同级被选中，并挂上仅传输的 `pool_candidate` 身份。
- 以池专属的平滑加权轮询为可用候选排序。调度键是池 id 加完整候选身份（服务商、原始 local/upstream 对、存储的协议）加入站协议，因此两个池、同一服务商的两个模型，以及路由到同一存储候选的 Chat/Responses 入口各自拥有独立循环。模型池请求绝不读取也不写入普通会话亲和绑定；已识别的同轮池工具延续只使用其自身的有界延续偏好，见 [Model Pools Prefer the Preceding Candidate for Same-Turn Tool Continuations](2026-10-15-model-pool-context-hold.md)。只有可用候选占用主槽；至多一个映射或 key 半开探测追加在可用候选之后，且绝不拓宽到该池选中集合之外。
- 把健康、诊断与记账落回真实来源。`attempt_policy::resolved_health_target` 对已准备的池候选返回存储的原始服务商/本地/上游映射，因此探测、重试与映射自动禁用都结算在真实行上。失败的池尝试点名真实服务商并附上原始映射身份，用量日志把公共别名记为 `local_model`、同时记录真实服务商 id 与上游模型；计价仍使用真实来源服务商的价格行。
- 把恢复限定在候选上。候选级失败——结构化 `error.type` 为 `FreeUsageLimitError` 的 429，或额度分类器视为模型级/未知范围耗尽的 400/402/429 消息——会记录进程内存候选冷却并只丢弃该候选，不标记共享 key、不耗尽它的 key、也不登记映射健康。冷却按池加完整候选身份键控、并在各入站之间共享；`cool_pool_candidate` 保留精确 `Duration`，缺失或非法延迟回退到 `POOL_CANDIDATE_COOLDOWN_SECS = 60`，有效的 `retry-after-ms: 0` 让候选立即重新可用。显式账户资金/额度耗尽信号与普通凭据 401/403、非凭据 403 仍保持既有 key、账户与映射策略。
- 通过 `commands.rs` 与 `app_runtime/run_app.rs` 暴露四个类型化命令：`ai_gateway_upsert_model_pool(pool)`、`ai_gateway_delete_model_pool(pool_id)`、`ai_gateway_set_model_pool_enabled(pool_id, enabled)` 与 `ai_gateway_model_pools_status()`。upsert 在既有串行 `storage::modify_config` 原语下校验并写入，因此校验或写入失败不改变任何东西。
- 保持新引用精确、旧引用可保留。新候选必须对最新配置可解析，而已经存储的引用在其来源变得不可用后依然有效，以便操作者保留或显式移除；候选需要非空字段、无重复 tuple 与范围内 weight。公共模型 id 不得与普通映射或另一当前池冲突。重命名或删除池会把其先前别名推入 `model_pool_reserved_models`；新池可复用退役别名，而 `ai_gateway_upsert_provider` 会拒绝将获取当前或退役别名的普通映射。
- 发布非机密状态。`ai_gateway_model_pools_status()` 返回每个池的身份与候选，只含来源身份、可用性代码（`ready`、`cooling`、`source_disabled`、`mapping_unavailable`、`missing_provider`、`no_usable_key` 或 `unsupported_protocol`）与 epoch 秒冷却截止（由单调截止向上取整）。它不发起任何网络或额度探测，也不持久化任何东西。
- 仅在成功发布后清理自有状态。`storage::write_config` 与 `storage::modify_config` 把此前持久化的池与已发布的池做差，并调用 `model_pools::prune_removed_pools` 清除被移除池或候选自有的调度与冷却条目；写入失败不清理任何东西。
- 在两个新模块中承载 OpenAI 协议转换。`src-tauri/src/ai_gateway/openai_conversion.rs` 识别两条 OpenAI 规范路径（`is_openai_path`、`client_protocol`、`endpoint_path`）并转换池请求/响应体；`src-tauri/src/ai_gateway/openai_sse.rs` 转换池流。`forwarding.rs` 为生效协议与调用方不同的已准备池候选改写上游路径与请求体；同协议池候选保留自己的端点。普通（非池）路由、key 策略、健康结算与 Protocol Router 均不受影响。
- 在选择之前强制便携请求契约。`openai_conversion::validate_pool_request(path, body, messages_candidate)` 在 `runtime_http.rs` 中先于 `plan_pool_request`、任何候选选择、SWRR 变更、尝试或探测运行，并返回点名违规字段的 `400`。每侧只接受公共文本/工具与控制面；无法识别的顶层或嵌套字段、无法表示的内容块、非布尔控制、非 `text` 输出格式或不透明推理/对话引用都按字段拒绝。唯一被识别的 provider 专有例外是历史上的助手 `messages[].reasoning_content` 痕迹（字符串，含空串或空白，或 `null`）：它在同协议 Chat 候选上被原样保留，在转换后的请求上被省略且不臆造推理，而其他每个未列出字段仍被拒绝。Chat 拒绝 `stop`、`frequency_penalty`、`presence_penalty`、`seed`、`logit_bias`、`logprobs`、`n != 1`、非空 `reasoning_effort`/`reasoningEffort`、非文本消息内容（图片、文件、音频）与未知 `stream_options` 成员；Responses 拒绝 `previous_response_id`、`conversation`、`truncation`、`include`、`logprobs`、`n != 1`、非空 `reasoning`、托管工具与非文本输入。`store: true` 或 `background: true` 以字段名拒绝，而 `false`（以及缺省值）被接受。`strict: true` 函数控制对纯 OpenAI 池予保留，但当池至少存储一个 `anthropic_messages` 候选时，无论轮转会选中哪个候选都拒绝，因为既有 Messages 适配器无法承载它；`strict: false` 这一可表示的默认值仍被接受。请求还会按相反的 OpenAI 方向检查，因此可表示性绝不依赖随机选中的候选或临时冷却。
- 双向转换两种 OpenAI 协议。`openai_conversion::convert_request(path, body, model, upstream)` 把调用方请求转换成所选候选的 OpenAI 协议并把模型改写为真实上游模型；`openai_conversion::convert_response(path, upstream, body, model)` 把非流式响应转换回来。两个方向都保留完整无状态文本历史、system/developer 指令、函数 schema、tool choice 与并行控制，以及调用 id/参数/结果。公共采样控制是 `temperature` 与 `top_p`；Chat 的 `max_completion_tokens` 优先于 `max_tokens`，Responses 使用 `max_output_tokens`，提供的上限为非负整数（含零），而该适配器下省略的上限保持省略，既有 Messages 适配器保留自己的 `4096` 默认值。同协议池响应原地规范化并改写模型别名（Responses 体还改写嵌套 `response.model`），因此调用方总能收到自己的入站协议与公共池 id。
- 增量转换流。`openai_sse::OpenAiSseConverter` 以调用方路径、上游协议、公共模型与调用方是否请求用量构造；`feed` 只缓冲到最早的 LF 或 CRLF SSE 边界，`finish` 冲刷末尾不完整帧。它保留稳定的文本/工具身份、区分 Responses 函数调用项 id 与其 call id、按文本/工具首次到达顺序发出稳定输出槽、发出规范 Responses 生命周期（`response.created`、`response.output_item.added`、content-part 与 `response.output_text.delta`、`response.function_call_arguments.delta`、对应的 `...done` 事件与 `response.completed`）以及恰好一个终止事件（Chat 为 `data: [DONE]`，Responses 为 `response.completed`）。提供布尔 `stream_options.include_usage: true` 的 Chat 请求会在转换后的 Chat 流里得到终止用量，而网关绝不向上游注入该标志。`is_success` 与 `has_in_band_error` 报告上游是否真正完成，因此畸形帧、Responses 的 `error`/`response.failed`/`response.incomplete` 事件，或状态不是 `completed` 的 `response.completed`，都绝不冒充成功答案。
- 保持传输边界。`runtime_http.rs` 只对 OpenAI 端点上的已准备池候选使用该 OpenAI 转换器，而原生 Anthropic Messages 候选保留既有适配器。非流式路径上的转换失败返回标准 `502` `conversion_error` 信封。原始上游用量在转换之前观测，因此计价与日志仍使用真实来源服务商与上游模型，公共别名作为 `local_model`。在写出首个客户端字节后，转换流失败按入站格式报错、不写成功终止符、绝不重放，下游取消停止上游尝试且不结算健康。唯一合格的半开探测按候选存储的协议复用，且绝不拓宽到未被池选择的来源。
- 在真实服务商旁提供虚拟运营商界面。既有 Add provider 选择器新增「创建模型池」通道，打开专用的 `ModelPoolDialog` 与 `ModelPoolCard`。对话框以默认显示名 `Free Modle` 与默认公共模型 id `free-model` 起步（均可编辑）；它把来源映射按服务商分组置于搜索框之后、以复选框独立多选，并保留一个已选列表，其中每个候选带 1..100 的整数权重与逐行移除操作，页脚固定为取消/保存、正文在固定标题下方滚动。`ModelPoolCard` 提供公共 id 复制、编辑、候选展开、日志入口，以及更多菜单内带二次确认的删除操作。启用开关把操作者意图与候选就绪分离。对话框在本地持有草稿并每次打开或切换目标时重新挂载，因此运行时状态刷新绝不覆盖未保存的名称、选择或权重编辑；被拒绝的保存保留草稿并显示后端消息，取消不写。候选可用性由当前配置加上仅该池自己的非机密状态派生（`resolveModelPoolCandidateState`、`MODEL_POOL_AVAILABILITY_LABEL_KEYS`、`POOL_KEY_QUOTA_MARK_TTL_SECONDS`），因此陈旧快照绝不把已禁用、已移除、协议不匹配或无 key 的来源复活，且绝不查询其他池的冷却；每个候选显示其本地化可用性代码，并把任何原始后端原因作为附加详情保留。
- 每个启用池只广告一次且绝不臆造能力。模型列表面板、运行状态卡与页签计数把每个启用的已配置池恰好计一次，包括其全部候选暂时不可用时，而已禁用或退役别名被排除。池列表行只广告池自己的名称与两条 OpenAI 入站协议并标识其真实来源，绝不借用来源模型的推理档、Responses npm 覆盖、虚构免费价格、合并余额或承诺流量百分比；来源账户额度仍留在真实服务商卡片上。池状态轮询仅在页面可见时按既有刷新节奏运行，绝不发起逐卡网络请求或推理探测。
- 从同一权威配置发布发现与终端载荷。`runtime_http.rs` 把每个启用池 trim 后的公共别名并入 `local_model_names`，与临时冷却无关；`models_payload` 经 `pool_discovery_entry` 为每个启用池发出恰好一行 `/v1/models`，携带池 `name`、`chat_completions` 与 `responses` 协议、`source_count` 及真实来源身份，且不含 key、endpoint、价格、推理档或就绪标志。`commands.rs` 新增 `build_gateway_provider_with_pools`：OpenCode 目录把每个启用池恰好加入一次为 Chat 兼容行，不推断推理变体也不给 Responses npm 覆盖；Codex 在 resync 时保留已选中的启用池别名，否则优先使用已存在的普通默认模型，再否则以第一个启用池别名兜底；原生 Claude 选择排除该 OpenAI 池。四个类型化池命令仍是唯一的池变更入口，profile 所有权与手动激活/投影规则保持不变。

## Alternatives considered

- 在每个池候选内存储独立服务商、key 与 endpoint，而不是引用既有映射行：拒绝，因为这会复制凭据、破坏 endpoint 与 key 的单一事实来源，并让池与来源映射的健康脱节。
- 对池候选复用普通调度器与会话亲和：拒绝，因为普通调度器按服务商、本地模型与协议键控，无法区分同一服务商的两个同级候选，且会话亲和会把池别名固定到单个候选，破坏池存在的轮转目的。
- 持久化候选冷却或发起推测性启动/网络探测：拒绝，因为它们在范围之外；冷却留在进程内存，既有每请求探测仍至多一个。
- 让禁用或退役别名回落到普通路由：拒绝，因为过期客户端随后可能把退役的免费模型别名发往无关的付费默认模型；别名边界必须 fail-closed。
- 在候选级模型限额上标记共享 key：拒绝，因为模型级额度会让一个被健康同级模型共享的 key 退出服务；只有该候选冷却，而显式账户耗尽保持既有账户与 key 策略。
- 为模型池字段提升配置 schema 或新增迁移：拒绝，因为 `#[serde(default)]` 已使旧文件可读，所以 schema 保持 3 且无迁移。
- 对池路径复用 Protocol Router 的有损文本扁平化与缓冲转换：拒绝，因为它会丢弃工具历史，也无法保留池契约要求的增量线格式。
- 静默丢弃无法转移的字段：拒绝，因为调用方无法得知自己的 stop、seed 或 JSON schema 控制被忽略；每个字段要么被忠实转换、要么在选择之前按字段名拒绝。
- 为获取用量而向上游注入 `stream_options.include_usage`：拒绝，因为网关绝不能改写调用方所描述的上游请求；转换后的 Chat 流在不注入的情况下尊重调用方的布尔值。
- 转换图片、文件、音频或托管工具状态：拒绝，因为它们在公共文本/工具契约之外，无法在两个方向上忠实表示。
- 复用真实服务商卡片与其弹窗作为池编辑器：拒绝，因为池携带公共别名、多来源选择与候选权重，这些是服务商记录无法承载的，且既有服务商界面必须保持自己的语义。
- 显示池级聚合权重、承诺流量百分比或免费价格/合并余额徽标：拒绝，因为池不拥有余额，候选可能未定价或被其来源改价，且轮转权重是每请求而非配额。
- 为 OpenCode 池条目推断推理档或 Responses npm 覆盖：拒绝，因为池只广告公共文本/工具面，绝不能臆造来源模型的能力。
- 让池自动替换普通 Codex 默认模型或原生 Claude 选择：拒绝，因为池是 OpenAI 专属，绝不能静默顶替操作者既有的普通或原生选择。

## Consequences

- 当前池别名只在池专属加权轮转下经其选中候选路由，禁用或退役别名 fail-closed，绝不触及普通来源或默认模型。既有 `anthropic_messages` 候选经既有适配器服务，与普通路由已有的行为一致，而任一条 OpenAI 端点上的候选都经新的池专属转换服务。
- 两种 OpenAI 协议对池请求双向互通（含同协议规范化），且无法在另一方向表示的请求现在会在任何候选、SWRR 变更或健康/key 变更前以点名字段的 `400` 失败。
- 健康、探测与诊断停留在真实来源行上：映射自动禁用、key 轮换与全部不可用消息点名真实服务商与原始映射，用量日志保留公共别名并伴有真实服务商与上游模型。
- 转换后的流是增量的且正确完成，保留文本/工具顺序与稳定身份，调用方收到自己的协议与公共别名；畸形或出错的流绝不报告为成功，也绝不在首字节后重放。
