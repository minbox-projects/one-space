# Agent Note: Cloud Agent Plan Execution

Status: implemented

[English](2026-10-30-cloud-agent-plan-execution.md) | 中文

## Problem

此前在自托管云端主机上执行已保存的冻结计划，只能依赖交互式终端会话或 Issue 驱动运行。Issue 运行从 Issue 文本开始而不是本地计划，交互式会话则要求人工持续附加以回答问题。用户需要从桌面端选择已保存工作区与从未开始的冻结计划，让云端针对最新拉取的远端代码执行，在桌面端断开后保持任务存活，并获得一个待审阅且不自动合并的 Pull Request。设计还必须防止重复提交启动第二次编码会话，避免上传本地源码改动，并明确云端可以代表用户回答哪些权限请求与问题。

## Decision

计划执行由云端掌握。桌面端提交计划后从云端读取持久任务状态，而不是再持久化一份执行权威。每个任务把准入记录、请求元数据与不可变的 `upload/` 副本存放在 `~/.config/onespace-cloud-agent/plan-tasks/<job-id>/` 下，在主机本地文件锁内原子写入。

准入以规范化仓库身份加冻结计划 ID 为键，而不是本地显示名或根路径。身份是 GitHub 或 GitHub Enterprise 主机与由服务商解析出的 owner/repository，统一 SSH/HTTPS 写法、主机大小写与 `.git` 后缀，并经 `gh repo view` 确认。相同身份、相同基线分支与相同上传字节在任意状态（包括 completed、failed 与 cancelled）都返回既有任务；新的客户端 request ID 只登记为别名，基线分支或载荷变化会被拒绝而不是替换已受理上传。准入字节与执行副本相互独立，因此编码把自身的计划记录写入克隆不会改变重放比较。

每个任务在配置的云端工作区根下获得全新的自有克隆。准备工作在编码前立即拉取选定分支，把完整拉取到的 SHA 记录为本次运行的基线，并在该 SHA 上创建任务交付分支。绝不按仓库基名复用共享检出，也绝不重置或清理无关工作。根路径映射属于调用而不是冻结文件：执行上下文声明原始本地项目根与等价云端根，由原始根前缀限定的任务 scope 与命令路径在拼装时映射到克隆，而冻结字节与摘要保持不变。映射之外的引用或仅本机可用的前置条件是可见阻塞，而不是扩大范围或改写冻结文档的理由。

提交即为该任务委托单次工具授权。自有权限请求以 `once` 回复，原生 `deny` 继续生效，运行器绝不设置全局 `always` 权限或修改宿主权限设置。问题自动回答是语法规则：只有当所有问题均为单选、且每个问题恰有一个选项标签在规范化首尾空白与英文大小写后以 `(Recommended)`、`(推荐)` 或 `（推荐）` 结尾时才自动回答，并返回原始标签。该规则绝不从选项顺序、唯一选项或描述文本推断推荐。它适用于每个匹配的问题，包括提及范围或验收的问题，因此刻意不做语义筛选，也不承诺被标记的选项一定安全；范围与验收仍由工作流执行。自由文本、多选、缺失标记与歧义标记的问题保持 `waiting_input`，等待通过 `opencode attach` 在同一会话接管。

完成是工作流证据而不是模型叙述。发布要求观察到成功的 `coding` skill 工具调用、编码自有的 `implementation.yaml` 标记为 `completed`、其记录的完整最终 SHA 等于交付分支 HEAD，且交付工作树干净。运行器不根据对话记录独立推断测试或审阅结论。经核验的代码树与捕获的基线完全一致时以 `no_changes` 结束，不建空提交或 Pull Request。

经核验的改动用普通非强制推送交付任务分支，并以显式仓库、基线与 head 创建一个 Pull Request。创建前及创建响应不确定后都会复用匹配的 Pull Request，因此响应丢失不会产生重复。发布会返回 Pull Request URL 与最终 SHA，失败时保留提交并报告所处阶段，且绝不合并远端 Pull Request：合并始终是人工操作。

取消只停止任务自有的进程并阻止尚未开始的发布，保留的状态与克隆仍可读取，已经发生的副作用会如实报告。失败或取消的任务不会自动重跑，新的执行需要新的冻结计划标识。缺少已安装的前置条件或 OpenCode 接口不受支持时，在编辑前停止；较旧的云端安装会报告需要升级，而不会猜测回退方案。

这些提示词与工作流约束都不是操作系统沙箱。服务保留既有执行权限与 `--yolo` 模式；隔离来自提示词、范围校验与自有进程，主机加固仍是操作者职责。

## Alternatives considered

- 以本地工作区路径、显示名或新的内容指纹标识任务：未采纳，因为本地路径不跨机器稳定，而规范仓库加计划 ID、基线分支与上传字节已足以标识一次执行，另一份指纹不会增加决策价值。
- 按仓库基名复用共享检出：未采纳，因为无关仓库可能同名，复用会混合无关工作或需要破坏性重置。
- 在桌面端持久化云端执行状态：未采纳，因为断开或切换的客户端会成为过期权威；云端保持唯一状态所有者。
- 对推荐选项做语义分类，或为涉及范围与验收的问题开白名单：未采纳，因为这会把运行器变成业务裁判并让行为不可审计；语法规则可预测、会记录日志，并把验收执行留给工作流。
- 在经核验的结果后自动合并 Pull Request：未采纳，因为交付明确要求经人工审阅的 Pull Request。
- 自动重跑失败或取消的任务：未采纳，因为副作用可能已经发生，中断后的归属也不确定；需要人工处理或新的冻结计划。
- 把冻结计划路径改写为云端根：未采纳，因为改写会改变冻结字节与摘要；在调用时映射才能保持计划的权威性。
- 在操作系统沙箱内运行计划执行：本能力未采纳，因为这会改变保留的权限与 `--yolo` 前置条件；缺少沙箱被记录为限制，而不是由提示词文本暗示具备。

## Consequences

- 任务状态、准入上传、请求记录与克隆保留在 `~/.config/onespace-cloud-agent/plan-tasks/<job-id>/` 与配置的工作区根下；关闭桌面端或 SSH 不会停止已受理任务，重连读取云端权威状态。
- 重复提交复用原任务及其 PR 或状态；基线分支或载荷变化会被拒绝，旧客户端的重试别名也无法启动第二次编码会话。
- 不匹配语法推荐规则的问题会阻塞进度，直到有人附着到精确会话并回答；操作者不应期待运行器判断被标记选项是否安全。
- 即使会话看起来空闲，缺少完成证据时发布仍会保持阻塞；反过来，`no_changes` 不创建提交或 PR。
- 云端主机必须已提供 `ai-workflow` CLI、`coding` skill、原生角色、Python、`tmux`、Git、已认证的 `gh` 以及以 1.19.5 为基线的受支持 OpenCode v1 接口；本能力不安装其中任何一项。
- 恢复是手工且非破坏性的：回退服务代码前先取消或停止自有任务，保留上传、状态、克隆与已发布 PR 供排查，且不把删除远端分支或关闭 PR 当作回滚副作用。
- 相关活跃笔记：[Cloud Agent 加固保证](../architecture/2026-10-29-cloud-agent-hardening.md) 继续作为服务级网关、Issue、会话与部署保证的当前记录；本记录补充计划执行的原因与取舍，不取代它。
- 验证为服务端单元与集成测试套件，包括在本地 bare Git 仓库上以模拟协议与 GitHub 响应覆盖的端到端流程，以及无 provider 的原生 OpenCode 冒烟；真实 Linux 部署与真实模型仍属于单独的部署证据，缺少 OS 沙箱这一事实不会因这些检查而减轻。
