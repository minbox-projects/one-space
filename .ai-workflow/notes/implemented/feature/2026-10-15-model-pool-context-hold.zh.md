# Agent Note: Model Pools Prefer the Preceding Candidate for Same-Turn Tool Continuations

Status: implemented

[English](2026-10-15-model-pool-context-hold.md) | 中文

## Problem

模型池以平滑加权轮询在其启用的来源候选之间轮转，因此同一客户端轮次的每个请求都可能由不同的来源服务，即使客户端正在延续同一个工具调用。一个 agent 客户端发出 Chat Completions 或 Responses 请求，某个来源返回一个函数调用，客户端随后追加助手工具调用与其结果而不新增用户消息。模型池此前没有这个轮次的概念，于是照常推进轮转、把延续挪到了同级来源。这次切换丢弃了前一来源的提示前缀及其上游前缀缓存复用，并可能在没有任何运营商或客户端意图的情况下中途改变作答的模型。普通会话亲和被刻意排除在池输入之外，因为把整个会话固定到单一来源会破坏模型池存在的轮转目的。因此问题很窄：让一个被识别的工具延续留在成功投递前一工具调用的来源上，既不把池变成会话级绑定，也不放宽允许服务的来源。

## Decision

- 在新模块 `src-tauri/src/ai_gateway/pool_context_hold.rs` 中承载该决策。候选解析、加权排序、探测、key 轮换、协议转换与传输仍留在各自既有模块中；本模块只决定一个当前仍健康的候选是否前移到已计划池顺序的最前面。
- 仅对命名当前启用池别名的请求解析延续作用域。作用域组合：第一个匹配任一被接受凭据头且被配置为启用的本地 key 的身份（绝不取凭据值）、既有优先级解析出的会话头、提供的非空 `thread-id`、池 id、其公共别名与入站协议。缺少可识别会话头，或该 ingress 没有历史数组的请求保持普通路由且不产生作用域。
- 以结构而非内容等价来识别延续。保留的调用方历史必须是精确结构前缀，指令/工具上下文必须完全相同，追加片段中不得出现用户消息，且追加的助手/函数调用与工具结果事实必须匹配上一次成功投递响应所报告的工具调用身份。Chat 工具结果按 `tool_call_id` 匹配，Responses 的 `function_call_output` 项按 `call_id` 匹配，支持一次响应内的多个调用。前缀被改写、指令或工具改变、调用身份未知、重复的独立请求或任何其他歧义历史都会让偏好失效并走普通选择。
- 在既有写出边界上增量观察调用方流，而非缓冲整段回答。`StreamingToolObserver` 只扫描网关已写入调用方的字节，逐条 SSE 行处理，重新拼接跨分片拆分的行并同时接受 LF 与 CRLF 边界；仅保留调用方协议的工具身份（Chat `choices[].delta.tool_calls[].id`、Responses 的 `function_call` 项按 `call_id`）。注释、元数据、仅用量、`[DONE]` 与错误事件不携带工具身份并被忽略，只缓冲当前未完行，线上字节不发生任何改变。
- 仅在确认由实际服务的候选（含被允许的成功探测）完整投递的流之后，以及成功投递的非流式调用方协议响应之后，才发布偏好。本模块从已投递的非流式响应体读取工具身份，或采用流式观察器在完成的客户端流上收集到的调用方协议身份，并把请求快照、指令/工具上下文与这些身份连同精确候选身份（池、服务商、原始 local/upstream 对与生效协议）以及已解析端点一起存储。无可识别调用方协议工具调用的已完成回答（无论流式与否）关闭偏好；失败、不完整、取消、断开或首个字节后失败的请求不发布、不刷新任何内容，也绝不重放。
- 仅在被保留候选当前仍合格时才偏好它：服务商与其映射行处于启用且未被自动禁用、映射仍解析为相同生效协议、存在可用 key、端点未改变且候选未冷却。该偏好只把一个候选移到已计划顺序的最前面，并保留其余候选的相对顺序与既有探测位置；绝不新增候选、绝不把不可用或仅探测候选提到健康候选之前，也绝不绕过池别名 fail-closed 边界。
- 严格限制保留状态。存储仅存在于进程内存、按作用域键控，单调空闲超时严格超过 30 分钟（恰好 30 分钟仍有效），至多 1024 条，单条保留序列化载荷至多 1 MiB、合计至多 16 MiB，并按最近最少使用逐出。超预算证据绝不保留，也绝不存储被截断的请求。请求或响应体、请求头、凭据或偏好状态绝不写入磁盘、日志或命令，新进程从无偏好开始。
- 以单调准入令牌把每个请求登记为其作用域的最新一轮，该令牌同时约束流式完成。已完成偏好仅在其令牌仍为该作用域最新时才写入其条目，因此较旧的并发请求即使最后完成也不能替换或复活较新的已准入轮次。
- 保持普通行为不变。独立池请求、无会话头请求、新用户消息以及禁用、退役或其他不合格别名保持既有平滑加权轮询、别名 fail-closed 与普通会话亲和。该偏好只重排一个已被选中的候选；它不改变任何请求字节、key、映射健康或计费。

## Alternatives considered

- 把整个池会话在其生命周期内固定到单一来源：拒绝，因为那正是本池刻意排除的普通会话亲和行为；它会把多轮会话固定到单一来源、破坏池存在的加权轮转，而单次工具延续只需前一来源多服务一轮。
- 从用户文本、内容哈希或指纹推断连续性：拒绝，因为相同或重建的用户文本并非同一轮次的证据，而哈希会掩盖必须让偏好失效的被改写或截断前缀；直接的结构前缀与工具身份比较既更严格也可检视。
- 把仅探测或其他不合格候选提到最前：拒绝，因为偏好绝不能拓宽候选集合、绕过当前合格性判断或放宽池别名 fail-closed 边界；不可用来源保持其正常 fallback 位置，健康候选继续服务。
- 把保留历史放到磁盘或用量日志中：拒绝，因为该偏好是临时的，绝不持久化请求体、请求头或凭据；一个有界、每次启动为空白的进程内存存储已经足够。
- 在作用域内串行化请求以裁决顺序：拒绝，因为网关绝不新增请求并发限制；单调准入令牌无需跨网络 I/O 持锁即可拒绝过时发布。

## Consequences

- 在已识别的同一用户轮次内，对启用池别名的 Chat Completions 或 Responses 工具延续会在轮转推进之前先尝试成功投递前一工具调用的来源，无论该投递是缓冲还是流式；转发的请求保留工具身份、参数与结果以及公共到真实的模型映射。经既有协议适配器的流式工具调用链——Chat 入站到 Responses 上游，或到原生 Messages 上游——偏好实际投递转换后工具调用的候选，客户端可见的工具身份与完成帧保持完整。新用户消息、重复的独立请求、无会话头请求或其他作用域立即回到普通加权轮转。
- 该偏好是有界的逐轮重排而非会话绑定：普通会话亲和、平滑加权轮转、key 轮换、探测、健康结算与记账保持既有行为，被移除、禁用、自动禁用、冷却、无 key、协议改变或端点改变的任何来源都不会被偏好。
- 状态刻意临时且有界：仅存在于进程内存，在单调空闲超时严格超过 30 分钟后过期，上限为 1024 条、单条 1 MiB、合计 16 MiB 并按最近最少使用逐出，新进程从无偏好开始。失败、取消或不可投递的请求不发布也不刷新任何内容，较旧的并发请求不能覆盖较新的已准入轮次。
- 验证：`src-tauri/src/ai_gateway/tests/pool_context_hold.rs` 中 32 个网关行为测试驱动真实回环监听器、加密临时配置与进程内 mock 上游并通过（模块过滤 `cargo test --manifest-path src-tauri/Cargo.toml --lib ai_gateway::tests::pool_context_hold::`，32 通过，退出 0）。它们覆盖稳定的 Chat 与 Responses 非流式工具链、流式 Chat 与 Responses 工具链、经 Responses 上游与经原生 Messages 上游的流式 Chat 链、成功故障转移成为下一个偏好、新用户消息重新选择、重复独立请求保持轮转、无会话头工具链保持轮转、会话/线程/key/ingress 的作用域隔离、同一服务商的同级映射保持区分、被移除候选不被偏好且池绝不逃逸、超大历史与超大流式请求仍按普通路由转发、无工具调用的完成流关闭偏好、流式元数据/用量/类工具标识符事件不产生偏好、中途断开与截断流不发布偏好且绝不重放，以及乱序完成的流式结果既不能替换也不能复活较新的轮次。在显式单调时刻驱动的隔离存储上的确定性边界检查断言：恰好 30 分钟空闲仍合格、严格更久即过期；第 1025 条已完成条目逐出最近最少使用条目；单条超出预算一字节的载荷不保留并清除任何陈旧条目；恰在单条 1 MiB 与合计 16 MiB 预算上的条目保留；超出合计预算的累计条目按最近最少使用优先逐出。相邻的 `ai_gateway::tests::openai_conversion::` 套件（44 通过，退出 0）、`ai_gateway::tests::anthropic_conversion::` 套件（40 通过，退出 0）与 `ai_gateway::tests::output_timing::` 套件（39 通过，退出 0）在同一构建上为绿，确认转换与输出计时路径未变。
- 已知限制与覆盖缺口：完整有界网关套件与对已交付指南的最终对账由同一特性的后续改动完成，本记录不在此声称已交付。网关行为测试与上述三个相邻套件即证据；不承诺也不测量任何真实服务商调用、缓存命中、延迟或成本改善。
