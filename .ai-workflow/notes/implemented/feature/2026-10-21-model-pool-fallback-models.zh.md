# Agent Note: Model Pools Fall Back Through an Ordered List of Gateway Models

Status: implemented

[English](2026-10-21-model-pool-fallback-models.md) | 中文

## Problem

模型池的后备单位此前是单个服务商特定的来源候选。运营商若想让别名在一个模型的所有服务商映射耗尽后仍可服务，只能挑选一个映射、复制它的服务商身份，并手动保持其权重与推理声明同步。只要服务商集合或映射元数据变化，这个单位就会陈旧，而且它永远无法使用实际服务该本地模型的其他映射。缺失的决策是一个以网关本地模型 id 为单位的后备：它自动展开到所有服务该模型的映射，同时常规候选仍然拥有主选择权。

## Decision

- 在网关配置 schema 4 下把有序 `fallback_models: Vec<String>` 列表持久化在 `ModelPool` 上。每项是 trim 后的网关本地模型 id，仅在非空时序列化，池仍要求至少一个常规候选。项不携带 provider、上游模型、协议、权重或后备自有推理，因为被引用的映射仍是唯一事实来源。保存校验会 trim 并去重列表、拒绝空白项、拒绝当前与退役池别名，并要求每个新提交模型至少解析到一个服务商映射。未改动的已存项在其来源消失或被禁用后仍可保留与清除；保存失败不改变任何加密字节。
- 在版本门控的配置读取路径上只迁移一次。旧单一后备对象只把其 trim 后的 `local_model` 贡献为一项列表，随后删除旧键。旧 provider、上游模型、协议、权重与推理被丢弃；缺失或 null 的旧后备不产生项；当前版本文件不被改写。迁移保持无关池值、常规候选、声明、权重、默认偏好、服务商、价格与凭据不变。
- 在请求期展开。一个已存模型 id 展开为所有 trim 后本地模型等于它的服务商映射，保持服务商与映射顺序，并对每个精确来源身份只发出一次。运行时资格沿用既有来源契约：服务商启用、映射启用、入站协议兼容、可用 key 且未冷却；自动禁用映射仅经既有共享探测额度可达。状态展开包含禁用与自动禁用映射，使其可用性代码与有界原因保持可见。
- 保持顺序并轮转服务商。较早存储模型的全部来源先于较晚模型的全部来源。在单个模型内，当前合格来源按池、该后备存储模型与入站协议隔离的等权平滑加权轮询共享排序，与主顺序及其他后备模型隔离。后备阶段获得一轮尝试，沿用普通轮内 key 轮换与整个请求至多一次共享映射或 key 探测；它不安排新的延迟重试循环，也不能被已耗尽的常规重试等待预算压制。
- 只跳过实际尝试过的来源。请求级集合记录每个作为常规候选、探测或后备来源实际尝试过的精确来源；后备队列跳过已存在的成员，并让同一模型的其余来源保持资格。健康常规候选存在时后备零调用。后备绝不进入主平滑加权轮询、普通会话亲和或池延续偏好。后备成功关闭任何陈旧 primary 偏好而不发布后备偏好，而成功的常规投递保持既有延续行为，即使其本地模型也出现在后备列表中。
- 按展开来源派生推理。每个来源的原生动作来自其精确映射的 `reasoning_efforts` 与生效协议：Chat Completions 与 Responses 用 OpenAI 档位，Anthropic Messages 用 Anthropic effort-inherit 档位。只有已声明的规范档位变成映射，`none` 仅在声明时成为显式禁用；不从模型名推断控制，也不持久化后备专用声明。分类、静态目录、发现与终端载荷使用常规候选加展开后备来源的并集。保留的具体默认在其来源不可用时可保持未改动声明，但后备列表变更若移除最后一个声明会被拒绝；既有 400、502 与输出上限拒绝路径保持不变。
- 报告与常规就绪分离的有序逐模型状态。每条记录携带 trim 后的存储模型 id、就绪标志、就绪与总来源计数、展开来源状态与可选有界原因；常规候选数组与就绪仍只含常规。来源状态只暴露可用性与冷却，绝不含 key、endpoint、header 或消息体。
- 仅在成功发布后清理。自有权身份集合是旧、新配置中的常规候选加每个展开后备来源；仍被任一角色或新配置引用的身份保留。写入失败既不改变加密字节，也不改变自有的调度或冷却状态。
- 保持运营商界面有序。池对话框编辑双语、键盘可达的列表，支持添加、上移、下移、移除与清空，显示每个已存模型的服务商计数，让不可用的已存模型保持可见与可清除，并在状态或配置刷新以及保存被拒后保留未保存草稿；取消不产生任何变更。池卡片独立于常规就绪报告有序模型及其计数。没有后备专用推理编辑器，因为推理自动跟随被引用的映射。
- 保持传输、记账与路由边界。两种 OpenAI 入口、流式与非流式、三种上游协议都可在首个客户端字节前服务后备；输出开始后沿用既有入站格式错误与关闭行为，不重放也不产生第二个成功终止符。断开不能产生后续后备尝试、虚假的成功终止行或虚假的健康/偏好成功。每个完成的业务请求仍恰好有一行终止记录：其 `local_model` 是公共别名，而服务商、上游模型、用量、价格与原生推理证据标识实际来源，并保留最后观测到的上游状态（含网络状态 0）。禁用池、退役别名、原生 Messages 池入口与普通模型路由保持既有围栏。
- 记录降级边界。旧二进制忽略 `fallback_models`，因此只服务常规池、不兑现后备列表。恢复旧行为需要为同一 profile 恢复迁移前配置并配合同一本地 key；不引入自动备份或迁移框架。

## Alternatives considered

- 保留单个服务商特定的后备候选并让运营商挑选一个映射：拒绝，因为运营商必须复制服务商身份，且无法使用该模型的每个当前映射。
- 为每个后备项存储 provider、上游模型、协议、权重与推理：拒绝，因为每份副本都会与被引用映射漂移，且无法自动跟随服务商或协议变化。
- 把展开的后备来源追加到主加权顺序：拒绝，因为它们会消耗主权重与槽位，并可能取代健康常规候选。
- 为每个后备来源新增延迟退避循环重试：拒绝，因为它超出既有的有限尝试与等待边界。
- 重新尝试请求已经尝试过的来源：拒绝，因为它会复用唯一有界的一轮，且不能改变该精确来源已经结算的结果。
- 要求每个后备项显式声明推理：拒绝，因为该项是模型 id，必须继承当前映射元数据，而不是携带第二份声明。
- 把后备就绪计入常规数组或计数：拒绝，因为运营商需要常规就绪保持仅含常规。
- 静默忽略不可用的已存模型或替换成另一个映射：拒绝，因为运营商必须保留或显式清除精确的已存项。
- 为降级新增自动配置备份或迁移框架：拒绝，因为既有显式配置恢复已足够，且不需要新的持久机制。

## Consequences

- 池别名现在可以指定有序的网关模型列表作为最后手段。每个模型的当前映射全部合格，因此服务商集合与映射编辑无需修改后备项即可生效。
- 服务商在单个已存模型内、以池、模型与入站为作用域等权轮转，而存储模型顺序仍决定先尝试哪个模型。只跳过实际尝试过的来源，健康常规候选让后备保持零调用。
- 推理支持自动跟随精确映射元数据与协议，因此分类、静态目录、发现与终端载荷与真正能服务请求的来源保持一致。
- 状态保持清晰：常规就绪仍只含常规，每个有序后备模型报告自己的就绪与总来源计数、不可用来源与有界原因。
- 配置经一次读取路径迁移进入 schema 4；无关池值与当前版本文件不被触碰。旧二进制忽略该列表，恢复旧行为需要恢复迁移前配置；不存在自动备份。
- 传输、终端记账与延续边界不变：后备只在首个客户端字节前服务，单条终止记录标识真实来源，后备成功关闭陈旧 primary 偏好但不成为偏好，断开不能伪造成功。
- 验证：四个限定后端套件分别以 67、47、31、19 例通过且均 exit 0；有界网关套件 1101 通过、0 失败、46 个既有忽略且 exit 0。五文件前端 vitest 运行 320/320 通过、0 失败；限定 eslint exit 0（0 错误、4 个既有警告），`npm run build` exit 0。原生 Tauri IPC、真实上游推理与真实终端投影未执行，也不声称截图证据。
- 部分取代：[Model Pools Use an Explicit Last-Stage Fallback Source](2026-10-20-model-pool-default-fallback.md) 予以保留并交叉引用。本记录仅取代其选择形状（单个可选、服务商特定的候选）与来源展开行为（单个精确映射），包括 schema 3 的加性无迁移形态、独立的可选后备状态与单一「Default fallback model」选择器。该记录的最后阶段位置、真实来源契约、推理并集保证、首字节边界与同轮延续保证继续有效。
