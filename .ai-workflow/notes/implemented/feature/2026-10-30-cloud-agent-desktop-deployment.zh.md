# Agent Note: Cloud Agent Desktop Deployment

Status: implemented

[English](2026-10-30-cloud-agent-desktop-deployment.md) | 中文

## Problem

操作者通过 SSH 使用 Cloud Agent 控制台，但在此变更之前控制台只能管理已经安装的 Agent；首次安装需要从源码检出目录手工运行服务端部署脚本。随包的 server 包与桌面应用也没有共享的「实际随包发布的 Cloud Agent 版本」声明；在 Python 可用之前，既有主机无法被判为空目录、部分发布或完整安装；也没有一个显式动作完成安装、选中该确切主机并在之后做健康检查。

## Decision

### Release identity and version sources

- `server/onespace-cloud-agent/VERSION` 是 Cloud Agent 发布的权威版本标识。CLI 部署器与桌面应用随包发布并部署携带该版本的同一份载荷，初始语义版本只是包自身的选择，与 OneSpace 应用及 OpenCode 的版本无关。
- 「本地最新」指当前 OneSpace 安装随包携带的包。不会查询互联网发布版本，因此更晚发布的新版本不会改变控制台报告或上传的内容。
- 远端 `VERSION` 报告已部署的代码版本，远端 `install-info.json` 携带 `version` 与 UTC ISO-8601 的 `installed_at`。两者是独立文件：安装元数据只在代码、启动器与单元发布完成且服务经验证处于 active 之后写入，与远端 `VERSION` 不一致的元数据版本不能提供当前安装时间。
- 未知版本与未记录时间保持区分。仅有 `VERSION` 时给出的是有版本但无记录时间；文件的 mtime 与当前时间都不能替代安装时间；有效时间以用户所在语言环境的本地时区展示，并明确时区。

### Prerequisites

- 新部署要求 Linux、root 权限、可访问的 systemd 以及 amd64 或 arm64。
- 只有在缺少运行时依赖时才要求 Ubuntu 22.04/24.04 或 Debian 12；当五项依赖均已可执行时，满足通用平台要求的其他发行版也被接受。
- 只安装缺失的 `python3`、`git`、`tmux`、`gh` 与 `opencode`，来源为官方渠道，既有可执行文件被保留且绝不升级。GitHub 认证不是部署门禁，模型凭据仍独立配置。

### Desktop handoff and deployment state

- 在 Python 可用之前，检查使用 shell 原语的文件存在性，把目标判为 installed、incomplete、not installed 或 probe error。非空且无可识别载荷的目录是路径冲突，配置错误也不等于 Agent 不存在。
- 完整安装绝不静默重装。incomplete 目标只有在本应用进程内持有同一 host 与安装路径的既有失败部署凭据时才可重试；该凭据在重启后消失，之后需要人工修复。
- 同一时刻最多只有一个部署。对话框在变更期间捕获目标并锁定目标与关闭操作，只消费匹配 operationId 的阶段进度；不提供取消 API，也不持久化作业日志，截止时间为 15 分钟，应用退出时清理本地进程组。
- 部署命令不做独立的安装后在线状态测试。成功后控制台选中被捕获的目标，同步使此前的宿主读取失效，在变更期间暂停轮询，并恰好执行一次新的状态刷新，即使该目标此前已被选中。之后的状态测试失败会让该主机保持选中并保留安装信息，同时提供只读重试。
- 部署绝不写入桌面 Cloud Agent 设置，绝不初始化本地设置文件，绝不导出凭据，也绝不改变已保存的默认主机。

### Self-contained resources

- 已安装的应用无需源码检出即可部署：`bundle.resources` 中显式的 13 个文件允许清单包含部署器、引导脚本、`VERSION`、默认与示例配置、`agent.py`、六个核心 Python 模块以及 systemd 单元，并通过 Tauri 资源路径解析，没有源码检出回退。
- 测试、本地 `config.json`、`.env` 文件与凭据不进入包。本地载荷与 `VERSION` 在任何 SSH 变更之前完成校验，控制台展示的本地版本就是上传载荷的版本。

## Alternatives considered

- 增加升级与卸载界面：未采纳，因为本次变更只交付首次部署；既有安装保持只读且可选择，升级或移除仍由操作者执行。
- 构建持久化部署作业引擎：未采纳，因为单个进程内部署守卫、匹配的进度事件与有界截止时间已覆盖单操作者场景，无需作业存储。
- 增加后端语义版本比较器：未采纳，因为前端已负责展示与比较，两个比较器可能得出不同结论。
- 为「本地最新」查询互联网发布版本：未采纳，因为随包发布的包定义了本次安装能够部署的内容。
- 增加自动回滚或在超时后声称已回滚：未采纳，因为超时后远端状态不确定，后续动作应检查实际状态而不是断言已恢复。
- 在不受支持的发行版上自动安装前置依赖：未采纳，因为其软件源与服务管理未经验证；发行版门禁只在缺少依赖时生效。

## Consequences

- 控制台新增 Deploy server 入口、展示远端版本/本地最新/安装时间的安装摘要、带目标检查与锁定提交的部署对话框，以及运行卡片上的只读重试动作。
- 前端负责语义版本比较与安装时间格式化。非法或缺失版本产生未知比较，可选 `v` 前缀、数值与预发布优先级以及构建元数据相等性遵循语义版本排序。
- 没有 `VERSION` 或元数据的旧版安装仍被视为已安装并可选择，展示未知版本与未记录时间，缺少历史元数据绝不授权重新部署。
- 失败保留既有内容：预检、上传或发布失败不会改动活跃文件、配置与快照，既有配置在重试时保持逐字节一致，非法 JSON 拒绝发布，失败前已安装的操作系统包不回滚。
- 已知缺口：未执行真实 root 服务器部署冒烟；静态资源检查不能证明原生 GUI 交互；更新器产物签名需要发布密钥，本地不可用；部分操作系统包安装不会被回滚。
