# Agent Note: Model Pools Route One Public Alias Across Explicit Source Candidates

Status: implemented

English | [中文](2026-10-13-free-model-pool.zh.md)

## Problem

The gateway exposed each public model id through exactly one provider mapping row. Operators who held several free or promotional mappings — for example two mappings of one provider, or several accounts — had no way to publish them as a single public model: clients had to know an individual mapping's local model name, every mapping carried its own health, and a model-scoped limit on one mapping had no boundary that kept it away from the others. There was also no persisted place to say that these exact source mappings form one public model, rotate among them, and never fall through to an ordinary paid default once the free sources are exhausted. A pool may also select a candidate whose stored OpenAI endpoint differs from the client's, but the ordinary gateway forwarded an OpenAI request only to the candidate's own endpoint and converted OpenAI to native Anthropic Messages, so a Chat Completions client could not be served faithfully by a Responses candidate (or the reverse). This record covers the backend routing, storage and validation boundary, the pool-only OpenAI protocol conversion and portable request contract, and the operator surface, model discovery and terminal payload integration.

## Decision

- Persist two `#[serde(default)]`, always-serialized `GatewayConfig` fields without changing the schema: `model_pools: Vec<ModelPool>` and `model_pool_reserved_models: Vec<String>`. `GATEWAY_CONFIG_SCHEMA_VERSION` stays 3 and no migration is added, so a configuration written before pools existed loads as an empty collection. `ModelPool { id, name, model, enabled, candidates }` exposes `model` as the public model id; `ModelPoolCandidate { provider_id, local_model, upstream_model, protocol, weight }` is one exact reference to an existing provider mapping row, with `weight` defaulting to 1 and bounded to 1..=100; `PoolCandidateIdentity { pool_id, provider_id, local_model, upstream_model, protocol }` is the transport-only identity of one prepared candidate. The additive optional `fallback` member reuses that candidate shape for a last-stage source outside this rotation, as recorded in [Model Pools Use an Explicit Last-Stage Fallback Source](2026-10-20-model-pool-default-fallback.md). A pool record never copies a source key or endpoint.
- Own the pool boundary in a new `src-tauri/src/ai_gateway/model_pools.rs`. `plan_pool_request` runs before any ordinary candidate is built: it matches the exact trimmed alias against the current pools, and a reserved retired alias fails closed; a disabled pool, an `AnthropicMessages` inbound request for a pool alias, or a pool with no usable candidate and no eligible probe returns the standard `all_providers_unavailable` 502 (the native `/v1/messages` entry keeps the existing Anthropic error envelope). No ordinary provider or default model can serve a current or retired pool alias.
- Resolve each candidate against the latest configuration. A candidate is available only when its provider exists, its original trimmed `(local_model, upstream_model)` mapping still resolves with the same effective protocol, the provider and mapping are enabled and not auto-disabled, the candidate can serve the inbound protocol, and the provider has a usable key. `prepare_provider` clones the real provider, key pool and endpoint into a one-mapping routing copy, rewrites the local model to the pool alias, clears `default_model` so no unselected sibling can be selected, and attaches the transport-only `pool_candidate` identity.
- Order the healthy candidates with a pool-scoped smooth weighted round robin. The scheduler key is the pool id plus the complete candidate identity (provider, original local/upstream pair, stored protocol) plus the ingress protocol, so two pools, two same-provider models and the Chat/Responses entries routing to one stored candidate each own an independent cycle. Pool requests never read or write the ordinary session-affinity binding; a recognized same-turn pool tool continuation uses only its own bounded continuation preference described in [Model Pools Prefer the Preceding Candidate for Same-Turn Tool Continuations](2026-10-15-model-pool-context-hold.md). Only available candidates consume a primary slot; at most one mapping or key half-open probe is appended after the healthy candidates and never widens beyond the pool's selected set.
- Settle health, diagnostics and accounting on the real source. `attempt_policy::resolved_health_target` returns the stored original provider/local/upstream mapping for a prepared pool candidate, so probes, retries and mapping auto-disable settle on the real row. A failed pool attempt names the real provider plus the original mapping identity, and the usage log records the public alias as `local_model` with the real provider id and upstream model; pricing still uses the real source provider's price row.
- Scope recovery to the candidate. A candidate-scoped failure — a 429 whose structured `error.type` is `FreeUsageLimitError`, or a 400/402/429 message the quota classifier treats as model-scoped or unknown-scope exhaustion — records a process-memory candidate cooldown and drops only that candidate, without marking the shared key, exhausting its keys or registering mapping health. The cooldown is keyed by pool plus full candidate identity and shared across ingresses; `cool_pool_candidate` preserves the exact `Duration`, an absent or invalid delay falls back to `POOL_CANDIDATE_COOLDOWN_SECS = 60`, and a valid `retry-after-ms: 0` makes the candidate immediately eligible again. An explicit account funds/credits/budget exhaustion signal and an ordinary credential 401/403 or non-credential 403 keep the existing key, account and mapping policy.
- Expose four typed commands through `commands.rs` and `app_runtime/run_app.rs`: `ai_gateway_upsert_model_pool(pool)`, `ai_gateway_delete_model_pool(pool_id)`, `ai_gateway_set_model_pool_enabled(pool_id, enabled)` and `ai_gateway_model_pools_status()`. The upsert validates and writes under the existing serialized `storage::modify_config` primitive, so a validation or write failure changes nothing.
- Keep new references exact and old references retainable. A new candidate must resolve against the latest configuration, while a reference that was already stored stays valid after its source becomes unavailable so the operator can retain or explicitly remove it; a candidate needs nonblank fields, no duplicate tuple and a weight within range. The public model id may not collide with an ordinary mapping or another current pool. Renaming or deleting a pool pushes its previous alias into `model_pool_reserved_models`; a new pool may reuse a retired alias, and `ai_gateway_upsert_provider` rejects an ordinary mapping that would acquire a current or retired alias.
- Publish nonsecret status. `ai_gateway_model_pools_status()` returns each pool's identity and candidates with only the source identity, an availability code (`ready`, `cooling`, `source_disabled`, `mapping_unavailable`, `missing_provider`, `no_usable_key` or `unsupported_protocol`) and a cooldown deadline in epoch seconds, rounded up from the monotonic deadline. It issues no network or quota probe and persists nothing.
- Prune owned state only after a successful publication. `storage::write_config` and `storage::modify_config` diff the previously persisted pools against the published ones and call `model_pools::prune_removed_pools`, which clears the scheduler and cooldown entries owned by removed pools or candidates; a failed write prunes nothing.
- Own the OpenAI protocol conversion in two new modules. `src-tauri/src/ai_gateway/openai_conversion.rs` classifies the two canonical OpenAI paths (`is_openai_path`, `client_protocol`, `endpoint_path`) and converts pool request/response bodies; `src-tauri/src/ai_gateway/openai_sse.rs` converts pool streams. `forwarding.rs` rewrites the upstream path and body for a prepared pool candidate whose effective protocol differs from the client's; a same-protocol pool candidate keeps its endpoint. Ordinary (non-pool) routing, key policy, health settlement and Protocol Router are untouched.
- Enforce a portable request contract before selection. `openai_conversion::validate_pool_request(path, body, messages_candidate)` runs in `runtime_http.rs` before `plan_pool_request`, any candidate selection, SWRR mutation, attempt or probe, and returns a `400` that names the offending field. Each side admits only the common text/tool and control surface; an unrecognized top-level or nested field, an unrepresentable content block, a non-boolean control, a non-`text` output format or an opaque reasoning/conversation reference is rejected by field. The single recognized provider-specific exception is the historical assistant `messages[].reasoning_content` trace (a string, including empty or whitespace, or `null`): it is preserved exactly on a same-protocol Chat candidate and omitted without fabricating reasoning on a converted request, while every other unlisted field stays rejected. Chat rejects `stop`, `frequency_penalty`, `presence_penalty`, `seed`, `logit_bias`, `logprobs`, `n != 1`, nonempty `reasoning_effort`/`reasoningEffort`, non-text message content (image, file, audio) and unknown `stream_options` members; Responses rejects `previous_response_id`, `conversation`, `truncation`, `include`, `logprobs`, `n != 1`, nonempty `reasoning`, hosted tools and non-text input. A `store: true` or `background: true` is rejected with the field named while `false` (and an omitted value) is accepted. A `strict: true` function control is preserved for a pure OpenAI pool but rejected, regardless of which candidate the rotation would pick, when the pool stores at least one `anthropic_messages` candidate, because the existing Messages adapter cannot carry it; `strict: false`, the representable default, stays accepted. A request is also checked against the opposite OpenAI direction, so representability never depends on the randomly selected candidate or a temporary cooldown.
- Convert both OpenAI directions. `openai_conversion::convert_request(path, body, model, upstream)` translates the client's request to the selected candidate's OpenAI protocol and rewrites the model to the real upstream model; `openai_conversion::convert_response(path, upstream, body, model)` converts a non-streaming response back. Both directions retain full stateless text history, system/developer instructions, function schemas, tool choice and parallel controls, and call ids/arguments/results. The common sampling controls are `temperature` and `top_p`; Chat `max_completion_tokens` takes precedence over `max_tokens` and Responses uses `max_output_tokens`, supplied limits are nonnegative integers including zero, and an omitted limit stays omitted for this adapter while the existing Messages adapter keeps its own `4096` default. A same-protocol pool response is canonicalized in place, rewriting the model alias (and the nested `response.model` for a Responses body), so the caller always receives its ingress protocol and the public pool id.
- Convert streams incrementally. `openai_sse::OpenAiSseConverter` is constructed with the client path, the upstream protocol, the public model and whether the caller requested usage; `feed` buffers only up to the earliest LF or CRLF SSE boundary and `finish` flushes the trailing partial frame. It preserves stable text/tool identities, distinguishes a Responses function-call item id from its call id, emits stable output slots in first text/tool arrival order, emits the canonical Responses lifecycle (`response.created`, `response.output_item.added`, content-part and `response.output_text.delta`, `response.function_call_arguments.delta`, the matching `...done` events and `response.completed`) and exactly one terminal event (`data: [DONE]` for Chat, `response.completed` for Responses). A Chat request that supplies a boolean `stream_options.include_usage: true` gets terminal usage in the converted Chat stream without the gateway injecting the flag upstream. `is_success` and `has_in_band_error` report whether the upstream actually completed, so a malformed frame, a Responses `error`/`response.failed`/`response.incomplete` event or a `response.completed` whose status is not `completed` is never mistaken for a successful answer.
- Keep the transport boundaries. `runtime_http.rs` uses the OpenAI converter only for prepared pool candidates on an OpenAI endpoint, while a native Anthropic Messages candidate keeps the existing adapter. On the non-streaming path a conversion failure returns the standard `502` `conversion_error` envelope. Original upstream usage is observed before conversion, so pricing and logging still use the real source provider and upstream model with the public alias as `local_model`. After the first client byte a converted post-byte failure produces an ingress-format error without a success terminator and without replay, and downstream cancellation stops the upstream attempt and settles no health. The single eligible half-open probe is reused under the candidate's stored protocol and never widens to an unselected source.
- Expose the pool through a virtual operator surface beside real providers. The existing Add provider picker gains a Create model pool channel that opens the dedicated `ModelPoolDialog` and `ModelPoolCard`. The dialog seeds the default display name `Free Modle` and the default public model id `free-model`, both editable; it groups source mappings by provider behind a search box, selects them independently as checkboxes, and keeps a selected list with a per-candidate integer weight bounded to 1..100 and a per-row remove action, under a fixed cancel/save footer with a scrolling body below a fixed title. `ModelPoolCard` offers the public-id copy action, edit, candidate expansion, a log shortcut and, behind the more menu, a delete action with a second confirmation. The enable switch expresses the operator's intent separately from candidate readiness. The dialog owns its draft locally and is remounted per open or target, so a runtime status refresh never overwrites an unsaved name, selection or weight edit; a rejected save keeps the draft and surfaces the backend message, and cancel performs no write. Candidate availability is derived from the current configuration plus only that pool's own nonsecret status (`resolveModelPoolCandidateState`, `MODEL_POOL_AVAILABILITY_LABEL_KEYS`, `POOL_KEY_QUOTA_MARK_TTL_SECONDS`), so a stale snapshot never revives a disabled, removed, protocol-mismatched or key-less source and another pool's cooldown is never consulted; each candidate shows its localized availability code with any raw backend reason kept as additional detail.
- Advertise each enabled pool once and never invent capability. The model-list panel, the runtime status card and the page-tab count include every enabled configured pool exactly once, including while all of its candidates are temporarily unavailable, while a disabled or retired alias is excluded. A pool list row advertises the pool's own name and both OpenAI ingress protocols and identifies its real sources, and it never borrows a source model's reasoning variants, a Responses npm override, a fabricated free price, a combined balance or a promised traffic percentage; source account quota stays on the real provider cards. The pool status poll runs only while the page is visible and at the existing refresh cadence, with no per-card network request or inference probe.
- Publish discovery and terminal payloads from the same authoritative configuration. `runtime_http.rs` unions each enabled pool's trimmed public alias into `local_model_names` independent of transient cooldown, and `models_payload` emits exactly one `/v1/models` row per enabled pool through `pool_discovery_entry` carrying the pool `name`, the `chat_completions` and `responses` protocols, `source_count` and the real source identities, and no key, endpoint, price, reasoning variant or readiness flag. `commands.rs` adds `build_gateway_provider_with_pools`: the OpenCode catalog adds each enabled pool exactly once as a Chat-compatible row with no guessed reasoning variants and no Responses npm override; Codex retains an already selected enabled pool alias across a resync, otherwise prefers an existing ordinary default, and otherwise falls back to the first enabled pool alias; native Claude selection excludes the OpenAI pool. The four typed pool commands remain the only pool mutations, and profile ownership plus manual activation and projection rules are unchanged.

## Alternatives considered

- Store an independent provider, key and endpoint inside each pool candidate instead of referencing an existing mapping row: declined because it would duplicate credentials, break the single source of truth for endpoints and keys, and let the pool drift from the source mapping's health.
- Reuse the ordinary scheduler and session affinity for pool candidates: declined because the ordinary scheduler is keyed by provider, local model and protocol and cannot separate two same-provider sibling candidates, and session affinity would pin a pool alias to one candidate, defeating the rotation the pool exists to provide.
- Persist candidate cooldowns or issue speculative startup or network probes: declined because they are out of scope; cooldowns stay in process memory and the existing per-request probes remain at most one.
- Let a disabled or retired alias fall through to the ordinary route: declined because a stale client could then send a retired free-model alias to an unrelated paid default; the alias boundary must fail closed.
- Mark the shared key on a candidate-scoped model limit: declined because a model-scoped quota would take a key shared by healthy sibling models out of service; only that candidate cools, while explicit account exhaustion keeps the existing account and key policy.
- Bump the configuration schema or add a migration for the pool fields: declined because `#[serde(default)]` already keeps older files readable, so the schema stays 3 with no migration.
- Reuse Protocol Router's lossy text-flattening and buffered conversion for the pool path: declined because it drops tool history and cannot preserve the incremental wire shapes the pool contract requires.
- Silently drop a field that cannot be transferred: declined because a caller could not tell that its stop, seed or JSON-schema control was ignored; each field is either translated faithfully or rejected by name before selection.
- Inject `stream_options.include_usage` upstream to obtain usage: declined because the gateway must not alter the upstream request the caller described; the converted Chat stream honors the caller's boolean without injecting it.
- Convert image, file, audio or hosted-tool state: declined because they are outside the common text/tool contract and cannot be represented faithfully in both directions.
- Reuse a real provider card and its dialog as the pool editor: declined because the pool carries a public alias, a multi-source selection and candidate weights that a provider record cannot hold, and the existing provider surfaces must keep their own semantics.
- Show an aggregate pool weight, a promised traffic percentage or a free-price/combined-balance badge: declined because the pool owns no balance, a candidate may be unpriced or repriced by its source, and a rotation weight is per request rather than a quota.
- Infer reasoning variants or a Responses npm override for an OpenCode pool entry: declined because the pool advertises only the common text/tool surface and must not guess a source model's capability.
- Let a pool automatically replace an ordinary Codex default or a native Claude choice: declined because the pool is OpenAI-only and must not silently displace an operator's existing ordinary or native selection.

## Consequences

- A current pool alias routes only through its selected candidates under a pool-scoped weighted rotation, and a disabled or retired alias fails closed instead of reaching an ordinary source or default. An existing `anthropic_messages` candidate is served through the existing adapter exactly as an ordinary route already is, while a candidate on either OpenAI endpoint is served through the new pool-only conversion.
- Both OpenAI protocols interoperate for pool requests in both directions, including same-protocol canonicalization, and a request that cannot be represented in the other direction now fails with a field-named `400` before any candidate, SWRR mutation or health/key change.
- Health, probes and diagnostics stay on the real source row: mapping auto-disable, key rotation and the all-unavailable message name the real provider and the original mapping, and the usage log keeps the public alias with the real provider and upstream model.
- Converted streams are incremental and complete correctly, preserving text/tool order and stable identities, and the caller receives its own protocol and public alias; a malformed or errored stream is never reported as success and is never replayed after the first byte.
- Configuration compatibility and rollback: the schema stays 3 with two serde-default fields, so an older binary reads the file but may drop the pool fields; returning to an older binary requires preserving the same-profile encrypted configuration and matching key material, and the retired aliases are not protected by that older writer.
- Operators configure and inspect the pool from the existing surfaces: Create model pool opens the dedicated dialog with the `Free Modle` / `free-model` defaults, provider-grouped search, independent multiselect, per-candidate integer weights and a fixed cancel/save footer; saved pools render as virtual cards beside real providers with copy, edit, candidate expansion, a log shortcut through the existing request-log query state and a delete action behind a second confirmation; readiness stays distinct from enabled intent. Each enabled pool appears exactly once in the UI model list and `/v1/models` with both OpenAI protocols and its real sources, and manual OpenCode and Codex sync can use the alias while native Claude selection excludes it.
