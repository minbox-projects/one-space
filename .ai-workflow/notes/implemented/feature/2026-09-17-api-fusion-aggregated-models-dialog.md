# Agent Note: API Gateway Aggregated Models Open in a Dialog With a Shared Count

Status: implemented

English | [中文](2026-09-17-api-fusion-aggregated-models-dialog.zh.md)

## Problem

The `Aggregated models` metric card on the `api-gateway` page showed a number the user could not inspect: clicking it switched the page to the `providers` tab, which lists upstream providers rather than aggregated local models. The card also counted the models itself, de-duplicating each `enabled && !auto_disabled` provider's `default_model` and mapping `local_model` values inside `RuntimeStatusCard.tsx`, so the metric carried its own definition of what the local gateway aggregates and any model list would have needed a second implementation that could disagree with it.

## Decision

The aggregated local models were moved out of the card into one shared aggregation: the card derives its number with `aggregateModels(config.providers).length` instead of counting for itself, and every aggregated-models surface renders the same `aggregateModels` result, so a count cannot disagree with the list it describes. This record originally delivered that list as `src/components/ApiGateway/AggregatedModelsDialog.tsx`, opened through the card's optional `onShowModels` prop and the page's `isModelsDialogOpen` state; [API Gateway Aggregated Models Open the Model List Tab Instead of a Dialog](../simplification/2026-09-21-gateway-aggregated-models-open-model-list-tab.md) removed that dialog surface on 2026-09-21, the `Model list` tab became the single aggregated-models list surface, and the card now selects it through `onSelectTab("models")`. The shared-aggregation and single-count decisions above remain in force.

`src/lib/apiGateway.ts` exports the aggregation as the public `aggregateModels(providers: GatewayUpstreamProvider[]): AggregatedModel[]` function together with the `AggregatedModel` (`model`, `providers`) and `AggregatedModelProvider` (`providerId`, `providerName`, `upstreamModel`, `endpoint`, `isDefault`) interfaces. A provider contributes while `enabled`, and only its enabled, not auto-disabled mappings contribute rows: each such mapping whose trimmed `local_model` and trimmed `upstream_model` are both non-blank is added with the trimmed `upstream_model` and `mapping.protocol ?? provider.protocol ?? "chat_completions"`. The provider's `default_model` is a fallback target for unmapped requests and is not aggregated as a row, so every source carries `isDefault: false` while the flag and its `Default` badge stay part of the interfaces. Mappings with a blank `upstream_model` are skipped so that every entry has a non-empty `upstreamModel`, matching the backend rule in `src-tauri/src/api_gateway/selection.rs` that treats an empty `upstream_model` as a miss and the existing `resolveMappingPreview`. Entries are grouped by local model, sources within one model are ordered by provider name and then upstream model, and models are ordered by name, so both the count and the list order are deterministic.

The list surface renders every aggregated local model with one row per upstream source (`providerName → upstreamModel`, an endpoint chip showing the path form `/responses` or `/chat/completions`, and a `Default` badge on default entries); the `Model list` tab that replaced the dialog keeps this presentation. The path form follows the existing convention in `src/components/ApiGateway/UpstreamProviderDetail.tsx`; the raw `chat_completions` / `responses` enum is not displayed. The metric card title keeps the `apiGatewayAggregatedModels` key, and `src/i18n.ts` keeps `apiGatewayAggregatedModelsDialogDesc` and `apiGatewayAggregatedModelDefaultBadge` for both languages; after the dialog removal, `apiGatewayAggregatedModelsEmpty` has no code reference ([API Gateway Aggregated Models Open the Model List Tab Instead of a Dialog](../simplification/2026-09-21-gateway-aggregated-models-open-model-list-tab.md)).

`AggregatedModelProvider` also carries an optional `displayName` for the model list tab added later: `aggregateModels` sets it only for mapping sources whose trimmed `mapping.display_name` is non-empty and never on a provider default source, and `src/lib/apiGateway.ts` exports `resolveAggregatedModelName` to resolve a model's display name. [API Gateway Model List Tab Reuses the Shared Aggregation](2026-09-18-api-gateway-model-list-tab.md) records that decision; the shared-aggregation and single-count decisions above still stand, while the dialog surface this record introduced is superseded by [API Gateway Aggregated Models Open the Model List Tab Instead of a Dialog](../simplification/2026-09-21-gateway-aggregated-models-open-model-list-tab.md).

## Alternatives considered

- Keep switching to the `providers` tab on click: declined because that tab lists upstream providers instead of the aggregated local models, so the number stayed uninspectable and no local model was connected to the upstream sources behind it.
- Let the dialog group the models itself while the card keeps its own de-duplicating count: declined because the card number and the dialog would then be two implementations of the same aggregation, and a count of aggregated models must not be able to disagree with the list it describes.
- Include providers or mapping rows the gateway refuses to serve in the aggregation: declined because the local gateway serves only user-enabled providers and their user-enabled, not auto-disabled mapping rows, so listing the others would advertise models the gateway refuses to serve.

## Consequences

- The shared count is current: the metric card renders `aggregateModels(config.providers).length` and no longer computes a count of its own. The click-through behavior recorded here was replaced: [API Gateway Aggregated Models Open the Model List Tab Instead of a Dialog](../simplification/2026-09-21-gateway-aggregated-models-open-model-list-tab.md) makes the card select the `Model list` tab on click and on Enter/Space instead of opening a dialog, and `onSelectTab` stays optional so the card still renders as a plain card when the prop is absent.
- The number on the card and the rows in the aggregated list come from the same call: `aggregateModels` groups user-enabled providers by local model and takes each user-enabled, not auto-disabled mapping whose trimmed `local_model` and trimmed `upstream_model` are both non-blank with the endpoint value `mapping.protocol ?? provider.protocol ?? "chat_completions"`; blank-`upstream_model` mappings contribute nothing, so `upstreamModel` is always non-empty. The provider's `default_model` is not aggregated, so an unmapped fallback never appears as a row and no entry carries `isDefault: true`.
- `src/lib/apiGateway.ts` publicly exports `aggregateModels`, `AggregatedModel` and `AggregatedModelProvider`; `src/components/ApiGateway/AggregatedModelsDialog.tsx` and its `AggregatedModelsDialog` export were removed by [API Gateway Aggregated Models Open the Model List Tab Instead of a Dialog](../simplification/2026-09-21-gateway-aggregated-models-open-model-list-tab.md).
- `src/i18n.ts` keeps `apiGatewayAggregatedModelsDialogDesc`, `apiGatewayAggregatedModelsEmpty` and `apiGatewayAggregatedModelDefaultBadge` in English and Chinese, and the metric card title still reuses `apiGatewayAggregatedModels`; the model list panel uses `apiGatewayAggregatedModelsDialogDesc` and `apiGatewayAggregatedModelDefaultBadge`, while `apiGatewayAggregatedModelsEmpty` became unreferenced when the dialog was removed ([API Gateway Aggregated Models Open the Model List Tab Instead of a Dialog](../simplification/2026-09-21-gateway-aggregated-models-open-model-list-tab.md)).
- Behavior coverage in `src/components/ApiGateway/ApiGateway.test.tsx` was updated with the dialog removal and now asserts that clicking the metric card, or pressing Enter or Space on it, selects the `Model list` tab, that the rendered model rows equal the number on the card, that the endpoint renders `/chat/completions` rather than the raw `chat_completions` enum, and that a configuration without enabled providers shows the panel's empty state ([API Gateway Aggregated Models Open the Model List Tab Instead of a Dialog](../simplification/2026-09-21-gateway-aggregated-models-open-model-list-tab.md)). `src/lib/apiGateway.test.ts` covers `aggregateModels` grouping, ordering, trimmed local and upstream models, a mapping whose trimmed `upstream_model` is blank contributing nothing, an auto-disabled row excluded while a healthy row of a shared model and a provider whose legacy `auto_disabled` is set still contribute, a model provided only by auto-disabled rows producing no entry, the `default_model` never contributing an entry, and empty input.
- The `api-gateway` feature in `.ai-workflow/index/navigation.json` no longer lists `src/components/ApiGateway/AggregatedModelsDialog.tsx` or the `AggregatedModelsDialog` symbol; the shared-aggregation symbols this record registered — `aggregateModels`, `AggregatedModel` and `AggregatedModelProvider` — remain registered, and `navigation.md` is regenerated from that JSON.
- Partial supersession: this record is retained and cross-linked by [Gateway Per-Model Mapping Disable Is an Explicit Exclusion](../architecture/2026-09-18-gateway-per-mapping-disable.md), which narrows the mapping-selection predicate above so that only user-enabled mapping rows contribute, and by [Gateway Per-Model Auto-Disable Settles Health on the Mapping Row](../architecture/2026-09-20-gateway-per-model-auto-disable.md), which narrows it further to rows that are also not auto-disabled and makes the provider predicate `enabled` alone; the shared-aggregation and single-count decisions here still stand, while the dialog surface this record introduced is superseded by [API Gateway Aggregated Models Open the Model List Tab Instead of a Dialog](../simplification/2026-09-21-gateway-aggregated-models-open-model-list-tab.md). The later removal of `default_model` entries is the current standard recorded in `MEMORY.md`. The usage-stats and request-log pages, the local-key create flow and the terminal-sync contract are unaffected.
- Supersession review for the model list tab: [API Gateway Model List Tab Reuses the Shared Aggregation](2026-09-18-api-gateway-model-list-tab.md) extends this record with the optional `displayName` and the tab, while the partial supersessions by [Gateway Per-Model Mapping Disable Is an Explicit Exclusion](../architecture/2026-09-18-gateway-per-mapping-disable.md) and [Gateway Per-Model Auto-Disable Settles Health on the Mapping Row](../architecture/2026-09-20-gateway-per-model-auto-disable.md) recorded above remain in force; [API Gateway Aggregated Models Open the Model List Tab Instead of a Dialog](../simplification/2026-09-21-gateway-aggregated-models-open-model-list-tab.md) later removed the dialog and made that tab the single aggregated-models list surface. The usage-stats, local-key, error-handling and bilingual-notes records are unrelated.
- `MEMORY.md` carries the current aggregation standard — user-enabled providers contribute, a row contributes only while user-enabled and not auto-disabled, and `default_model` is not aggregated — and records that the metric card switches to the `Model list` tab, so the later narrowing is recorded there.
