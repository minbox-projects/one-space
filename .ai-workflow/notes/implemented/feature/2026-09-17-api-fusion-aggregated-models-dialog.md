# Agent Note: API Gateway Aggregated Models Open in a Dialog With a Shared Count

Status: implemented

English | [中文](2026-09-17-api-fusion-aggregated-models-dialog.zh.md)

## Problem

The `Aggregated models` metric card on the `api-gateway` page showed a number the user could not inspect: clicking it switched the page to the `providers` tab, which lists upstream providers rather than aggregated local models. The card also counted the models itself, de-duplicating each `enabled && !auto_disabled` provider's `default_model` and mapping `local_model` values inside `RuntimeStatusCard.tsx`, so the metric carried its own definition of what the local gateway aggregates and any model list would have needed a second implementation that could disagree with it.

## Decision

The aggregated local models are now shown in `src/components/ApiGateway/AggregatedModelsDialog.tsx`, and the metric card opens that dialog. `RuntimeStatusCard.tsx` no longer changes tabs from the card: it calls a new optional `onShowModels` prop from both the click handler and the Enter/Space keydown handler, and it derives its number with `aggregateModels(config.providers).length`, so the card and the dialog share one aggregation. `src/components/ApiGateway/index.tsx` owns the new `isModelsDialogOpen` state and renders the dialog with `open`, `onOpenChange` and `providers={config.providers}`.

`src/lib/apiGateway.ts` exports the aggregation as the public `aggregateModels(providers: GatewayUpstreamProvider[]): AggregatedModel[]` function together with the `AggregatedModel` (`model`, `providers`) and `AggregatedModelProvider` (`providerId`, `providerName`, `upstreamModel`, `endpoint`, `isDefault`) interfaces. A provider contributes while `enabled`, and only its enabled, not auto-disabled mappings contribute rows: each such mapping whose trimmed `local_model` and trimmed `upstream_model` are both non-blank is added with the trimmed `upstream_model` and `mapping.protocol ?? provider.protocol ?? "chat_completions"`. The provider's `default_model` is a fallback target for unmapped requests and is not aggregated as a row, so every source carries `isDefault: false` while the flag and its `Default` badge stay part of the interfaces. Mappings with a blank `upstream_model` are skipped so that every entry has a non-empty `upstreamModel`, matching the backend rule in `src-tauri/src/api_gateway/selection.rs` that treats an empty `upstream_model` as a miss and the existing `resolveMappingPreview`. Entries are grouped by local model, sources within one model are ordered by provider name and then upstream model, and models are ordered by name, so both the count and the dialog order are deterministic.

The dialog lists every aggregated local model with one row per upstream source (`providerName → upstreamModel`, an endpoint chip showing the path form `/responses` or `/chat/completions`, and a `Default` badge on default entries), and renders the new `apiGatewayAggregatedModelsEmpty` copy when there is nothing to list. The path form follows the existing convention in `src/components/ApiGateway/UpstreamProviderDetail.tsx`; the raw `chat_completions` / `responses` enum is no longer displayed. Its title reuses the existing `apiGatewayAggregatedModels` key, and `src/i18n.ts` gains `apiGatewayAggregatedModelsDialogDesc` and `apiGatewayAggregatedModelDefaultBadge` for both languages.

`AggregatedModelProvider` also carries an optional `displayName` for the model list tab added later: `aggregateModels` sets it only for mapping sources whose trimmed `mapping.display_name` is non-empty and never on a provider default source, and `src/lib/apiGateway.ts` exports `resolveAggregatedModelName` to resolve a model's display name. [API Gateway Model List Tab Reuses the Shared Aggregation](2026-09-18-api-gateway-model-list-tab.md) records that decision; the dialog and metric-card decisions above still stand.

## Alternatives considered

- Keep switching to the `providers` tab on click: declined because that tab lists upstream providers instead of the aggregated local models, so the number stayed uninspectable and no local model was connected to the upstream sources behind it.
- Let the dialog group the models itself while the card keeps its own de-duplicating count: declined because the card number and the dialog would then be two implementations of the same aggregation, and a count of aggregated models must not be able to disagree with the list it describes.
- Include providers or mapping rows the gateway refuses to serve in the aggregation: declined because the local gateway serves only user-enabled providers and their user-enabled, not auto-disabled mapping rows, so listing the others would advertise models the gateway refuses to serve.

## Consequences

- Clicking the `Aggregated models` metric card, or pressing Enter or Space while it is focused, opens the aggregated-models dialog; it no longer changes the active tab, and `onShowModels` stays optional so the card still renders as a plain card when the prop is absent.
- The number on the card and the rows in the dialog come from the same call: `aggregateModels` groups user-enabled providers by local model and takes each user-enabled, not auto-disabled mapping whose trimmed `local_model` and trimmed `upstream_model` are both non-blank with the endpoint value `mapping.protocol ?? provider.protocol ?? "chat_completions"`; blank-`upstream_model` mappings contribute nothing, so `upstreamModel` is always non-empty. The provider's `default_model` is not aggregated, so an unmapped fallback never appears as a row and no entry carries `isDefault: true`.
- `src/lib/apiGateway.ts` publicly exports `aggregateModels`, `AggregatedModel` and `AggregatedModelProvider`, and `AggregatedModelsDialog` is exported from the new `src/components/ApiGateway/AggregatedModelsDialog.tsx`.
- `src/i18n.ts` gains `apiGatewayAggregatedModelsDialogDesc`, `apiGatewayAggregatedModelsEmpty` and `apiGatewayAggregatedModelDefaultBadge` in English and Chinese; the dialog title reuses `apiGatewayAggregatedModels`.
- Behavior coverage in `src/components/ApiGateway/ApiGateway.test.tsx` asserts that clicking the metric card, or pressing Enter or Space on it, opens the dialog without switching the active tab; that the rendered model rows equal the number on the card; that the endpoint chip renders `/chat/completions` rather than the raw `chat_completions` enum; that only user-enabled providers and their user-enabled, not auto-disabled mappings contribute rows, with a user-disabled mapping and an unmapped `default_model` excluded; and that a configuration without enabled providers shows the empty state. `src/lib/apiGateway.test.ts` covers `aggregateModels` grouping, ordering, trimmed local and upstream models, a mapping whose trimmed `upstream_model` is blank contributing nothing, an auto-disabled row excluded while a healthy row of a shared model and a provider whose legacy `auto_disabled` is set still contribute, a model provided only by auto-disabled rows producing no entry, the `default_model` never contributing an entry, and empty input.
- The `api-gateway` feature in `.ai-workflow/index/navigation.json` lists `src/components/ApiGateway/AggregatedModelsDialog.tsx` in `related_files` and `read_scope` and registers the four new public symbols, and `navigation.md` is regenerated from that JSON.
- Partial supersession: this record is retained and cross-linked by [Gateway Per-Model Mapping Disable Is an Explicit Exclusion](../architecture/2026-09-18-gateway-per-mapping-disable.md), which narrows the mapping-selection predicate above so that only user-enabled mapping rows contribute, and by [Gateway Per-Model Auto-Disable Settles Health on the Mapping Row](../architecture/2026-09-20-gateway-per-model-auto-disable.md), which narrows it further to rows that are also not auto-disabled and makes the provider predicate `enabled` alone; the shared aggregation dialog and count decision here still stands, and the later removal of `default_model` entries is the current standard recorded in `MEMORY.md`. The usage-stats and request-log pages, the local-key create flow and the terminal-sync contract are unaffected.
- Supersession review for the model list tab: [API Gateway Model List Tab Reuses the Shared Aggregation](2026-09-18-api-gateway-model-list-tab.md) extends this record with the optional `displayName` and the tab, while the partial supersessions by [Gateway Per-Model Mapping Disable Is an Explicit Exclusion](../architecture/2026-09-18-gateway-per-mapping-disable.md) and [Gateway Per-Model Auto-Disable Settles Health on the Mapping Row](../architecture/2026-09-20-gateway-per-model-auto-disable.md) recorded above remain in force; the usage-stats, local-key, error-handling and bilingual-notes records are unrelated.
- `MEMORY.md` carries the current aggregation standard — user-enabled providers contribute, a row contributes only while user-enabled and not auto-disabled, and `default_model` is not aggregated — so the later narrowing is recorded there.
