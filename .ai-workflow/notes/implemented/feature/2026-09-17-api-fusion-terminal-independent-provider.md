# Agent Note: API Fusion Terminal Sync Writes an Independent Gateway Provider

Status: implemented

English | [中文](2026-09-17-api-fusion-terminal-independent-provider.zh.md)

## Problem

API Fusion's terminal sync previously overwrote the user's existing `opencode` / `codex` service provider records in place, replacing only their `base_url` and `api_key`. That approach worked only when such a record already existed, silently mutated the user's own provider configuration, and could not express a gateway the user never activated. It also had nowhere to carry the gateway's model mapping list, so the tool could not display the models the gateway exposes.

## Decision

`api_fusion_configure_terminal` / `api_fusion_sync_terminal` no longer rewrite existing records. For each supported tool (`opencode`, `codex`) the backend creates or updates exactly one independent gateway service provider named `API Gateway`, carrying the gateway's local base URL, the effective default local key, and the gateway's model mapping list, and always writes the `api_fusion_gateway` marker, recognized at the top level or under `tool_config`. The record itself never carries an activation flag; once the ledger is persisted, the backend activates the `opencode` gateway service provider and projects it to `~/.config/opencode/opencode.json` (including `options.apiKey`), while `codex` keeps manual activation and manual projection. Only user-enabled gateways contribute models, and only their user-enabled, not auto-disabled mapping rows: `opencode` writes `tool_config.models`, keyed by each such mapping's `local_model` with the value's name taken from `display_name` and falling back to the upstream model name; `codex` writes `tool_config.wire_api = chat` and sets `model` to the first non-empty user-enabled, not auto-disabled mapping `local_model` across active gateways, falls back to the first non-empty `default_model` only when no such mapping exists, and omits the key when neither is available. The provider-level `auto_disabled` field is legacy and never filters. Re-syncing reuses the `terminal_syncs` ledger provider id only while that id still names a same-tool provider carrying the gateway marker; a ledger id that now points at an unmarked user record is stale, so a new independent provider with a fresh UUID is created instead of rewriting the user's record. Only when no ledger id matches does the backend fall back to a marked gateway provider for the tool, and only when neither exists does it generate a new id. `api_fusion_terminal_targets` returns one target per supported tool and applies the same marker rule, so an unmarked provider is never reported as synced. Both commands take tool names through `target_tools` (the frontend wrapper key is `targetTools`); tool names are validated case-insensitively and stored lowercase (`opencode` / `codex`). The mapping schema gained an optional `display_name` (`Option<String>`, serde default and skipped when absent). The frontend no longer re-derives pending state and instead reads the backend-provided `target.pending_sync`; the exported `isTerminalSyncPending` helper was deleted from `src/lib/apiFusion.ts`. `claude` / `antigravity` records and Protocol Router routes remain untouched.

The terminal panel no longer offers top-level global add/sync buttons or per-target checkboxes: each tool row carries a single action button on its right side. A tool that has never been added (`hasBeenAdded = synced || synced_key_id != null || synced_at != null` is false) shows `Add provider` and issues `api_fusion_configure_terminal`; an already-added tool shows `Sync` and issues `api_fusion_sync_terminal`. The backend-provided `pending_sync` only drives the row's synced/pending badge, and a row is never disabled for lack of a default key — without an enabled local key the command is rejected with a prompt to add and enable one. Every write still happens only on the user's explicit click; the `opencode` activation and projection above then run as part of that same sync, while `codex` stays manual. If the user deleted the gateway record in `AI Environments`, pressing `Sync` creates a brand-new `API Gateway` record automatically.

## Alternatives considered

- Keep overwriting existing `opencode` / `codex` records: declined because it silently mutates the user's own provider configuration, requires a pre-existing record, cannot express an inactive gateway, and has nowhere to carry the model mapping list.
- Trust the `terminal_syncs` ledger provider id unconditionally on re-sync: declined because a stale or reused id can point at the user's own provider, so the ledger id is reused only while the target record still carries the gateway marker; an unmarked record is treated as stale and a new independent provider is created.
- Auto-activate and project the `codex` gateway too: declined because `codex` keeps manual activation and manual projection, so only the `opencode` gateway is activated and projected automatically for its entry and `options.apiKey` to land on disk.
- Include every gateway's models regardless of state: declined because the gateway's own `/v1/models` list and candidate selection serve only user-enabled gateways and their user-enabled, not auto-disabled mapping rows, so listing the others would advertise models the local service refuses to serve.
- Create a new provider on every sync: declined because repeated syncs would accumulate duplicate gateway providers; the per-tool ledger entry keeps re-sync idempotent on one marked record.

## Consequences

- Syncing `opencode` activates its `API Gateway` provider and projects it to `~/.config/opencode/opencode.json`, so the gateway entry and its key land on disk as part of that sync; `codex` still requires manual activation and manual projection in `AI Environments`.
- The ledger is keyed by tool and stores the provider id. Re-sync updates the same record only while it remains the marked same-tool gateway provider; if the record becomes unmarked, is renamed, or is deleted, the backend falls back to a marked gateway provider and otherwise creates a new independent record, never rewriting the user's own provider.
- `codex`'s single `model` is the first non-empty user-enabled, not auto-disabled mapping `local_model` across active gateways, falling back to the first non-empty `default_model` only when no such mapping exists and omitting the key otherwise.
- `ModelMapping` gained the optional `display_name` field, consumed by the gateway's model list and editable through the local-model-name input (`apiFusionLocalModelNamePlaceholder` / `apiFusionLocalModelNameAria`); the unused `apiFusionLocalModelName` key was removed from `src/i18n.ts`.
- `src/lib/apiFusion.ts` exports no pending-state helper; the terminal panel and the tab badge read the backend-provided `target.pending_sync` directly.
- The terminal panel is single-action per row with no global buttons, checkboxes, or batch sync: the row button reads `Add provider` before the first write and `Sync` (`apiFusionSyncOne`) afterwards; the orphan `apiFusionSyncSelected` key was removed and `apiFusionTerminalSyncDesc` was rewritten for the single-action panel.
- `MEMORY.md`, `docs/USAGE.md` and `navigation.json` describe the independent-provider behavior; the terminal sync tests were rewritten for it.
- Partial supersession: this record is retained and cross-linked by [Gateway Per-Model Mapping Disable Is an Explicit Exclusion](../architecture/2026-09-18-gateway-per-mapping-disable.md), which narrows the terminal-sync selection above so that `opencode` `models` and `codex` `model` take only user-enabled mappings, and by [Gateway Per-Model Auto-Disable Settles Health on the Mapping Row](../architecture/2026-09-20-gateway-per-model-auto-disable.md), which also skips auto-disabled rows and makes the gateway predicate `enabled` alone, and by [Template Sync Best-Effort Refreshes Previously Synced Terminal Tools](2026-09-23-template-terminal-resync.md), which adds a best-effort terminal refresh after a successful template sync and therefore extends this record's explicit-click write trigger; the independent gateway provider decision here still stands.
