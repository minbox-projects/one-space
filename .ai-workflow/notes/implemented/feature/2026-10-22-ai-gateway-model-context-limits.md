# Agent Note: AI Gateway Model Context Limits Are Declared Metadata

Status: implemented

English | [中文](2026-10-22-ai-gateway-model-context-limits.zh.md)

## Problem

The gateway had no owned per-model total context window. Terminal integrations need this metadata, but deriving it from model names, prices, completion limits or a second catalog would publish guesses that can exceed what a provider actually serves. Several configured sources can serve the same public model, so a single advertised value is only safe when every contributing source declares a known bound, and inherited copies must not let a stale editor or a health transition invent a larger value.

## Decision

`ProviderTemplateModel` and `ModelMapping` now carry optional `context_window: Option<u32>` measured in total context tokens. Both fields are serde-defaulted and skipped when absent, so old configuration files read as unspecified rather than zero, and the configuration schema stays at version 4 with no migration. Because the persisted type is `u32`, negative, fractional and above-`u32` declarations are rejected during decoding; a submitted zero is rejected before any write.

A template-bound provider is read-only for this field. The mapping follows the latest effective template, matched by trimmed, case-sensitive upstream model ID with the existing first-match rule, including aliases and user-disabled or automatically disabled rows. A manual template save and `ai_gateway_upsert_provider` both canonicalize submitted bound values against the latest template, so a stale dialog cannot establish an override. Creation, restoration and rebinding inherit the current template value; unbinding retains the last inherited value for later manual maintenance; removing a template model clears only that orphan inherited value without changing the existing mapping-retirement behavior; a template without the model yields unspecified.

Remote model lists are decoded only for declarations. Top-level `context_length` and nested `limit.context` each accept a positive integer or an explicit `null`; when both are declared they must agree, including both being `null`. A missing or `null` `limit` parent, or an object without `context`, declares no nested field, while any other non-object `limit` is invalid. Declarations are validated only after the existing hidden-entry, unsupported-endpoint and first-duplicate filters, so a rejected entry's malformed metadata cannot fail the sync. An invalid declared type, non-positive value, fraction or overflow fails the entire sync without publishing templates, mappings or timestamps. An absent declaration preserves the previous value for the same model ID (a new model stays unspecified), an explicit `null` clears the value, and a valid declaration replaces a previously manual value. Context is never inferred from prices, input or output limits, maximum completion tokens or model names.

`src-tauri/src/ai_gateway/context_limits.rs` exposes `resolve_public_context_window(&GatewayConfig, &str, UpstreamProtocol) -> Option<u32>` with `pub(in crate::ai_gateway)` visibility. It aggregates ordinary aliases across providers and every pool candidate plus expanded ordered fallback sources, deduplicating exact source identities of provider, local model, upstream model and effective protocol. The aggregate is the minimum only when every contributing source declares a known positive value; any unknown or unresolved configured source makes it unknown. Configured disabled and automatically disabled sources may conservatively contribute, while key marks, cooldowns, runtime health and recovery never raise the advertised bound. Pool aliases do not resolve on native Anthropic Messages ingress, and a `default_model` fallback route resolves only from the same provider's exact upstream declaration. The resolver reads declarative configuration only and does not touch routing or the network.

Native terminal adaptation consumes that resolver only on each tool's existing write path. An OpenCode generated model carries the conservative aggregate as a numeric `limit.context` with a fixed `output: 0`, and omits the `limit` object entirely when the aggregate is unknown; the existing free-form `tool_config.models` renderer serializes the whole model object, so no companion field or renderer change is added. A Codex sync writes the aggregate for the currently selected model as a top-level integer `model_context_window` on the existing manual-activation projection path, and records an explicit `null` when the aggregate is unknown so a merged canonical record clears a stale scalar. A Claude sync deduplicates the default choice and the three family choices and takes their minimum: a known minimum of at least 100000 becomes the decimal string `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, capped at 1000000, while a below-threshold minimum, an unknown value or an incomplete selection clears the managed key and reports the reason; compaction itself stays enabled, and the global renderer plus the isolated profile materializer that serves create and resume write the same value. Each terminal target exposes a `TerminalContextSummary` with `mode`, `scope`, `TerminalContextCoverage` counts and stable reason codes; it never carries a credential and never claims that a running CLI consumed the value. The Codex summary resolves its selected model through the same retained enabled pool alias that generation retains, so `selected_model` and `applied_context` agree with the generated selection.

The operator UI reuses the declared-value helpers instead of re-deriving them, with one deliberate display difference. `src/lib/aiGateway.ts` exports the declared-value helpers `knownContextWindow`, `parseContextWindowInput`, `formatContextWindow`, `resolveTemplateContextWindow`, `resolveOrdinaryContextWindow`, `resolvePoolContextWindow` and `resolveMappingContextWindow`, together with the `1`–`4294967295` value bounds, the `100000` minimum and `1000000` cap, and the `GatewayTerminalContextCoverage` and `GatewayTerminalContextSummary` DTOs. `resolveOrdinaryContextWindow` and `resolvePoolContextWindow` intentionally aggregate a source-wide conservative minimum across every configured mapping, pool candidate and expanded fallback, independent of ingress; per-terminal projections and summaries instead evaluate protocol availability for their own ingress, such as OpenCode's Chat-or-Responses row choice or pool aliases not resolving on native Anthropic Messages. Because the displayed aggregate is a minimum over a superset, it cannot overstate a per-ingress value, though it may report unknown where an ingress-specific projection is known. `ProviderTemplateEditDialog` labels a token input for every template model and explains that a valid source declaration overwrites a manual value, a missing declaration preserves it, and an explicit null or blank clears it. `ProviderDetailDialog` provides the same labeled input for unbound mappings, renders a bound mapping read-only with its inherited value and source, and states when the template or template model is missing; an invalid draft stays visible and blocks the save, and cancelling writes nothing. `ModelListPanel` shows each source value and the conservative aggregate or an incomplete-unknown state for ordinary and pool rows, and a pool has no independent editable override. `TerminalSyncPanel` presents each OpenCode, Codex and Claude target's mode and scope, known and total coverage, selected model, raw and applied tokens, stable reasons for unknown, below-minimum, capped and incomplete selections, and the new-or-rematerialized-session scope, without claiming that a running CLI consumed the value. `ClaudeModelSelectionDialog` shows the shared threshold, the cap and the unavailability reasons before synchronization. A successful manual template save reloads provider configuration and terminal targets. Both locales provide the labels and accessible names, while hidden-panel behavior and polling cadence stay unchanged.

## Alternatives considered

- Infer a window from model names, pricing, output limits or maximum completion tokens: declined because such a value is a guess that can overstate the provider's real capacity.
- Let a bound provider keep a manual override: declined because a stale dialog or an older template could establish a value that disagrees with the authoritative template.
- Advertise the largest or first known source value when another source is unknown: declined because a public model must not claim more than every configured contributor supports.
- Treat an absent remote declaration as zero, unlimited or a clear: declined because absence preserves an existing value and only an explicit `null` clears it.
- Add a second model catalog or a configuration migration: declined because the template and mapping already own the metadata and an additive optional field keeps schema version 4 readable.

## Consequences

- Existing encrypted configurations stay readable with unspecified context; values round-trip only when present, and an older build may discard them on a later save.
- A remote refresh is atomic for this metadata: malformed or conflicting declarations leave the prior configuration and sync timestamp unchanged, while a valid, absent or `null` declaration follows the replace, preserve or clear rule.
- Bound rows cannot diverge from their template, and unbinding preserves the last inherited value until the operator edits the now-unbound mapping.
- Public advertising is conservative: complete aggregates report the minimum of all configured contributors, and any required unknown keeps the aggregate unknown instead of borrowing a larger value.
- [Provider Templates Drop Built-in Model Catalogs and Prices](../architecture/2026-09-19-provider-template-manual-model-sync.md) is partially superseded for its template-model shape and remote-sync merge facts by the optional declared context window and its ownership rules; its reduced catalog, manual per-template sync, pricing and retirement decisions remain in force.
- `MEMORY.md` and the authoritative navigation index register the backend module, the frontend context helpers and terminal summary DTOs, and the corresponding behavior-test paths in the same change; the generated navigation view and note pairing record are refreshed alongside them. [API Gateway Model List Tab](2026-09-18-api-gateway-model-list-tab.md) now also carries per-source and conservative context values, while its filtering, copy and aggregation decisions remain in force.
- Native configuration is additive and clearable: an unknown OpenCode value omits `limit`, a Codex unknown writes an explicit `null` so the merged canonical record clears the stale scalar, a gateway-managed reset removes the context key together with `model_reasoning_effort` and the other gateway-owned keys while preserving unrelated native keys and returns rendered content that the existing projection application path persists, and a Claude unavailable, below-minimum or capped value clears or narrows only the managed key while compaction stays enabled; unrelated native fields and the existing ownership, marker and activation rules are unchanged.
- Context-only drift now feeds `pending_sync`: an OpenCode model list missing the current limit, a Codex `model_context_window` mismatch, or a Claude selection or compact-threshold mismatch marks a previously synced target pending without exposing key material. A context-changing provider or manual template save refreshes previously synced tools once after persistence outside the lock, and a refresh failure never changes the saved gateway result.
- Behavior coverage lives in `src-tauri/src/ai_gateway/tests/context_terminal_sync.rs` and `src-tauri/src/app_store/tests/gateway_context_projection.rs` for native projection, and in `src/components/AiGateway/ContextLimits.test.tsx` together with the existing AiGateway interaction suites for the operator surfaces. They use isolated temporary homes, injected sources and Testing Library, so native GUI interaction and a running third-party CLI remain unexercised.
- [Template Sync Best-Effort Refreshes Previously Synced Terminal Tools](2026-09-23-template-terminal-resync.md) is partially superseded: a context-changing provider save and a context-changing manual template save now also trigger its once-only best-effort refresh, while its template-sync trigger, synced-tool predicate, order and swallowed-error contract remain in force. [Gateway Terminal Sync Flags Model-Selection Drift as Pending](../bug-fix/2026-09-29-gateway-terminal-pending-model-drift.md) is partially superseded by the added Codex context scalar and Claude selection/threshold comparisons, while its ledger rules, key-material exclusion and read-only computation remain.
- Operator surfaces are delivered: template and unbound mapping token inputs, read-only inherited values with missing-template explanations, per-source and conservative model-list values, per-target terminal summaries with reasons and session scope, the pre-sync Claude threshold view, both locales and accessibility labels, and a template-save reload of providers and terminal targets. The scoped frontend suite passes 300 of 300 tests, the production build and scoped ESLint exit zero with three warnings, and the bounded gateway suite passes 1151 tests with zero failures and 46 existing ignored tests; generated configuration and Testing Library assertions do not certify native GUI interaction or consumption by a running third-party CLI.
