# Agent Note: Provider Templates Drop Built-in Model Catalogs and Prices

Status: implemented

English | [中文](2026-09-19-provider-template-manual-model-sync.zh.md)

## Problem

Provider templates used to be a curated catalog inside the app. The built-in snapshot carried 103 OpenCode Zen models and 62 CommandCode models with four-tier prices, weekday peak/off-peak windows and reasoning efforts, and the sync pipeline parsed two vendor-specific payloads — the `opencode` entry of `https://models.dev/api.json` and the public CommandCode model list — to rewrite derived providers, including provider-scoped price rows. That design had three compounding problems: the catalog drifted from the live endpoints and every model-list refresh was a manual change to the shipped snapshot; the curated price data created a second price surface that could disagree with the operator's mapping-row prices, and a sync could overwrite a price the operator had edited; and the same official data was fetched through two different paths, the standalone `api_gateway_fetch_models` command for hand-imported models and the template sync for template-bound providers. The approved direction was to keep the template as an endpoint definition with an optional model-list URL, refresh its model list through an explicit manual action against that URL, and keep pricing fully manual on the provider mapping row.

## Decision

The built-in snapshot now carries metadata and an empty catalog. `provider_templates.json` keeps `id`, `name`, `description`, `base_url`, `protocol`, `source`, `models_url` and `models`; both built-in templates ship an empty `models` list and a preconfigured model-list URL — `opencode-zen` uses `https://opencode.ai/zen/v1/models` and `commandcode` uses `https://api.commandcode.ai/provider/v1/models` — and each template's `source` is that same URL. `ProviderTemplate` drops `snapshot_version`, and `ProviderTemplateModel` is reduced to `upstream_model`, an optional `display_name`, an optional `protocol` and a persisted `enabled` flag (`#[serde(default = "default_true")]`, always serialized; a model stored without the flag reads as enabled); the four price tiers, `off_peaks` and `reasoning_efforts` no longer exist on a template model. `parse_template_snapshot` keeps the structure fatal on invalid JSON, an empty template id and a duplicate template id, keeps the model-shape rules (an empty identifier, an unknown protocol string and a duplicate `upstream_model` keep only the first valid entry) and normalizes a blank `models_url` to none.

`api_gateway_sync_provider_template` syncs one template from its own `models_url` and fails with an actionable error, writing nothing, when no URL is configured. `fetch_template_models` GETs the URL through `reqwest` with a 15-second timeout and no credentials. `parse_model_list_source` accepts the OpenAI-compatible shapes — a `data` array, a `models` array (where `name` may serve as the identifier), a root array and plain string entries — takes an object entry's `id` as the upstream model name and completes its `name` into a display name covering the whole identifier ([Gateway Synced Model Names Cover the Whole Identifier](../bug-fix/2026-09-20-gateway-synced-model-name-completion.md)), and derives the protocol from `supported_endpoints` only when that field is an array: `/chat/completions` wins over `/responses`, a declared array that contains neither drops the entry, and a missing or non-array field keeps the entry with no protocol so it inherits the template protocol. The parsed list replaces the template's model list wholesale: for an identically named model a source-provided protocol replaces the template value and the display name is replaced by the completed name, a source that omits them keeps the local values, and `enabled` always keeps its local value; new models start enabled and duplicate identifiers keep the first. A network failure, a timeout, a non-2xx response, a non-JSON payload, a missing model array, an entry without an identifier and an empty effective model set are fatal, and the error names the URL and the reason. The sync stages the new template and every derived-provider update on a clone, persists once through the encrypted atomic `write_config` and only then commits to memory; the returned view records `synced_at`, keeps the template's `source` and reports `from_snapshot` as false.

A sync still never replaces a derived provider wholesale. `propagate_to_derived` updates a derived provider's `name`, `base_url` and `protocol` only while they still equal the previous template values, and adds a mapping for each enabled template model that the provider's `ignored_models` does not block and has no mapping yet; an existing mapping's `display_name` and `protocol` update only while they still equal the previous template values. A template-disabled model is never added, `local_model` is never touched and a sync never enables an existing mapping; a mapping whose model the previous template carried and the new list removed is disabled by the sync while the row is kept, a mapping the template no longer carries stays on the provider and stays marked deprecated by `isMappingDeprecated`, and the sync creates or modifies no price row. [Gateway Template Model Retirement](2026-09-20-gateway-template-model-retirement.md) records the retirement rule. A manual provider's fields and mappings stay field-for-field unchanged.

`api_gateway_create_provider_from_template(template_id, name, base_url, protocol, api_key)` rejects a blank API key before anything is staged, falls back to the template name and base URL when they are blank, and always takes the protocol argument. The new provider carries `template_id`, leaves `default_model` empty, receives one enabled mapping per enabled template model (`local_model` equals `upstream_model`, the display name when present, the model protocol or the template protocol) and no price row; a template with no enabled models creates a provider with no mappings. `api_gateway_delete_provider_model` removes the mapping and that model's provider-scoped price row on both a template-bound and a manual provider, and on a bound provider records the upstream model in `ignored_models` exactly once so a later sync cannot resurrect it. `api_gateway_restore_provider_model` removes the model from the ignored set, rebuilds only the mapping from the template's current data and reports an actionable error when the template no longer carries the model; the restored model starts unpriced until the operator enters a price.

The template editor maintains the model list only: upstream name and display name inputs, an enabled toggle (new rows start enabled), add and delete actions, and a complete-list save through `api_gateway_upsert_provider_template`; it has no price inputs and no fetch-models panel. The template card renders the 「同步模型列表 / Sync models」 action only when `models_url` is non-blank, keeps the model count, the source and the last-sync time, lists models without price tiers, peak/off-peak windows or reasoning efforts, and renders a disabled model row de-emphasized with `data-disabled="true"`. Pricing stays fully manual on the provider mapping row: `MappingPriceEditor` is the only price entry.

## Alternatives considered

- Keep the built-in snapshot catalog and regenerate the official model lists in-app: declined because the app would keep owning a copy of two live endpoints that drifts between releases, while the endpoint itself can serve the list.
- Keep the hardcoded models.dev and CommandCode sync sources with their vendor-specific parsers: declined because a template already carries a `models_url` and a user-maintained template can point at any endpoint, so per-vendor parsers cannot cover it; the removed `TemplateSourceKind` selection existed only to switch between two vendors.
- Keep template price rows and the sync price propagation: declined because prices are account-specific and go stale in a curated copy, and a sync writing them can overwrite the operator's mapping-row edit; manual pricing on the mapping row is the single source.
- Propagate disabled template models as enabled mappings: declined because a template model's `enabled` flag is the operator's local intent; a sync must not resurrect a model the operator disabled and creation must not copy it.
- Let the local display name and protocol win permanently over the source: declined because the endpoint is the authority for the official model name and protocol; the approved source-wins rule refreshes the protocol while the completed-name rule sets the display name, and the untouched-only mapping rule and the local `enabled` flag still protect local intent.

## Consequences

- Templates ship no catalog and no prices: before the first sync or a manual edit a built-in template's model list is empty, and the two built-ins point at their model-list URLs. Removed fields are ignored on read; a persisted template state written before this change still loads with its model identifiers, display names, protocols and enabled flags, and an older `api_gateway.json` needs no migration because `ProviderTemplateState` and `ProviderTemplateModel` keep serde defaults.
- Sync semantics: the action is manual and per-template; a successful sync replaces the list wholesale with the completed display name and the source-wins protocol, keeps local values the source omits and the local `enabled` flag, and records the sync time; a blank URL, a timeout, a non-2xx response, a non-JSON payload, a missing model array, an entry without an identifier and an empty effective set each fail with an error naming the URL and the reason and write nothing; the write boundary is the template state and the derived providers' fields and mappings — never local keys, `terminal_syncs`, forwarding runtime state, usage history or price rows.
- Binding and maintenance: bound providers gain enabled mappings for newly available enabled models only; disabled and ignored models are not added; existing mapping display names and protocols update only while untouched; retired models keep their mapping rows and deprecated marking while the sync disables them; delete removes the mapping and the provider-scoped price row and records the ignored model exactly once; restore rebuilds the mapping with no price row; manual providers are unaffected.
- Pricing and editor: pricing is fully manual on the provider mapping row and `MappingPriceEditor` is the only price entry, so a template flow can only remove a price row (through delete) and never create or change one; the editor and the card no longer render price tiers, peak/off-peak windows or reasoning efforts.
- Removed code: `api_gateway_fetch_models` and the `apiGatewayFetchModels` wrapper, `fetch_models_from_url`, `fetch_template_source`, `TemplateSourceKind`, `template_source_kind`, `template_source_label`, `parse_source_value`, `ModelsDevSource`, `non_empty_string`, `merge_source_price`, `reasoning_efforts_from_options`, `parse_models_dev_source`, `commandcode_protocol`, `parse_commandcode_source`, `normalize_price` and `sanitize_out_of_range_numbers` are removed from product code, and the behavior tests assert that the removed command and wrapper are no longer registered or exported; the template commands stay exported from `lib.rs` and registered in `app_runtime/run_app.rs`.
- Rollback: reverting the code needs no data migration because the older build's `ProviderTemplateModel` keeps serde defaults for the price fields and ignores the new `enabled` field, and its built-in snapshot still carries the catalog, so template creation and sync return to the older curated form; persisted template state written by this build is readable by the older build, and a later older-build sync repopulates template prices under its own merge rules; after reverting, the older build passes its own `cargo test` and `npm test` and loads a configuration written by this build.
- Partial supersession: this record replaces the built-in 103/62-model catalog, the models.dev/CommandCode-specific parsing, the sync price propagation and the create/restore price rows of [API Gateway Provider Templates and Incremental Model Sync](2026-09-18-api-gateway-provider-templates.md), and the template-sync price-row rule of [Gateway Model Prices Move Into Provider Mappings](2026-09-19-gateway-model-prices-in-provider-mappings.md); the naming, template binding, ignored-model lifecycle, deprecated marking, untouched-only merge, atomic write and weekday price semantics of the first record and the per-mapping price entry, provider-scoped matching, read-time normalization and frozen recorded amounts of the second record remain in force, and the remaining active records are unrelated; [Gateway Template Model Retirement](2026-09-20-gateway-template-model-retirement.md) later partially supersedes this record's retired-model rule while its remaining decisions stay in force; [Gateway Synced Model Names Cover the Whole Identifier](../bug-fix/2026-09-20-gateway-synced-model-name-completion.md) partially supersedes this record's stored-`name`-as-display-name fact while its remaining decisions stay in force; [Template Sync Best-Effort Refreshes Previously Synced Terminal Tools](../feature/2026-09-23-template-terminal-resync.md) partially supersedes this record's sync write boundary, because after a successful sync the shared command best-effort refreshes previously synced terminal tools through the existing terminal pipeline, so `terminal_syncs` and tool records can be written by that delegated stage while this record's template-sync-stage boundary and all other decisions remain in force.
- `MEMORY.md` and the `api-gateway` / `api-gateway-backend` entries in `navigation.json` describe the reduced template shape, the conditional manual sync, the enabled flag and its creation and propagation effects, the completed display-name rule, the source-wins protocol rule and fully manual pricing in the same change, and `navigation.md` was regenerated from the authoritative JSON.
