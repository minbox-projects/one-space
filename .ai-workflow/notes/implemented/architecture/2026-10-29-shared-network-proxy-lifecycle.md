# Agent Note: A Single Global Network Proxy Snapshot Drives Generation-Scoped Transport and Relay Leases

Status: implemented

English | [中文](2026-10-29-shared-network-proxy-lifecycle.zh.md)

## Problem

Proxy behavior was spread across consumers. The AI Gateway owned a separate `settings.proxy_url`, ordinary features built HTTP clients ad hoc, some long sequential and fallback paths reused a client captured for the whole batch, the ACME account builder captured transport when the account was created, and the JavaScript updater plugin performed its own fetch outside managed transport. A save could publish runtime state without a single validated source, so a failed device-configuration write or client preparation could leave the saved setting and the active transport disagreeing. The Zen relay also identified itself by a proxy string and timeout, and replacing it on a switch could drop an admitted SSE response or leave an unused child behind.

The delivered behavior needs one validated global snapshot, a next-request effect without restarting the application, explicit direct behavior that clears inherited proxies, a loopback bypass, unchanged state after a failed save, complete coverage for application-owned HTTP(S), and a migration that does not preserve a second gateway-local proxy source.

## Decision

- `src-tauri/src/proxy.rs` owns the global source. A save validates the effective configuration, prepares the transport, persists the device configuration and only then publishes the runtime snapshot; competing publications are serialized. `ProxyManager` publishes an immutable `ProxySnapshot` whose generation advances only when the effective identity changes: enabled state, type, host, port, username or decrypted password. An equivalent save, or a change only to `check_interval`, keeps the generation and the published transport. The shared builder policy clears automatic, system and environment proxies first, applies the current explicit proxy when enabled, and remains explicitly direct when disabled or absent. `localhost`, `127.0.0.1` and `::1` connect directly. `apply_process_proxy_env` and the app-owned Git child helpers derive both upper- and lower-case environment variables plus loopback exclusions from the same snapshot; user Git configuration is never edited. `current_client()` is the production seam that builds a client from the current global or test snapshot with the shared default request and connect timeouts. After a successful publish, `save_storage_config` emits the credential-free `proxy-config-updated` event carrying only the new generation. `proxy_generation` exposes the current generation, and `PROXY_CONFIG_UPDATED_EVENT` names the matching update event.
- Every managed HTTP operation and every retry resolves the current snapshot through the shared builder policy. Sequential RSS sources, CLI update primary and fallback requests, AI Environments model lists, MCP metadata and probes, HTTP tools, the protocol router, uptime probes and alert webhooks, SSL DoH and Cloudflare calls, webhook replay and mirroring, the OAuth/Gmail bridge, application updates and newly spawned Skills and Subagents Git tasks no longer reuse a client captured for a long batch. Draft connection testing builds its own transport and publishes nothing.
- AI Gateway clients are cached by proxy generation and resolve current transport per attempt. Quota, OpenCode Go usage and template operations key their single-flight identity by the generation in addition to the exact source or template identity, so a matching request inside one generation still shares one flight while a refresh admitted after a switch starts independently. Late old-generation results settle their original callers but cannot replace newer cache, template or failure state. Gateway configuration advances to schema 6; the version-gated migration removes only the obsolete `settings.proxy_url`, lets a schema-5 file skip earlier gates, preserves every other value, does not rewrite current-schema reads and never downgrades a future version.
- The Zen relay identity is the global generation, the explicit proxy URL derived from the snapshot and the read timeout. A new generation starts a new child; admitted ordinary and SSE responses hold leases on the retiring child, which exits after its last response body finishes. An equivalent save reuses the current child, and gateway or application shutdown terminates every owned current and retiring child. A missing or unusable transport fails the attempt explicitly rather than falling back to direct Zen traffic.
- The SDK boundaries follow the same source. `AcmeHttpClient` implements instant-acme's `HttpClient` and builds transport for every SDK HTTP operation, and both account-builder sites inject it. The native updater uses official `tauri-plugin-updater` 2.9.0 with `configure_client` resolving the current snapshot for every check or download client build; application commands own typed `Update` handles and verified bytes, clear them on shutdown, and keep official signature verification and installation. The frontend updater facade uses those native commands and the download event, routes GitHub fallback and release-note requests through the managed Rust HTTP bridge, and invalidates old check throttling when the proxy generation changes. The JavaScript updater package and its permission are removed.
- `ProxySettingsPanel` is the only proxy editor. Its copy states the next-request effect, the covered application-managed traffic, the loopback behavior and the external-process boundary. The gateway UI has no independent proxy editor. SSH/SFTP, native TCP, Ping and raw DNS probes, direct TLS inspection, local listeners and application IPC remain outside the HTTP proxy boundary.

## Alternatives considered

- Keep per-consumer proxy overrides and leave the gateway's independent URL in place: declined because the same user action would produce different routes, and the obsolete gateway value could silently win over the global setting.
- Propagate the change only through environment variables: declined because automatic proxies are captured when a client is built, existing clients do not observe a later environment change, and disabled mode must explicitly clear inherited settings rather than merely omit an override.
- Rebuild every client unconditionally for every request: declined because it discards connection reuse within one generation and adds construction cost without changing the routing result.
- Kill the old Zen relay as soon as a new generation is published: declined because an admitted ordinary or SSE response would be cut off; response leases let old work drain while new work uses the new child.
- Implement a replacement update protocol or signature path: declined because the official updater already owns verification and installation, and only its client-construction hook and resource ownership needed adaptation.
- Introduce a per-feature proxy framework or a general client factory: declined because every consumer needs the same builder policy, while timeouts, redirects, headers and TLS remain caller-specific; the shared policy plus a generation seam is smaller and keeps existing behavior.

## Consequences

- A successful save affects the next admitted request or retry without an application restart, while an already admitted request may finish on its existing transport. An equivalent save or a check-interval-only change does not restart transport, gateway clients or the relay.
- Direct mode does not inherit an operating-system, environment or previous proxy. Loopback stays direct. A valid but unreachable proxy fails through that proxy, and a failed validation, preparation or persistence keeps the last valid saved and active state.
- Old-generation flights and late results cannot overwrite newer gateway cache, template or failure state, and retiring relay children exit after their last leased response. Gateway or application shutdown stops every owned relay child.
- Schema 6 removes only the gateway-local proxy URL. Recovering that removed value requires a pre-change encrypted gateway backup or manual re-entry; the current data cannot reconstruct it.
- Coverage is limited to application-owned HTTP(S). Native SSH/SFTP, TCP, Ping, raw DNS, direct TLS inspection, local listeners, IPC and external processes are not covered, and the settings copy states that boundary.
- Native macOS and Windows GUI, ACL and system-proxy integration, real provider, certificate-authority, DNS and service behavior, and real update installation remain unexecuted; tests use local fixtures and mocks.
