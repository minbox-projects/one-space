# Agent Note: A Provider Template Sync Deletes Retired Mappings

Status: implemented

English | [中文](2026-10-08-provider-template-retired-mapping-removal.zh.md)

## Problem

A template sync replaced the template's model list wholesale from its `models_url`, but a model the endpoint had dropped only had its derived mapping disabled and kept. A bound provider therefore accumulated disabled, never-served deprecated rows that no longer matched its template, the operator had to find and delete each one by hand, and the provider's `ignored_models` recorded nothing, so a removed model stayed absent only while its disabled row was never re-enabled. The retirement behavior had to remove the stale rows completely while keeping a later sync from silently re-adding a model the sync had removed.

## Decision

A template sync now deletes, in every provider bound to that `template_id`, each mapping whose `upstream_model` the previous template carried and the fetched list no longer contains (whatever the mapping's enabled flag), and each already-disabled mapping whose `upstream_model` is absent from the fetched list. `propagate_to_derived` (`src-tauri/src/ai_gateway/templates.rs`) collects the removed `upstream_model` values in mapping row order without duplicates and retains the remaining mappings; a mapping whose model the new list still carries stays untouched even when the user disabled it, an enabled manual extra the sync never retired stays, and a manual provider or a provider bound to another template does not change.

Each removed model is appended at most once to the bound provider's `ignored_models` (`GatewayUpstreamProvider` in `src-tauri/src/ai_gateway/types_config.rs`, whose doc comment now states that both the manual model delete and a template sync write it), so a later sync whose list contains the model again adds no mapping for it; `ai_gateway_restore_provider_model` stays the only path back while the template lists the model and keeps its current actionable error while it does not.

The sync deletes the affected provider's `model_prices` rows whose `upstream_model` is one of the removed models, while other providers' rows for the same model and rows of other models stay. When the provider's `default_model`, compared after trimming, equals a removed model name the sync clears it; a `default_model` naming a kept model stays.

After the configuration write succeeds the sync records exactly one `template_mappings_retired` warning for every bound provider with at least one deleted mapping: source `ai_gateway`, category `template_mappings_retired`, severity `warning`, the provider-scoped dedupe key `ai_gateway_template_mappings_retired:<provider_id>`, target tab `ai-gateway` with the provider as `entity_id`, and both the bilingual summary and the `detail` field list the removed models in mapping row order with duplicates removed (`template_mappings_retired_message_input` in `commands.rs` sets `detail` to the same comma-joined list as the summary). An already-disabled legacy row triggers the same notice. A sync with no deletion, a provider with no deletion and a failed write record nothing.

Every deletion, ignored-set, price-row and `default_model` change is staged on the single existing configuration clone and committed by the one existing atomic `write_config`; a failed write leaves every provider, price row and message unchanged. The unchanged propagation rules stay: provider `name`, `base_url` and `protocol` and mapping `display_name` and protocol update only while they still equal the previous template values, `local_model` is never modified, ignored and template-disabled models are never propagated, and no existing mapping is ever re-enabled. With the rows deleted, the existing retired-mapping pill (`isMappingDeprecated` and the per-instance dismissal store) renders nothing for a cleaned provider because it derives from current state and finds no disabled absent rows. The ignored-models section description on both language sides, and the component fallback, now say models were removed from the provider by the user or by a template sync; the translation key keeps its name.

## Alternatives considered

- Keep the former disable-and-keep behavior recorded by the prior retirement record: declined because a disabled deprecated row never served, stayed visible on the card and still required a manual delete; deleting the row and recording the model in `ignored_models` removes the stale state once and keeps a returning model from being re-added.
- Keep the removed row's provider-scoped price data and a `default_model` that names it: declined because a price row and a default route would outlive the mapping they describe and could price or default-route a model the provider no longer maps.
- Delete every mapping absent from the new list, including a disabled manual extra and mappings of other templates: declined because a mapping whose model the previous template never carried, a manual provider and a provider bound to another template are outside the template's contract; only the previous-template-minus-fetched-list difference and the already-disabled absent rows are removed.
- Record the removal as a persisted sync event for the card hint: declined because the hint only describes current state; once the rows are deleted it finds nothing, so a stored event would add a persisted field and its own lifecycle for no operator-visible benefit.
- Re-enable or resurrect a removed model when a later sync lists it again: declined because the ignored set is the durable record of the removal; the operator restores the model explicitly through `ai_gateway_restore_provider_model` while the template lists it.

## Consequences

- Retirement is destructive by design: the mapping row, its provider-scoped price row and a matching `default_model` are removed and the model is written once to `ignored_models`; the configuration schema, the command signatures and the message schema are unchanged and no migration or backfill exists.
- Rollback reverts code and behavior but cannot restore rows a sync already deleted; after a revert the reverted build never re-enables a mapping and forwards exactly as before for every remaining row.
- Behavior migration: a legacy already-disabled deprecated row is deleted by the next sync, manual or automatic, and reported in the provider-scoped warning; a mapping an earlier build left enabled after a template removal already left the previous template, so it stays outside the retirement set and keeps its state until it is disabled (then removed by a later sync) or deleted by the operator.
- An older build reads the resulting configuration as ordinary rows and ignored entries, and the retired-mapping pill simply finds nothing.
- The current-state hint still counts any remaining mapping with the disabled-and-absent shape, for example a user-disabled manual extra, because the sync deletes only the rows in its retirement set; it is not an event log and re-enabling a mapping stays the operator's explicit act.
- The delivery rewrites the behavior tests in `src-tauri/src/ai_gateway/tests/templates.rs` for the deletion scope, the ignored set, the price rows and `default_model`, and the provider-scoped message summary and `detail`, replacing the previous disable-and-keep assertions.
- Supersession: full supersession of [Gateway Template Model Retirement Disables Derived Mappings](2026-09-20-gateway-template-model-retirement.md), which is retained with this statement because its disable-and-keep decision and its declined delete alternative are reversed here while its card avatar, current-state hint and one-way mapping rule remain as its own history; partial supersession of the retirement-message clause of [Gateway Alert Pills Dismiss per Instance and Archive Provider-Scoped Warnings](../feature/2026-10-07-gateway-alert-badges-and-message-center.md), whose pill and dismissal decisions stand; partial supersession of the clauses in [Provider Templates Refresh Automatically on a Persisted Interval](../feature/2026-09-23-template-auto-refresh.md) that said a sync never writes `ignored_models` or a price row and in [Automatic Template Sync Notifies the Message Center on Real Mapping Changes](../feature/2026-09-24-ai-gateway-template-auto-sync-notification.md) that described a disable-only retirement, whose scheduler, additions-only info message and failure-isolation decisions stand; and in-place correction of the retired-model and sync-price-row facts of [API Gateway Provider Templates and Incremental Model Sync](2026-09-18-api-gateway-provider-templates.md) and [Provider Templates Drop Built-in Model Catalogs and Prices](2026-09-19-provider-template-manual-model-sync.md), whose remaining decisions stand.
- `MEMORY.md` and the `ai-gateway` and `ai-gateway-backend` entries in `navigation.json` describe the deletion rule and the corrected ignored-models copy in the same change, and `navigation.md` was regenerated from the authoritative JSON.
