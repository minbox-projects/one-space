# Agent Note: Toolbox Plugin Registry Replaces Hand-Maintained Tool Lists

Status: implemented

English | [中文](2026-09-25-toolbox-plugin-registry.zh.md)

## Problem

Toolbox tool metadata was hand-maintained in parallel lists: `MoreToolsSection` ids and aliases in `src/lib/navigation.ts`, card presentation in `src/lib/moreToolPresentation.ts`, visibility defaults in `src/lib/launcherToolVisibility.ts`, Hub cards in `src/components/MoreToolsHub.tsx`, Launcher quick tools and internal targets in `src/components/Launcher.tsx`, and Notes/Snippets sidebar and tray entries in `src/App.tsx` and `src/lib/trayMenu.ts`. Adding, renaming or hiding one tool required editing every list, and a miss left a surface unreachable or inconsistent. The MD5 tool carried a legacy camelCase id (`md5Encryption`) beside its kebab-case navigation id, the Hub forwarded an always-true visibility to the active tool so a hidden tool kept polling and refreshing, and every tool re-implemented copy feedback, safe-localStorage, history, Tauri-event, polling and badge logic in slightly different ways. The same period accumulated compatibility code with no reachable behavior: the experimental CloudDrive surface, the `backup` ghost route that resolved to a tab with no render path, `normalizeLegacyTabTarget`, the Launcher `ai-flow` filter, the one-shot localStorage-to-backend launcher migration, the legacy RandomPassword and JT/T input-history migrations, an advertised `notes_search` assistant capability with no backing implementation, and an atomic AI Workflow save-and-activate command used only by its own tests.

## Decision

One registry is the single source for every toolbox surface, and dead compatibility code was removed rather than retained.

1. `src/toolbox/types.ts` defines the descriptor model (`ToolboxSurface`, `ToolboxToolDescriptor`, `ToolboxNavAlias`, `ToolboxBilingualText`, `ResolvedToolboxTarget`), one descriptor per tool lives in `src/toolbox/plugins/`, and `src/toolbox/registry.ts` exposes `TOOLBOX_TOOLS`, `listToolboxTools`, `getToolboxTool`, `resolveToolboxNavigationAlias`, `assertToolboxRegistryIntegrity` and `resolveToolboxText`. Hub cards come from the registry `hub` surface and are never hidden by launcher visibility; the Hub detail, Launcher quick tools, the Launcher internal toolbox targets (Notes and Snippets, via `launcher-internal`), `resolveNavigationTarget` aliases, launcher visibility defaults, the `defaultOrder` sort of `listToolboxTools`, Notes/Snippets sidebar entries and the App active-tool breadcrumb derive from those descriptors, while the tray menu structure stays hand-maintained with only its Notes/Snippets labels resolved through the registry (falling back to `tray.notes` / `tray.snippets`). `assertToolboxRegistryIntegrity` rejects duplicate ids, unknown surfaces and non-kebab Hub ids. Notes and Snippets are plugins without Hub cards; `md5-encryption` is the canonical id and a legacy `md5Encryption` visibility record is ignored so the tool defaults to visible. `src/lib/moreToolPresentation.ts` was deleted after its last consumer moved to the registry.
2. `src/toolbox/invoke.ts` (`invokeToolboxCommand`, `ToolboxInvokeError`, `isToolboxInvokeAvailable`), `src/toolbox/localStore.ts` (`readLocalJson`/`writeLocalJson`), `src/toolbox/historyStore.ts` (`createHistoryStore`), `src/toolbox/useCopyToClipboard.ts` (`COPIED_FEEDBACK_RESET_MS = 1600`), `src/toolbox/useTauriEvent.ts` and `src/toolbox/useVisibleInterval.ts` replace the hand-written runtime implementations, and `src/components/toolbox/` provides `ToolShell`, `ToolErrorBanner`, `ToolStatusBadge` and `ToolEmptyState`. The seven copy affordances (Random Password, JSON Parser, MD5, Short Link, File Sharing, Protocol Router and the JT/T parser) use the shared copy feedback, and the migrated event, polling and badge call sites use the shared helpers; the shared history store and safe-localStorage writer back `shortLinkHistory`, while `jttInputHistory` keeps its own all-or-nothing invalid-record recovery. SshServers and ProtocolRouterTool keep raw `invoke` for their remaining backend commands, but every call site first checks `isToolboxInvokeAvailable()` so no raw invoke is reachable without the Tauri runtime. `MoreToolsHub` derives its cards from the registry `hub` surface and forwards its host tab visibility as `isVisible && activeTool === id`, so a hidden tool issues no polling or event-driven refresh; it also subscribes to `LAUNCHER_TOOL_VISIBILITY_UPDATED_EVENT` so the detail `Show in Launcher` switch reflects launcher-visibility changes.
3. CloudDrive is removed end to end: the component, its plugin descriptor, Hub and Launcher entries, route alias, `onespace_aliyun_token` access and bilingual keys. The removal is behavior-neutral because the experimental surface had no consumer and nothing else referenced it.
4. The `backup` ghost Hub route is removed: `backup` is neither a Hub tool id nor a More Tools alias, and the backup action descriptors now target the real `mcp-servers` tab, so backup messages resolve to an existing page instead of a tab with no render path.
5. Legacy navigation compatibility is removed: `normalizeLegacyTabTarget` and the Launcher `ai-flow` filter are deleted, and `resolveNavigationTarget` resolves only the current smart-workspace aliases and registry aliases. A stale persisted launcher record or historical message target that no longer resolves is passed through and opens no page; that is the approved cost, and no producer emits those targets anymore.
6. The one-shot legacy localStorage-to-backend launcher migration is deleted; launcher records are read from backend storage only. The removal is behavior-neutral for current data because no current producer writes the old localStorage format, and the approved cost is that un-migrated legacy items are not imported.
7. The legacy history migrations are deleted: RandomPassword's legacy localStorage history is cleared rather than migrated, and the `jttInputHistory` string-array migration is deleted so a stored legacy string array is treated as an invalid history and cleared by its all-or-nothing recovery, while current-format reads and writes stay unchanged. The legacy formats are no longer produced, so no valid history is lost.
8. `notes_search` is withdrawn end to end from the assistant tool policy, the capability snapshot, the default agents, the model tool definitions, the conversation prompt, the stub dispatcher, the frontend types and the bilingual labels, including the unreferenced `allowNotesSearchLabel` key removed from both i18n bundles. The withdrawal was behavior-neutral because no implementation ever backed the capability, and keeping it advertised would have made an assistant offer a capability that cannot run. The assistant and its AI Workspace capability badges and toggles have since been removed end to end ([AI Workspace Removed End to End](../simplification/2026-09-29-ai-workspace-removal.md)); no `AgentToolPolicy`, capability snapshot or capability badge surface remains in the tree.
9. The atomic AI Workflow chain is removed: `save_and_activate_profile`, `ai_workflow_save_and_activate_profile`, the command registration and re-export, the frontend `saveAndActivateProfile` wrapper and the Rust tests whose subject was that atomic semantics are gone, while `ai_workflow_rename_profile` remains among the registered commands. Saving and activation remain separate with unchanged behavior, and the removal changes no user-visible flow because the atomic command had no production caller.
10. Dead and duplicated tool code is removed where no reachable path used it: the JsonParser unreachable fallback, FileSharing unused snapshot fields, the unused `subscribeFileSharingUpdates` export, empty-snapshot duplication and `window.confirm`, the SshServers duplicate host type and console-only key-file error, the SshTunnels duplicated batch paths, stale saved-probe display (saved probes now expire), the unlocalized draft-probe error and hardcoded Chinese, the ProtocolRouter duplicated backend defaults and normalizer, double stats controls and unguarded route test, and the jttDataParser duplicated hex/time/uint32 helpers, duplicate error types and dead CRC condition. The JT/T position parser is now one specification-ordered implementation (latitude at byte offset 8, longitude at byte offset 12) feeding the tree, JSON, 0x0801 multimedia and JT809 paths, and the `JT808_F3_FRAGMENT_1` synthetic fixture that stored the reversed order is corrected by swapping the position dwords, leaving its checksum unchanged. These removals preserve every reachable behavior and make the labels match the specification.

## Alternatives considered

- Keeping the parallel hand-maintained lists and adding consistency tests only: declined because tests would detect drift after the fact while every label, icon, default or alias change would still multiply across the lists that the registry now derives.
- Generating the registry from the existing lists with codegen: declined because the source of truth would remain ambiguous and the one-descriptor-per-tool data is small enough to state directly, with integrity assertions enforcing the invariants.
- Keeping the compatibility shims (legacy navigation normalization, the `ai-flow` filter, the launcher and history migrations, the ghost route, the advertised `notes_search` capability and the atomic command): declined because no producer emits those inputs, the remaining callers were tests of the removed behavior, and the approved cost is that a stale target opens no page rather than keeping unreachable code paths alive.
- Migrating the legacy histories into the shared store instead of clearing them: declined because the legacy record shapes are no longer produced and the existing invalid-record recovery already yields an empty history, so a migration would add one-off conversion code for data that no current version writes.
- Keeping an always-true visibility contract at the Hub: declined because a hidden tool kept polling; forwarding the host's real visibility is the truthful contract and is asserted by the interval and event tests.

## Consequences

- Adding or changing a toolbox tool is one descriptor edit: id, icon and accent, i18n keys or bilingual text, aliases, surfaces, default visibility and order, and the component. The Hub cards, Launcher quick and internal toolbox targets, sidebar entries and navigation aliases derive from it, while the tray menu structure stays hand-maintained with Notes/Snippets labels resolved through the registry, and the registry integrity test rejects duplicate ids, unknown surfaces and non-kebab Hub ids.
- The shared runtime is the only implementation of the migrated copy feedback, safe-localStorage and history helpers, Tauri events, visibility-gated polling and the tool shell, badge, empty-state and error-banner surfaces; the shared history store currently backs `shortLinkHistory` while `jttInputHistory` keeps its own recovery, and SshServers and ProtocolRouterTool guard their remaining raw invokes with call-time availability checks. Copy feedback clears after 1600 ms, corrupted storage reads return safe defaults, writes never throw, and hidden tools issue no polling or event-driven invoke.
- The removed surfaces no longer exist: CloudDrive, the `backup` route, legacy navigation normalization, the `ai-flow` filter, the legacy launcher and history migrations, `moreToolPresentation.ts`, `notes_search` and the atomic AI Workflow command. Stale persisted launcher records and historical message targets open no page, which is the approved behavior; no producer emits them and no test was weakened.
- The assistant capability contract is truthful: the policy and the capability snapshot carried only fields with implementations, and that whole surface, including the AI Workspace badges, toggles, types and labels, was removed end to end ([AI Workspace Removed End to End](../simplification/2026-09-29-ai-workspace-removal.md)).
- `MEMORY.md` and `.ai-workflow/index/navigation.json` record the registry, the shared modules and the removals, and this note records the registry decision, the removal rationale and the behavior-neutral argument. The [Tray menu ownership and contract](2026-09-22-tray-menu-ownership-and-contract.md), [AI Workflow Model Switcher Delivers 9-by-3 Matrix with Backend Profile Commands](../feature/2026-09-22-ai-workflow-model-switcher.md) and [AI Workflow Profile Save and Activation Are Separate Actions](../feature/2026-09-23-ai-workflow-profile-save-activation.md) notes retain their decisions (no full supersession) and were updated in place to the delivered registry wiring, command set and separate save/activation flow.
