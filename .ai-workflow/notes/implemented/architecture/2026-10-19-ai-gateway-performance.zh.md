# Agent Note: AI Gateway Avoids Redundant Configuration, History, Database, Stream Framing and Management Fetch Work

Status: implemented

[English](2026-10-19-ai-gateway-performance.md) | 中文

## Problem

热网关读取通过文件身份缓存避免了重新解密，但每次读取仍返回拥有所有权的 `GatewayConfig` 深拷贝。请求处理、监听器状态/启动/停止、模型发现、自动启动与逐次尝试的 key 标记重读都支付了这份拷贝，因此尽管这些消费者只读，本地工作仍随完整存储的服务商、映射、key、价格与池集合增长。模型池规划还有第二重放大：它为每个已存候选克隆完整服务商来构建单映射路由视图，包括永远无法服务或被探测的禁用服务商与禁用映射。同轮延续解析把调用方历史数组复制成一个 `Value`，而记录已投递保留时又克隆一次该历史，因此大型会话在既有前缀、工具身份与字节预算检查运行前被复制了两次。流式观察还在做已经不再需要的工作：计时观察器为整条上游流解析每一个完整 SSE 事件，但只有第一个有意义事件才能确定首输出时刻。该时刻已知后，同一次读取中剩余的事件以及之后的每个分片仍会被缓冲、扫描边界、取出并解析，最后一个无终止符事件也可能一直留在缓冲区直到结束，即使观察窗口已经关闭。用量面板在数据库层重复了同一模式：每次读取都打开、初始化并迁移 SQLite 文件并重新准备相同语句，用量统计第二次扫描服务商集合并逐模型过滤，服务商历史为同一次读取另开并初始化自己的句柄。额度与 Go 用量刷新以同样方式重复工作：同一账户的并发查询各自发起自己的网络抓取，即使第一次仍在飞行中，于是一批卡片刷新会放大上游请求。内置服务商模板快照也在每次模板查询时重新解析，尽管其内嵌字节在运行时不可能改变。管理面板在页面层重复了类似的冗余读取。每次加载都读取今日统计与一份分组的今日日志，只为汇总统计中已经暴露的失败数；五秒新鲜度轮询与焦点追赶即使已有等价请求在途也会再次读取；配置事件突发会为每个事件启动一次作用域重载；而配置变更或较早的响应可能被更早开始、随后返回的响应覆盖。首次挂载还会构造所有重型页签与所有用量子视图，即使从未访问；非活动面板也仍在每次渲染时重建其行与数字格式化器。

## Decision

`storage` 保留按路径、字节长度与修改时间作键的进程读取缓存，但改存 `Arc<GatewayConfig>`。`read_config_shared()` 为只读热消费者返回共享不可变值：请求边界、监听器启动/停止/状态、自动启动以及逐次尝试的 key 标记刷新。`read_config()` 仍是需要所有权调用方的拥有式 API，仅在必须交出拥有值时克隆；`modify_config()` 在既有写锁下取得拥有式副本以便修改，原子写入，并仅在成功写入后把归一化结果作为新缓存 `Arc` 发布。改变文件身份的直接磁盘重写仍会被下一次读取观察到；不新增 TTL、结果缓存、内容哈希或序列化字段。唯一的拷贝计数器是仅测试用的 `cfg(test)` 接缝。

模型池规划现在只为服务商与映射均启用的候选构建单映射路由克隆。自动禁用映射仍会被准备，因为它可能是合格的半开探测目标；禁用服务商与禁用映射保持借用且绝不被准备。健康候选列表持有已解析候选的引用，加权排序只为实际返回的已准备服务商克隆，并加上它追加的单个探测目标。候选集、资格、权重、独立 SWRR 计费、fallback 顺序、推理过滤、冷却与探测位置均不变。

`CallerHistory` 把历史存为 `Arc<Value>`，`HoldEntry` 共享该值而不克隆。解析在 `Arc` 内一次性分配数组；记录已投递保留只递增引用计数。前缀比较、指令/工具上下文相等、工具调用身份、准入令牌顺序、条目数、单条与合计字节预算、过期与逐出均不变。

`OutputTimingObserver` 在首个有意义输出已知后停止观察。`feed_at` 在 `first_output_at` 已设置时直接返回，不再缓冲或分帧；在建立该观测的那次读取中，它在那个事件处停止分帧，丢弃剩余的已缓冲事件并清空缓冲。`finish_at` 仍在其首次调用时记录整次尝试的结束时刻；在尚无任何输出时，它仍识别不带终止空行的最后一个有效事件。永远不终止的缓冲仍由既有 `MAX_BUFFER_BYTES` 限界。首字时刻、整次尝试 TPS 窗口、有意义输出规则、原始上游观察与所有转发字节均不变。用量采集与池同轮延续观察保持独立并保留各自的容错语义；不引入共享 SSE 分帧 helper，因为观察器是这条「首输出后停止」规则的唯一消费者。

`usage_store` 为每个数据库路径保留一条查询连接，与既有写连接分离。每个路径与角色各有自己的互斥锁；全局条目表锁只覆盖短暂查找，并在 SQL 或 schema 初始化之前释放，因此无关路径绝不互相串行。仅当实际文件身份（device 与 inode）仍匹配时才复用句柄，因此被替换、恢复或删除的数据库会针对真实存在的文件重新打开并初始化。查询连接使用容量为 256 的 `prepare_cached`；这复用语句而非结果，所以新提交的行仍然可见。`UsageLogStore::query_connection`、`with_query_connection`、`QueryConnection` 与仅测试用的 `QueryWorkStats` 计数器均限于 `ai_gateway` 内部，不是新的公共命令或字段。`usage_stats` 由一次分组扫描加哈希查找派生模型聚合与服务商行，替代第二次全量服务商扫描与逐模型过滤。`provider_usage_history` 在同一读事务内经同一查询连接读取 metadata 与汇总。明细行与合格的服务商/日贡献仍在单个请求事务内提交，保留清理仍在每次成功追加后立即运行，且不合并不同请求。未新增索引；配置 schema 3、用量库 `user_version` 2、既有表、列、存储值与 DTO/命令序列化均不变，journal 模式、持久性与 busy timeout 也不变。

`quota` 与 `go_usage` 在既有五分钟快照缓存旁各保留一张在途表。航班按精确源身份键控：服务商 id、固定源 key 值、服务商 base URL 与有效配额策略名。身份已有航班的冷未命中会加入它；强制刷新仍绕过已完成的快照缓存，但会加入匹配的在途抓取，而不发起第二个网络请求。owner 通过保持自身接收端存活的 `watch` 通道发布结算结果，因此在结算之后才订阅的跟随者仍能取得该结果。结算仅在条目仍指向同一 owner 时移除它。抓取或解析失败会发布给当前加入者，但绝不写入快照缓存，因此后续查询会重试；在完成前丢弃 owner 会以其航班错误结算并只移除自己的条目，不影响替代航班。固定 key 选择、任何 key 或 base URL 读取之前的有效策略守卫、固定端点、既有 15 秒超时与禁止重定向客户端、300,000 ms 新鲜度、按服务商的 key/base URL 失效、强制刷新绕过已完成缓存以及只读行为均不变。不新增 DTO、命令签名、序列化字段或持久化状态。

`templates::builtin_templates` 经 `OnceLock` 每进程只解析一次编译期内嵌快照，并返回已校验列表的克隆。已持久化模板快照仍在 `effective_template` 中优先，未知或已删除模板 id 仍会失败。`commands`、`auto_refresh` 与 `daily_reset` 无需产品改动：其被测管理路径没有值得编辑的重复读取，模板批次顺序、手动/自动 single-flight、终端写入边界、日重置扫描与生命周期行为均不变。不引入通用 single-flight 框架或调度器重构。

`aiGatewayUsageStats(range, options?)` 与 `aiGatewayRequestLogs(query, options?)` 按完整参数集加入同一次在途读取。条目在精确源 promise 结算时立即移除（失败亦然），因此后续读取会重试且不缓存结果；`{ fresh: true }` 为手动刷新启动独立读取而不加入。该选项类型为内部类型，查询负载、DTO 与命令序列化均不变。

`AiGateway/index.tsx` 保留配置、今日、状态与池的世代号；隐藏页面、较新的配置读取或较新的请求会使更早的响应在提交前失效。隐藏页面不发起任何页面读取，配置事件突发至多运行一次当前作用域读取加一次后续读取，隐藏期间的事件只记录待处理工作。隐藏到可见的切换执行一次连贯页面读取，并消费间隔的一次性追赶。今日失败数由同一统计快照按 `max(0, request_count - successful_request_count)` 派生，因此分组日志读取被移除；仅当统计不可用时，由一次普通的不分组今日日志读取提供回退失败数。配置变更取代更早的读取，运行时更新保留既有合并与草稿行为。

模型列表、模型池、终端集成与三个用量子视图在首次访问时挂载，此后保持挂载（隐藏但保留状态）；服务商仍为初始挂载页签。已访问面板经 memo 化，并在非活动时跳过行、候选与计数派生，回调保持稳定，页签计数经 memo 从配置派生。统计、日志、历史与额度区块按解析后的 locale 缓存 `Intl.NumberFormat`。不修改 DTO、schema、i18n 或运行时状态/可见性 API。

## Alternatives considered

- 增加 TTL 或结果缓存，或为每条路由保留独立配置快照：未采纳，因为从既有身份校验缓存交出的不可变 `Arc` 在没有陈旧窗口或另一失效面的情况下保持新鲜度。
- 对配置字节做哈希以校验缓存：未采纳，因为路径、字节长度与修改时间已经能使每一次真实变化失效（包括直接磁盘重写），无需哈希机密或增加密码学工作。
- 继续为每个已存候选准备完整服务商克隆：未采纳，因为禁用服务商与禁用映射无法被选择或探测，其拷贝工作绝不能随已存集合增长。
- 在记录已投递保留时再次克隆调用方历史：未采纳，因为解析后的历史不可变；前缀与字节预算检查可以读取同一共享值。
- 把共享状态移入可序列化传输类型：未采纳，因为该共享是进程内部的；公共命令、DTO、序列化字段与 schema 保持不变。
- 为观察器与各转换器抽取共享 SSE 分帧 helper：未采纳，因为只有观察器需要「首输出后停止」的规则，而各转换器与 usage 观察器保留不同的容错与完成语义；共享 helper 要么合并这些规则，要么增加一个没有第二个使用者的抽象。
- 缓存查询结果或为用量读取增加 TTL：未采纳，因为需求是从当前文件读取新鲜已提交数据，结果缓存只会增加陈旧性，却不减少占主导的打开、初始化与准备语句工作。
- 让读写共用一条池化连接，或在 SQL 期间持有条目表锁：未采纳，因为读会等待写，且无关数据库路径会在 schema 工作期间串行；按路径分离的条目保持两个边界独立。
- 在没有执行计划证据时新增索引：未采纳，因为被测路径已在既有列上分组与过滤，本次不引入未经验证的索引或迁移。
- 全局串行化额度或 Go 查询，或为在途请求增加结果 TTL：未采纳，因为无关来源会排队，而既有快照缓存已负责新鲜度；按身份的航班只合并同一来源。
- 允许强制刷新在匹配抓取仍在途时另发第二个抓取：未采纳，因为它会重复读取同一账户却不产生更新的数据，并在刷新高峰放大上游负载。
- 让强制刷新复用已完成的快照缓存：未采纳，因为强制刷新的含义就是显式绕过已完成快照；只共享在途合并。
- 每次查询重新解析内置模板快照，或把含持久化状态的有效模板一并记忆化：未采纳，因为内嵌字节不可变，而持久化同步必须保持权威且可观察，不能引入陈旧备忘。
- 缓存已结算的面板读取或增加 TTL：未采纳，因为可见轮询与手动刷新必须观察到已提交行；在途共享在不引入陈旧性的前提下消除重复工作。
- 仅按命令名合并或串行化所有页面读取：未采纳，因为范围、筛选、分组与页码是不同的读取，无关视图会互相等待。
- 保留分组日志读取以计算今日失败数：未采纳，因为统计总量已含请求与成功计数；不分组日志读取仅作为统计不可用时的回退。
- 继续急切挂载所有页签或在离开时卸载页签：未采纳，因为急切挂载会构造未访问视图，而卸载会丢弃筛选、草稿与焦点；首次访问挂载兼顾两者。
- 以 jsdom 耗时作为 UI 改动的门槛：未采纳，因为确定性重复工作计数直接验证读取与渲染工作，jsdom 时间只是代理。

## Consequences

- 热读取共享缓存配置：预热后重复八次模型发现读取观察到零次拥有式配置拷贝，而此前实现观察到八次。
- 下一次读取会观察到文件身份改变的直接配置重写，下一次尝试会观察到在上一次尝试进行中发布的 key 状态；请求起始快照与共享缓存都不会冻结 key 标记。
- 当池的已存候选数从二增长到十二时，服务商拷贝数保持持平，而此前实现分别复制了三次与十三次。只有实际可服务或可探测的候选会被准备，交付顺序与探测保持等价。
- 解析并记录一个已投递延续至多复制一次历史，而此前实现复制两次；既有延续限制与决策不变。
- 流式观察现在在首个有意义事件处结束分帧工作：建立观测的事件仍被计入，而同一读取中的后续事件与之后的全部分片都不再分帧。首字时刻与整次尝试 TPS 保持其定义，首个输出前观察到的无终止符最后有效事件仍在结束时被识别。
- 热查询路径按文件身份只打开、初始化并迁移一次真实数据库，重复的相同读取复用 prepared statements；被删除或被替换的文件会重新打开并初始化，而不是继续从旧句柄返回行。由于不缓存结果，新提交的行仍然可见。
- 用量统计现在用一次分组扫描同时产出模型聚合与服务商行，服务商行经本地模型哈希查找组装；服务商历史在同一查询连接的同一读事务内读取 metadata 与汇总。
- 验证：五个新回归通过，聚焦套件在 `--test-threads=1` 下通过 119 个测试（routing 15、pools 25、continuation 43、attempt policy 15、reasoning 21）。routing 模块的 15 个断言通过，但外层 shell 包装器在测试命令之后对只读 shell 变量赋值失败，因此不声称干净的包装器退出码。这些聚焦计数本身不证明端到端延迟、吞吐、缓存命中、成本或常驻内存改善；对比测量记录如下。
- 流式回归通过：网关测试在 `--test-threads=1` 下 179 个通过（输出计时 41、原生 Messages 11、Anthropic 转换 40、OpenAI 转换 44、池同轮延续 43）。未发现字节、事件、工具身份、用量、取消或整次尝试计时的等价性回归。不声称端到端延迟改善。
- 数据库回归与聚焦套件通过：精确的查询复用回归通过，套件通过 usage store 18 个（另有 1 个既有 ignored）、provider usage 10 个、migration 30 个与 DeepSeek cache 20 个。第一次 migration 调用在仅编译准备阶段达到 600,000 ms 工具超时且没有测试结果；完全相同的重跑完成 30/30 个 migration 测试并通过。计数器是线程局部的，因此未运行并行全套执行；写侧准备与进程级隔离不在这些计数器范围内。
- 首字与整次尝试 TPS 的公开定义未被取代：[Gateway Request Latency: Observed First-Token and Generation TPS](../feature/2026-10-14-gateway-request-latency.md) 与 [Gateway Whole-Attempt Average TPS](../bug-fix/2026-10-16-gateway-whole-attempt-tps.md) 的定义、验证与持久化事实继续有效；本记录只增加「首个有意义事件后停止分帧」这一观察工作量事实。
- Supersession：[Gateway Configuration Writes Serialize on One Lock and Reads Cache by File Identity](2026-09-25-gateway-config-write-serialization-and-read-cache.md) 被部分取代。其串行写锁、文件身份缓存、原子发布、迁移与无操作抑制继续有效；本记录把其每次读取的拥有式克隆替换为共享 `Arc` 交接。[Core Workflows Cleanup and Optimization](2026-10-09-core-workflows-cleanup-and-optimization.md) 在配置重读、池/历史拷贝与网关数据库连接事实层面被部分取代。其尝试策略抽取、串行结算、不冻结的逐次尝试重读、写连接、单请求事务、commit 后保留清理与日志失败隔离继续有效；本记录增加独立的查询连接、prepared statement 复用与单次扫描聚合。两条记录均保留并交叉链接；不做完整合并。
- 并发的匹配冷启动或强制额度与 Go 用量查询现在只执行一次网络抓取，而 key、base URL 或有效策略不同的查询保持独立，各自取得自己的结果。
- 失败的额度或 Go 用量查询会传递给当前加入者，但不留下快照条目，因此下一次查询会重试；被取消的 owner 以错误结算其跟随者，且不会滞留后续查询。
