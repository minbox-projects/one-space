# Agent Note: Native Anthropic Messages Entry, Protocol Recognition and OpenAI Entry Conversion

Status: implemented

[English](2026-10-11-ai-gateway-anthropic-messages.md) | 中文

## Problem

AI 网关此前只中继 OpenAI 兼容的 `/v1/chat/completions` 与 `/v1/responses` 两个入口。服务商持久化的 `protocol` 只认识 `chat_completions` 与 `responses`，模型清单来源解析会丢弃 `supported_endpoints` 中既未声明 Chat Completions 也未声明 Responses 的条目，且回环服务器把 `/v1/messages` 当作未知路径。因此仅支持 Messages 的上游既无法被配置、也无法被原生调用，而使用原生 Messages 协议的 Claude Code 在网关中没有任何入口。当这类上游可配置之后，既有 OpenAI 入口仍然无法触达它：候选解析把 Anthropic 映射排除在 Chat 与 Responses 请求之外，且不存在任何请求、响应或流转换，因此使用 Chat Completions 或 Responses 的调用方无法使用网关仅能经 Messages 服务的模型。终端同步与 configure/sync 命令只支持 `opencode` 与 `codex`，刻意不触碰 `claude` 记录，也没有任何位置持久化操作者的四个模型选择（默认模型加 haiku/sonnet/opus 家族别名）。Claude 工具的原生 Anthropic 基地址是不带路径的回环 origin，而不是 OpenAI 工具的 `/v1` 基地址，因此复用既有基地址会追加第二个 `/v1`。既有服务商 upsert 会整体替换记录，因此省略选择的后续同步会静默清空它们，而固定的 profile code 或未标记的用户记录可能命中或覆写用户自己的 Claude 配置。

## Decision

- 持久化协议：在 `src-tauri/src/ai_gateway/types_config.rs` 新增 `UpstreamProtocol::AnthropicMessages` 并序列化为 `anthropic_messages`；它被服务商默认、每条映射行、模板默认与每个模板模型接受，`endpoint_path()` 返回 `/messages`。`src-tauri/src/ai_gateway/migration.rs` 中穷尽的协议匹配把新变体当作兼容管道处理；配置 schema 保持 3，不引入迁移。
- 来源识别：`src-tauri/src/ai_gateway/templates.rs` 在声明的 `supported_endpoints` 中按 Chat Completions > Responses > Messages 的偏好识别 `/messages` 与 `/v1/messages`；三者都不含的条目被丢弃，没有端点信息的条目不带协议并继承模板。通用继承与 Go 声明感知路径保持不变，源声明的 Messages 端点现在进入兼容集合，禁用/忽略状态与原子同步不变。
- 路由模块：`src-tauri/src/ai_gateway/anthropic.rs` 提供原生辅助 `is_messages_path`、`DEFAULT_ANTHROPIC_VERSION`（`2023-06-01`）、Anthropic 的 `error_payload` 与 `stream_error_event` 分片，以及转换入口 `is_conversion_path`、`convert_request`、`convert_response` 与 `validate_conversion_request`；`src-tauri/src/ai_gateway/anthropic_sse.rs` 提供只读的 `AnthropicSseObserver` 与 `AnthropicSseConverter`；转发路径以 `feed` 与 `finish` 驱动转换器，`feed` 在上游字节上暴露的转换错误属首字节后失败，会停止流且不写成功标记，`finish` 转换到达时缺少空行终止符的尾部事件，因此终止完成标记仍会发出。
- 原生入口：`src-tauri/src/ai_gateway/runtime_http.rs` 提供 `POST /v1/messages`，包括 `?beta=true` 这样的查询串（同时容忍 `/messages`），以本地 Key 经 `Authorization: Bearer` 或 `x-api-key` 本地鉴权，网关自身生成的错误使用 Anthropic 错误信封/事件，只替换映射后的模型，把选中的上游密钥池 key 作为 `x-api-key` 发送，透传 `anthropic-beta` 与 `anthropic-version`，并且仅当调用方省略时才补充 `anthropic-version: 2023-06-01`；该路由上配置读取失败改用 Anthropic 错误信封而非 OpenAI 信封。停止监听不依赖可读配置：配置不可读时 `stop_server` 仍停止正在运行的监听器并上报 best-effort 状态。
- 请求转换：启用的 `anthropic_messages` 映射（或 Anthropic 默认）现在也服务 Chat 与 Responses 调用方。`convert_request` 把 `system`/`developer` 消息与 Responses 的 `instructions` 转换为 Messages 的 `system` 字段，把文本与 URL/base64 的 `image_url`/`input_image` 内容转换为文本/图片块，把 `user`/`assistant` 轮次、客户端函数工具 schema 转换为带 `input_schema` 的 `tools`，把助手 `tool_calls` 与 Responses 的 `function_call` 转换为 `tool_use`，并把 `tool`/`function_call_output` 结果转换为 `tool_result`，保留工具 id 与多轮连续性。`tool_choice` 把 `auto`/`required`/`none`/`function` 映射为 `auto`/`any`/`none`/`tool`，`parallel_tool_calls: false` 把 `disable_parallel_tool_use` 折叠进 `tool_choice` 对象（缺省选择变为携带该标志的显式 `auto`，因为该对象是 Anthropic 接受该控制的唯一位置），`temperature`/`top_p` 透传，Chat 的 `stop` 变为 `stop_sequences`。对 Chat，`max_completion_tokens` 优先于 `max_tokens`；Responses 使用 `max_output_tokens`；省略的上限默认 4096；显式零或正整数保留，负数、小数或字符串上限在任何 Anthropic 尝试之前以字段级 400 拒绝。入站 Chat 或 Responses 请求体的 `stream` 严格为布尔 `true` 时，把 `stream: true` 写入转换后的 Anthropic 请求体；`stream` 缺失或为 `false` 时省略该字段（绝不写成 `false`）。原生请求绝不接受该转换默认值。
- 不支持的转换：`previous_response_id`、未解析的条目引用、`background: true`、`store: true`、`n > 1`、不受支持的 `response_format`（JSON/schema 输出；纯文本 `{"type":"text"}` 在 Anthropic 侧没有对应控制、按无操作接受）与不可翻译的非空推理选项，都会在 Anthropic HTTP 或 key 健康尝试之前以字段级 400 拒绝，且当任一候选解析为 `anthropic_messages` 时 `runtime_http.rs` 会在尝试之前执行该校验。携带这些字段的同协议 OpenAI 请求保持既有透传行为，绝不被转换器拒绝。
- 响应转换：`convert_response` 把 Anthropic JSON 响应体转换为调用方格式并标识本地模型：文本块变为 Chat 消息内容与 Responses 的 `output_text`，`tool_use` 块变为 Chat 的 `tool_calls` 与 Responses 的 `function_call` 条目（参数的字符串形式），完成原因与用量一并转换；无法转换的上游 2xx 响应体变为调用方格式的 502 `conversion_error`，而不是原始 Anthropic 字节。
- 流转换：`AnthropicSseConverter` 把分片的 Anthropic SSE 增量转换为调用方事件，具有稳定的文本与工具标识和有序参数增量：`message_start` 捕获消息 id 并合并用量，且对 Responses 先以 `response.output_item.added` 宣告助手 `message` 条目、对 Chat 不发增量；`content_block_start`/`input_json_delta` 发出 Chat 工具调用分片或 Responses 的 `response.output_item.added`/`response.function_call_arguments.delta`；文本增量发出 Chat 内容或 Responses 的 `response.output_text.delta`；`message_stop` 发出恰好一次 Chat `[DONE]`，或对 Responses 先为已宣告的助手消息发 `response.output_item.done`，再发 `response.completed`，其 `response.output` 携带助手消息条目与 `function_call` 条目、`response.usage` 为包含式输入用量。ping 等原生专属事件不编造任何内容。`AnthropicSseObserver` 只读转发字节，按字段合并 `message_start.message.usage` 与累积 `message_delta.usage`（出现的值替换、缺失的值保留）；原生与转换流都只有在 `message_stop` 之后才算成功，带内 `error` 事件绝不视为成功。
- 失败与生命周期：首字节之后出错、EOF、转换器 `feed` 错误或缺少 `message_stop` 会以调用方格式结束转换流且绝不写成功完成标记或重放，而原生流保持其原生错误格式；该失败尝试保留失败前累积并按字段合并的用量。既有首客户端字节重试边界、下游取消（丢弃缓冲行且不结算上游健康）、空闲读取超时、key 轮换、探测与健康结算均不变。
- 转换感知解析与计量：`src-tauri/src/ai_gateway/selection.rs` 在候选的有效协议等于入站协议时，或在候选为 `anthropic_messages` 且入站协议为 Chat Completions 或 Responses 时解析该候选。`runtime_http.rs` 在任何 Anthropic 尝试之前执行 `validate_conversion_request`，包括唯一候选解析为 `anthropic_messages` 的半开探测，因此不受支持的字段是字段级 400，既不到达上游也不结算任何探测或 key 健康；探测按被探测行自身生效的上游协议转发（自动禁用行对正常的已服务行解析不可见）。因此原生 Messages 绝不选择 Chat 或 Responses 上游，Chat-only 与 Responses-only 上游在没有 Anthropic 适配器时保持互斥，禁用行、自动禁用行、默认、加权调度、会话亲和与 key/重试策略保持既有行为。用量在转换之前取自实际上游：按字段的 Anthropic 合并归一化为既有四档，因此转换后的 Chat 响应报告包含式输入（普通输入加缓存读加缓存写，符合 OpenAI 形态），而持久化的普通上游输入保持独立。
- Claude 目标与 DTO：`claude` 加入既有 `ai_gateway_configure_terminal` 与 `ai_gateway_sync_terminal` 命令，两者新增可选 `claude_models: Option<ClaudeModelSelection>` 参数。`ClaudeModelSelection`（`src-tauri/src/ai_gateway/types_config.rs`）携带四个显式本地映射 id `{ default_model, haiku, sonnet, opus }`，每个都是本地 id（绝不从模型名猜测厂商 id），同一 id 可填多个槽位。同一结构体也被序列化到仅模型快照 `TerminalTarget.claude_models`，且绝不携带凭据值。
- 校验与原子性：`src-tauri/src/ai_gateway/commands.rs` 的 `validate_claude_selection` 要求四个选择都非空、已启用且可作为原生 Anthropic Messages 本地映射（一条 Anthropic 映射行或服务商默认，经与请求路径同一套权威 `selection::resolve_model_for_protocol` 解析）服务。缺失的首次选择、非法选择或无可用本地 Key 会在任何 Claude provider/ledger/projection 写入之前被拒绝，且整批载荷在首个 upsert 之前全部构建，因此拒绝不会留下部分已 upsert 的批次。
- 持久化与所有权：四个选择只持久化在 gateway 拥有的 canonical Claude 服务商顶层 `model` 与 `claude_model_mappings`（`haiku`/`sonnet`/`opus` 三行的 `upstream_model`），后续同步从该拥有记录读回完整选择、经与显式提交相同的 `validate_claude_selection` 可服务性校验后再整份重发，因此既有替换式 upsert 无法清空省略的选择，不可用或不可服务的已存选择也绝不会被盲目重发。管线只复用同工具、同 profile 的标记网关记录；`code` 在首次创建时由新 provider UUID 派生并在此后原样复用，因此固定名冲突或用户自己的未标记服务商绝不会被认领或覆写，另一 profile 的记录不受影响。
- Origin、变量与复用：`src-tauri/src/ai_gateway/storage.rs` 新增 `local_origin(port)`，即不带 `/v1` 的裸回环 origin `http://127.0.0.1:<port>`。Claude 服务商以该 origin 作为 `base_url`，并写 `claude_api_format = "anthropic_messages"`、`claude_connection_mode = "native_anthropic"` 与 `claude_auth_env_key = "ANTHROPIC_API_KEY"`，复用既有 upsert、按 profile 激活与 Claude 投影。手动同步成功后激活并投影 Claude；由于 upsert、激活与投影不是同一事务，之后的投影失败会被如实上报，而不是谎报为成功应用。
- 目标、pending 与 fan-out：`TerminalTarget` 新增可选的仅模型 `claude_models` 快照（不含凭据）；Claude 目标的 `pending_sync` 比较 ledger 的 key id 与裸 origin，并把不可读或不完整的选择视为漂移，因此地址、Key 与选择都当前时不 pending。先前已同步的 Claude 记录参与既有的 best-effort 模板刷新 fan-out（`previously_synced_terminal_tools` 顺序 `opencode`、`codex`、`claude`）；无效或缺失的选择只跳过该次自动 Claude 写入，且不提示、不替换、不清空已保存的选择，而其他被请求的工具（`opencode`、`codex`）仍照常同步，模板同步结果仍然成立。
- OpenCode 适配器优先级：只要任一启用网关能经 Chat Completions 或 Anthropic Messages 服务该本地模型（包括同时可经 Responses 与 Anthropic 服务的来源），OpenCode 就保持既有 Chat 适配器；只有真正仅 Responses 的本地模型获得 `@ai-sdk/openai` npm 覆盖。Codex 配置、身份与手动激活不变。
- 前端协议选择器：`src/lib/aiGateway.ts` 的 `GatewayUpstreamProtocol` 联合类型新增 `anthropic_messages`，且全部四个配置面——模板默认、单个模板模型行、服务商默认与单个服务商映射行——都提供第三选项，英文标签 `Anthropic Messages (native)`、中文标签 `Anthropic Messages（原生）`（键 `aiGatewayProtocolAnthropicMessages`）。行选择器保留继承：缺省或 `null` 的行协议仍跟随父级，因此一行可用 Messages 而相邻行保持 Chat 或 Responses。
- 协议徽标、计数与筛选：`gatewayShared.ts` 的 `protocolShortLabel` 返回 `Anthropic Messages`，`protocolBadgeClass` 为其提供独立色调；`ProviderTemplateSection` 统计并筛选第三协议，`ProviderTemplatePickerDialog` 在模板卡片上展示它，`ModelListPanel` 的协议筛选与端点徽标纳入第三协议并显示 `/messages`。
- Claude 目标与选择对话框：`AI_GATEWAY_SUPPORTED_TERMINAL_TOOLS`（`src/lib/aiGateway.ts`）现含 `claude`，`TerminalSyncPanel` 渲染 Claude 目标行（`ai-gateway-target-claude`、动作 `ai-gateway-sync-claude`）。新组件 `ClaudeModelSelectionDialog`（`src/components/AiGateway/ClaudeModelSelectionDialog.tsx`）经 `open`/`models`/`initialSelection`/`busy`/`onSubmit`/`onCancel` props 收集四个选择，并使用 `claude-model-selection-dialog`、`claude-model-select-default`/`-haiku`/`-sonnet`/`-opus` 与 submit/cancel testid。
- 前端终端封装：`GatewayTerminalTarget` 新增可选 `claude_models` 快照，`src/lib/aiGateway.ts` 导出 `ClaudeModelSelection = { default_model, haiku, sonnet, opus }`；`aiGatewayConfigureTerminal(targetTools, claudeModels?)` 与 `aiGatewaySyncTerminal(targetTools?, claudeModels?)` 仅在提供选择时附带顶层 `claudeModels` 键，保持嵌套 snake_case 形状且绝不携带凭据。
- Claude 选择流程：候选本地 id 来自聚合后端点 `anthropic_messages` 的启用映射，因此对话框绝不提供不受支持的模型。有效已存选择直接复用而不弹窗；首次、缺失或不可服务的选择（槽位为空或 id 不在可服务候选集合内）打开对话框；取消不写任何命令。对话框与标签随英文/中文键 `aiGatewayClaudeModelDialogTitle`/`aiGatewayClaudeModelDialogDesc`、`aiGatewayClaudeDefaultModel`、`aiGatewayClaudeHaikuModel`、`aiGatewayClaudeSonnetModel`、`aiGatewayClaudeOpusModel` 与 `aiGatewayClaudeModelPlaceholder` 一起交付。

## Alternatives considered

- 保留仅 OpenAI 的协议枚举并为 Messages 入口单独配置：未采纳，因为服务商默认与映射行已经表达有效协议，平行的配置面会重复模板绑定、密钥池与选择逻辑。
- 把原生入口与 OpenAI 入口转换作为不可分割的一步交付：未采纳，因为原生入口与协议识别可独立验证，而转换依赖它们的选择与运行时管道已经就位。
- 直接把 Chat Completions 转换为 Responses 或反向转换、合成多个生成候选、增加服务端 Responses 会话/检索/后台存储，或猜测结构化输出与推理参数等价物：未采纳，因为这些都不是调用方请求的协议，且会凭空发明上游可能不支持的行为；不受支持的关键字段改为按字段拒绝。
- 修复或静默改写不支持的转换输入而不是拒绝它：未采纳，因为发送畸变或降级的请求会歪曲调用方意图；在任何尝试之前给出字段级 400 是明确且安全的。
- 让转换输出上限无界或继承任意上游默认值：未采纳，因为省略的上限需要一个确定且有文档的边界；固定的 4096 默认值只应用于转换请求。
- 改写或规范化原生流字节，或向原生流注入 OpenAI 终止符：未采纳，因为原生调用方与本网关都是字节忠实的中继，注入 `[DONE]` 或改写事件会破坏 Messages 协议。
- 为 Claude 提供独立的同步路径与自己的存储，而不是扩展现有 configure/sync 命令与 canonical 服务商：未采纳，因为这会重复 upsert、激活、投影与标记所有权，而既有命令已经表达按工具的目标。
- 只把四个选择存到终端目标或新的旁路台账，而不是拥有的 canonical Claude 服务商：未采纳，因为 canonical 服务商是既有投影器已经读取的唯一来源，平行存储会与投影出的 `ANTHROPIC_MODEL` 与家族变量失去同步。
- 派生固定的 Claude profile code 或复用任意同工具记录：未采纳，因为固定 code 会在不同安装间冲突，而未标记记录是用户自己的配置；由 UUID 派生、且只在拥有的标记记录上复用的 code 让再次同步幂等而不认领用户数据。
- 为 Claude 在 OpenAI 基地址上追加 `/v1`，而不使用裸 origin：未采纳，因为 Claude 的原生 Anthropic 基地址就是 origin，且网关已经容忍缺失 `/v1`；第二个 `/v1` 会产生重复的版本段。
- 当模型不可用时静默清除或替换 Claude 选择：未采纳，因为抹掉操作者的显式选择具有破坏性；自动刷新跳过 Claude 写入，手动同步请求替换。
- 要求四个选择必须互不相同：未采纳，因为操作者可能刻意让多个家族别名指向同一模型；只有空白、禁用或不可服务的 id 才被拒绝。
- 每次 Claude 同步都打开四选择对话框，而不只在首次、缺失或非法选择时打开：未采纳，因为已保存的选择是权威的，每次重复询问会丢弃操作者的显式选择并给重复同步增加摩擦。
- 把四个模型槽位内联在终端行中而不是使用对话框：未采纳，因为四个选择组成一份必须在任何写入之前一起校验的协调载荷，而对话框保持该行的单动作形态。
- 以厂商模型名而不是本地映射 id 作为候选项：未采纳，因为原生 Messages 上游只能服务操作者已配置的本地映射 id，而厂商名是网关无法校验的猜测。

## Consequences

- 服务商默认或映射行可以持久化 `anthropic_messages`，既经原生 `POST /v1/messages` 入口服务，也经转换通过既有 `/v1/chat/completions` 与 `/v1/responses` 入口以调用方请求的模型标识服务；原生 Messages 请求仍只选择 Anthropic 上游。
- 请求、JSON 响应与 SSE 转换覆盖 system/developer/instructions、文本与 URL/base64 图片、函数工具 schema、调用与结果、tool choice、并行控制、采样/停止选项与输出上限，并给出有序的增量调用方事件；上限遵循既定优先级（Chat `max_completion_tokens` 优先于 `max_tokens`，Responses `max_output_tokens`，默认 4096），非法上限与不受支持的关键语义在任何 Anthropic 尝试之前按字段失败。
- 流保持增量与稳定的标识和顺序：Chat 以 `[DONE]` 恰好结束一次，Responses 携带自己的工具与完成事件，仅 ping 输入不编造内容，首字节后出错、EOF 或缺少 `message_stop` 产生调用方格式的失败且无成功标记或重放，同时保留已捕获的用量。
- 转换感知解析保留每一条运行时边界：尝试与探测都携带实际生效的上游协议，加权调度保持在入站范围内，排除、默认阻塞与 key/重试策略成立，原生 Messages 绝不选择 OpenAI 上游，Chat-only 与 Responses-only 上游保持互斥。
- 计量保持实际：按字段的 `message_start`/`message_delta` 合并归一化为既有四档，转换后的 Chat 响应包含式输入可与持久化的普通上游输入不同，而尝试、价格与服务商标识仍取上游实际值。
- 兼容与边界：配置 schema 保持 3 且无新迁移，同协议 OpenAI 载荷除既有模型改写外保持既有行为，且不添加 Chat 到 Responses 的转换、多候选、服务端 Responses 存储、结构化输出/推理推断或整理的模型/价格清单。本变更交付 Step 1 与 Step 2（原生入口、协议识别与 OpenAI 入口转换）、Step 3（Claude 终端同步：目标、DTO、命令、校验、持久化、所有权、origin 与 fan-out）、Step 4（四条协议选择器、第三协议标签、徽标/计数/筛选、Claude 目标行与四选择对话框）与 Step 5（`MEMORY.md`、导航索引、本 Note 与 `docs/USAGE.md` 的已交付指引，以及集成门禁）。
- 前端配置面：模板默认与模板模型行、服务商默认与服务商映射行都带继承地选择 `anthropic_messages`，且协议徽标、计数与筛选纳入第三协议，`ModelListPanel` 的端点徽标显示 `/messages`。
- Claude 选择面：Claude 终端行直接复用有效已存选择而不弹窗，仅在首次、缺失或不可服务的已存选择时打开四选择对话框；对话框只提供可经原生 Messages 服务的本地 id，取消不写任何内容，提交的选择作为顶层 `claudeModels` 键到达命令，绝不携带凭据。
- Claude 终端同步：四个有效选择的首次手动同步把它们持久化到拥有的 canonical 服务商并激活/投影 Claude；后续同步复用它们，无效的自动刷新只跳过 Claude 写入而不替换、其他工具仍照常同步，手动同步可请求替换，用户未标记的服务商或另一 profile 绝不被覆写。
- 集成门禁与验证：限定范围的网关集成运行 `cargo test --manifest-path src-tauri/Cargo.toml --lib ai_gateway::` 退出码 0，755 通过、0 失败、2 忽略，覆盖跨入口路由、探测、key 与实际用量/计量；修复轮中聚焦的 `claude_projection`（7 通过）与 `claude_profiles`（36 通过）套件、以及前端 Step 4 `vitest` 全量（632 通过）与 `tsc`/build 退出码 0 同样通过。`tools/check-ai-gateway-redaction.sh` 退出码 1，唯一命中是 `src-tauri/src/ble_lock/central.rs` 中 `authorization_from` 的参数名 `authorization` 与其类型 `CBManagerAuthorization` 组成的参数标注被 Authorization/Cookie 头部字面量正则匹配的既有误报（主线已存在，与本计划无关）；本计划新增测试文件命中 0 处，私钥与凭据字面量计数仍为 0。因无凭据或 CLI，live provider/CLI smoke 被跳过，不计为通过。
- `MEMORY.md`、权威的 `ai-gateway`（前端）与 `ai-gateway-backend` 导航条目、重新生成的 `navigation.md` 与 `docs/USAGE.md` 在同一变更中描述新模块、符号、测试、调用方路由、混合逐模型协议、Claude 选择流程与回滚。
- 部分取代：[API Gateway Provider Templates and Incremental Model Sync](2026-09-18-api-gateway-provider-templates.md) 保留其增量合并、忽略集合生命周期与称谓决策，而其端点过滤与识别新增 Messages，且其识别出的 Messages 映射现在可经既有 OpenAI 入口通过转换服务；[Provider Templates Own Closed Strategies and Bind Providers by Template Id](2026-10-10-provider-template-bound-strategies.md) 保留其封闭策略字段、绑定校验与有效策略解析，而其 Go 声明基线接纳源声明的 Messages id，且该 id 现在可由转换经 OpenAI 入口服务；[API Gateway Cache Hit Rate Normalizes Provider Usage Semantics](../bug-fix/2026-09-21-api-gateway-cache-hit-accounting.md) 保留其四档归一化、存储迁移、合格谓词与覆盖契约，而原生与转换的 Messages 用量由独立的按字段合并观察，且转换调用方的包含式输入仍与持久化的普通档位不同；[OpenCode Responses-Only Models Carry the @ai-sdk/openai npm Override](../bug-fix/2026-09-28-opencode-responses-npm.md) 保留其按模型 npm 覆盖、跨全部启用网关求值与回滚决策，而其「网关不做请求体转换」边界与逐模型可服务性现在计入 Chat/Responses 到 Messages 的转换以及 Anthropic Messages 作为可经 Chat 服务来源，因此覆盖仅留给真正仅 Responses 的模型；[API Fusion Terminal Sync Writes an Independent Gateway Provider](../feature/2026-09-17-api-fusion-terminal-independent-provider.md) 保留其独立服务商、台账复用与标记所有权决策，而 `claude` 成为第三个受支持终端目标并拥有自己的模型选择、裸 origin 与激活/投影，且终端面板新增其 Claude 行与四选择对话框（首次、缺失或不可服务的已存选择会提示，有效已存选择直接复用而不弹窗，取消不写任何内容），从而收窄其早先「不触碰 `claude` 记录」的表述。
