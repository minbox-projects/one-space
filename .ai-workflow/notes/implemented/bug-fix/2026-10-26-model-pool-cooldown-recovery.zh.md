# Agent Note: 模型池候选冷却有界并在精确来源成功后清除

Status: implemented

[English](2026-10-26-model-pool-cooldown-recovery.md) | 中文

## Problem

模型级失败只冷却受影响的模型池候选，但可用性完全照搬上游的 `Retry-After` 取值。一次带整日提示的 429 `FreeUsageLimitError` 响应因此可以让本来健康的候选整天不可用，即使网关只应根据自己观察到的请求判断可用性。该冷却也没有成功恢复路径：当另一个池或普通映射已经证明该精确来源可以再次服务时，候选仍在每个池中被排除，直到截止时间到期。

## Decision

- `model_pools::cool_pool_candidate` 把候选冷却上限固定为 `POOL_CANDIDATE_COOLDOWN_SECS = 60`。缺失或非法延迟回退到 60 秒；有效的 `retry-after-ms` 或 `Retry-After` 零、亚秒或更短时长原样保留；更长延迟封顶到 60 秒。截止时间仍是进程内存中的单调时刻，并对同一候选跨入站共享。
- 当正常完成的成功尝试在原始服务商 id、trim 后的本地/上游模型对与生效上游协议上完全匹配时，`attempt_policy::settle_success` 释放该精确来源的冷却。清除按来源身份而非池匹配，因此普通候选、key 探测与后备对同一来源的引用一起恢复。
- 只有正常完成的成功尝试会清除冷却。普通直连映射、池常规候选与池后备都走同一成功结算；失败、取消或中止的流不清除，兄弟模型或不同生效协议保持冷却，服务商级操作绝不清除无关身份。
- 半开探测成功保持既有探测结算，不改变候选冷却策略。候选冷却仍与 key/账户健康和映射自动禁用分离：清除它绝不标记或耗尽共享 key，绝不登记映射健康，既有凭据、账户耗尽与探测规则保持不变。
- 可用性由请求驱动：网关只能从自己观察到的成功中清除冷却。外部客户端（例如 OpenCode）直接发往自己服务商、绕过网关的请求不可见，不能缩短冷却。

## Alternatives considered

- 严格照搬上游每个重试提示：拒绝，因为陈旧或模型级的整日提示会让候选在观察到该请求很久之后仍被排除，而网关无法验证提示是否仍然有效。
- 只让冷却到期、不提供成功恢复：拒绝，因为另一个池或普通路由已经证明精确来源健康时，候选仍会在所有池中被排除。
- 在任意尝试、兄弟模型或服务商范围上清除冷却：拒绝，因为这会把恢复扩大到未经证明的来源，并可能掩盖真实失败。
- 持久化冷却或主动探测上游来获知健康：拒绝，因为冷却仍为进程内存，既有每请求探测策略和持久 key/映射标记保持独立。

## Consequences

- 模型级失败至多排除候选 60 秒；零、亚秒与更短提示仍精确保留，整日提示不再让健康来源整天退出服务。
- 经任一网关路由取得的精确来源成功会让它在所有池中立即重新可用；兄弟模型与其他协议各自保留冷却。
- 网关无法观察外部客户端直连请求，因此冷却只能由网关观察到的成功或 60 秒到期结束；这一可见性边界不承诺外部健康。
- 验证：`src-tauri/src/ai_gateway/tests/model_pools.rs` 中的限定行为测试覆盖 60 秒上限及 59/60 秒可用边界与真实路由重试、流式与非流式成功跨池清除、兄弟模型与协议冷却不变，以及失败流不清除。四个聚焦冷却用例、完整模型池用例集、池终端同步用例集以及 OpenAI 与 Anthropic 转换用例集均通过，无失败。
- 本记录只细化 [Model Pools Route One Public Alias Across Explicit Source Candidates](../feature/2026-10-13-free-model-pool.md) 的候选冷却条目；该记录其余每项决策继续有效。
