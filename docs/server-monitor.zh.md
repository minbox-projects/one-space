# Server Monitor

[English](server-monitor.md) | 中文

## Overview

服务器监控通过 SSH 采集可访问 Linux 主机的 CPU、内存、本地磁盘与网络使用情况，并以既有 OneSpace 工具风格展示当前数值、采集状态和保留的历史记录。它使用你已有的 SSH 账户执行固定的只读命令，不安装 exporter 或 agent，不开放指标端口，不创建转发隧道，也不修改任何远端配置。该工具仅支持 Linux，并要求从本机可直连 SSH；只能通过其他网络访问的主机需要先具备自己的访问路径。

## Requirements

- 从本机可直连 SSH，并沿用既有 SSH 的配置解析、身份认证与 host-key 校验行为。
- 使用已有 SSH 别名，或使用自定义连接填写主机、端口、用户以及密码或私钥路径。Agent 认证通过已有 SSH 别名提供；自定义连接提供密码与私钥两种认证。
- 普通用户账户即可读取 `/proc`，并可运行 `cat`、`sleep`、`df` 与 `uname`。`df` 应为 GNU 兼容实现，因为采集会执行 `LC_ALL=C df -l -P -k -T`。
- 不需要 `sudo`、已安装服务、exporter、agent、转发端口或 HTTP 指标端点。命令缺失或不受支持时只会使对应资源不可用。

## Managing targets

在工具中点击 **Add** 创建目标。名称会被去除首尾空白，长度必须为 1–80 个字符。可选择已有 SSH 别名或自定义连接；自定义连接要求主机、用户、1 到 65535 的整数端口，以及密码或私钥路径。目标默认启用，显示名称允许重复，但每个目标保留独立身份。

**Edit** 更新同一条存储记录。编辑密码认证目标时留空密码会保留已存储的密码，界面只显示“已存在密码”；输入新密码则替换。新建密码认证目标必须提供密码。**Test connection** 使用草稿值执行一次临时一次性采集，无论结果如何都会关闭会话，且不保存目标与历史。**Save** 只有在加密配置写入成功后才会发布新状态。

**Pause** 停止该目标的自动采集并关闭其自有会话；显式 **Collect now** 仍可执行，且不会改变暂停状态。**Delete** 会要求确认并说明该目标已采集的历史也会被移除。确认后删除该目标的样本与每日时段认领；取消则不写入任何内容。删除一个目标不会影响其他目标。

## Scheduling modes

同一时间只有一种调度模式生效。**Settings → Services → Server Monitor** 控制两种模式，工具内的设置操作会直接打开该区块。

### Interval mode

周期模式为每个目标最多保持一个持久 SSH 会话。应用启动、目标激活、恢复目标以及启用自动采集时会采集一次，之后在上一轮采集完成后才开始下一轮。持久会话在空闲 30 秒后显式发送 keepalive，keepalive 与采集在同一会话上串行执行。保存修改后的间隔会从保存时间重新计时，不会额外采集一次。手动采集与计划采集冲突时会共享正在进行的结果。全局最多同时进行四个采集，单个目标绝不会同时有超过一个采集。

### Daily mode

每日模式支持多个本地时间点。每个到点的采集都会新建一次性 SSH 会话，执行一次采集后在成功或失败时关闭；时间点之间不保留会话或 keepalive。启动、保存、创建目标与恢复目标只会武装本机时区中的未来时间点。错过的时段会被跳过，睡眠或退出应用后不会补采。

在对某个目标、本地日期与时间执行任何网络操作之前，调度器会持久认领该时段。即使遇到重复 tick、应用重启或时钟回拨，一个时段最多也只尝试一次；认领写入失败时不会建立连接。夏令时前进造成的不存在时间会被跳过；回拨造成的重复时间在同一本地日期与时间最多执行一次。手动采集与到点时段重合时会认领该时段并共享结果。周期模式切换到每日模式会关闭持久会话并等待下一个未来时间点；每日模式切换到周期模式会在旧工作释放后执行初次周期采集。全局禁用或暂停目标都会关闭自有会话。

## Settings and validation

默认值为启用自动采集、周期模式、5 分钟间隔、每日时间 `09:00` 以及 7 天历史保留。

- 间隔必须是 1 到 1440 分钟的整数。
- 保留天数必须是 1 到 30 天的整数。
- 每日时间必须是非空的精确 24 小时制 `HH:mm` 列表，且不能重复。`00:00` 与 `23:59` 有效；`9:00` 与 `24:00` 无效。有效保存时间会被排序。
- 可在设置中配置 CPU、内存与硬盘的告警阈值（1 到 100%），以及告警冷却时间（1 到 1440 分钟），避免告警消息频繁写入。

前端与后端都会校验提交值，绝不静默修正非法输入。只有当前模式控制调度，非活动模式的数值会保留。保存、重置与脏状态仅属于该设置区块，不会改变其他区块。重置会丢弃草稿并重新加载已保存值。缩短保留期会永久删除新窗口之外的历史，区块内会给出提示。

## Metrics and states

CPU 来自同一次采集中的两次 `/proc/stat` 采样。总时间由 user、nice、system、idle、iowait、irq、softirq 与 steal 组成，不会再次累加 guest 与 guest_nice。使用率为 `100 × (Δtotal − Δidle − Δiowait) / Δtotal`。出现负增量、CPU 标识变化或非正总增量时，CPU 数值不可用。

内存使用 `/proc/meminfo`：已用为 `MemTotal − MemAvailable`，从内核 kB 转换为 1024 字节单位。缺少 `MemAvailable` 时内存不可用，不会回退到 `MemFree`。

磁盘数据来自 `LC_ALL=C df -l -P -k -T`。每个本地持久挂载显示总量、已用、可用空间与 `used / total`。支持包含空格的挂载路径。`proc`、`sysfs`、`tmpfs`、`devtmpfs`、`overlay` 与 `squashfs` 会被排除；挂载绝不求和。可用空间为负时视为零可用空间，同时保留报告中的已用与总量；总量非法或为零则不可用。磁盘卡片显示使用率最高的挂载，下方提供全部硬盘挂载点使用概览。当服务器出现任意一项指标超出告警阈值时，在左侧卡片及详情页进行显著图标与 Tag 标注，并在满足冷却时间时向消息中心写入告警通知。

网络速率按网卡分别计算，用同一次采集中的计数器增量除以真实的 uptime 正差值。`lo` 被排除，网卡之间绝不求和。默认选择按名称排序后的第一个有效网卡，切换器会同时改变标签与数值。启动标识变化、网卡缺失或变化、计数器下降时，对应速率不可用。CPU 与网络数值覆盖约一秒的采样窗口；内存与磁盘是快照。

不可用值显示为 `—`，绝不显示为零。至少有一个可用资源的采集为部分成功；非 Linux 主机、没有可用资源、脚本失败或整体超时会使采集失败。认证、host-key 与配置错误属于阻塞状态，直到显式重试或编辑。采集失败会保留最后成功快照及其时间戳与错误；每日模式在时间点之间显示等待，禁用目标显示暂停。

## History

历史按实际采集时间戳绘制 24 小时与 7 天坐标。每日观测是离散点，不表示连续测量。周期曲线会在失败、暂停以及间隔超过该观测记录间隔两倍的缺口处断开，因此睡眠缺口或停止调度会如实显示而不会被连线跨过。历史会裁剪到保留窗口内。

数据库按保留设置保存样本。启动时与采集后的修剪会删除旧样本，但保留当天及已认领的未来每日时段，因此更改保留期或修剪不会让当天时段再次执行。删除目标只会移除该目标自己的样本与认领。

## Privacy and local storage

该功能把数据保存在当前 profile 的应用目录：加密的 `server_monitor.enc.json` 保存目标与设置，本地 `server_monitor.db` SQLite 数据库保存样本与每日时段认领。配置使用应用主密码加密、原子写入，并且在既有文档无法读取或解密时绝不覆盖。密码只保留在加密记录内；快照、历史、事件与日志只暴露是否已存在密码。这些文件不会加入 iCloud 或 Git 同步，凭据除目标 SSH 认证外不会发送到任何地方。

## Troubleshooting and rollback

- **配置无法读取** — 应用会报告该问题，并拒绝启动采集或覆盖文件。请自行修复或移除文件后重试。
- **认证、host-key 或配置错误** — 目标会被阻塞。请修正连接或使用显式重试/恢复；这些错误不会循环重复认证。
- **没有可用资源、脚本失败或超时** — 确认主机为 Linux、普通账户可读取 `/proc`，并且 `cat`、`sleep`、`df` 与 `uname` 可用。
- **每日时间点之间显示等待** — 有意关闭的会话不代表服务器离线；下一个未来时间点会重新连接。
- **释放会话** — 退出应用，或关闭自动采集并暂停目标；应用关闭会关闭自有会话。停止该功能/应用即可释放其会话。
- **回滚** — 回退该功能的实现会保留 `server_monitor.enc.json` 与 `server_monitor.db`；旧版本应用会忽略这两个文件。无需移除任何远端配置、服务或已安装软件。重新安装该功能会重新打开自己的目标与历史，每次采集都会获取全新的样本对。
