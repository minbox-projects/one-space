四款布局方案对比

目标：废除左侧列表 + 右侧详情的旧布局，为 Claude Profile（独立工作目录 + 独立 apiKey）设计全新界面。内容不拥挤、不隐藏信息、布局可完全替换。每款方案均为可交互原型，点击上方导航可快速跳转。

方案 A
仪表盘 + 侧滑详情面板
Dashboard + Slide-over Detail Panel

设计说明

顶部为全局统计栏（Profile 总数、活跃数、默认 Profile、可用 API Key 数），下方为 3 列卡片网格，每张卡片展示一个 Profile 的核心信息（名称、认证方式、工作目录、权限模式、默认模型）。点击卡片后，右侧滑出详情面板，展示完整配置（API Key、5 个模型路由、Reasoning Effort、MCP 配置、工具白/黑名单等），可在面板内直接编辑保存。

  • 卡片网格密度自适应：宽屏 3-4 列，中屏 2 列，窄屏 1 列
  • 详情面板宽度 420px，覆盖卡片区域但不遮挡其他 Profile 卡片
  • 面板外点击可关闭（overlay dismiss）
  • 每个卡片上有快捷操作：启动、复制命令、打开目录
优势：一眼扫到所有 Profile 概况；统计栏提供全局感知；卡片 + 面板的组合既保留概览又支持深度编辑；符合现代 SaaS 仪表盘的认知模式。
不足：详情面板会遮挡右侧部分卡片；Profile 数量很多时卡片区域需要滚动；新增 Profile 需要弹窗或行内表单。

方案 B
看板工作区
Workspace Kanban Board

设计说明

将 Claude Profile 按状态分列到看板栏目中：默认、活跃/运行中、已配置（未启动）、待完成。每列中的卡片显示 Profile 名称、认证方式、工作目录路径、Code 标签。卡片底部有快捷操作按钮（启动、编辑、复制命令）。点击"编辑"弹出行内编辑区，展开显示所有配置字段。

  • 列与列之间可拖拽卡片（调整 Profile 状态，如标记默认、停用等）
  • 每列顶部的计数 badge 实时更新
  • "待完成"列用于标记缺少 API Key 或配置不完整的 Profile
  • 顶部有导入 / 导出 / 新建操作栏
优势：状态可视化极强，一眼看出哪些 Profile 可用/在跑/待配置；拖拽交互直觉化；适合 Profile 数量较多的场景；自然区分"活跃"和"闲置"。
不足：列式布局对编辑深度配置不友好（卡片面积小）；需要弹窗或行内展开才能编辑完整字段；对于只有 2-3 个 Profile 的用户，看板显得空旷。

方案 C
全宽手风琴列表
Full-width Accordion List

设计说明

每个 Profile 占据一整行，折叠状态下展示：头像、名称、状态标签（default / OAuth / API Key）、Code、工作目录路径、权限模式、默认模型。点击展开后，在当前行下方内联展开完整的编辑表单（所有字段），无需弹窗或侧滑面板。可同时展开多个 Profile 进行对比编辑。

  • 折叠行高度固定（约 56px），信息密度高但不拥挤
  • 展开区域宽度 100%，编辑空间充足
  • 可多开对比：同时展开 2-3 个 Profile 的编辑表单
  • 行内操作按钮（启动 / 复制 / 打开目录）始终可见
  • 顶部工具栏：筛选（按认证方式 / 权限模式）、搜索、排序、新建
优势：编辑区域最大（全宽）；折叠/展开切换快速；多开对比编辑是独有优势；没有弹窗或侧滑的遮挡问题；对键盘操作友好（Tab 导航）。
不足：缺少全局统计概览；没有视觉上的"工作区"感觉；大量 Profile 时列表较长，需要搜索/筛选辅助。

方案 D
Tab 工作区
Tabbed Workspace

设计说明

每个 Claude Profile 是一个 Tab 标签，Tab 栏横向排列在页面顶部。选中某个 Tab 后，下方区域分为左右两栏：左侧为主编辑区（按区块分组：基本信息、认证、模型路由、高级配置），右侧为 Quick Info 面板（显示运行状态、会话列表、快捷操作、设备同步信息）。"+" Tab 用于新建 Profile。

  • Tab 标签上显示 Profile 名称 + 状态圆点（绿色=运行中 / 灰色=闲置）
  • 左编辑区按逻辑分组，字段排列宽松，每行最多 2 个字段
  • 右侧 Quick Info 面板展示只读信息和操作按钮
  • 所有 Profile 的配置在同一页面内切换，无需跳转或弹窗
  • 顶部可放置 CLI 版本状态栏（与旧布局保持一致）
优势：最接近传统"设置页"的认知模式；编辑区宽敞、字段分组清晰；Quick Info 面板提供运行态上下文；Tab 切换快速；适合需要频繁修改配置的场景。
不足：同时只能编辑一个 Profile，无法对比；Tab 数量过多时会拥挤（需横向滚动）；没有全局概览（需要逐个 Tab 查看）；缺乏仪表盘的全局感知。
