🏆 推荐方案

首选 A（Dashboard + 侧滑面板）：在概览性和编辑深度之间取得最佳平衡。顶部的统计栏提供全局感知（Profile 总数、运行中、默认、API Key 配置情况），卡片网格一目了然，侧滑面板提供充足编辑空间。认知模式最符合现代工具习惯，且实现复杂度可控。

备选 C（全宽手风琴列表）：如果用户更重视编辑效率而非概览，C 方案的多开对比编辑（同时展开多个 Profile 表单）是独有优势。实现最简单，改动范围最小，且对键盘导航最友好。

不推荐 B（看板）：虽然状态可视化出色，但编辑深度配置体验差（卡片面积小），且需要拖拽库或复杂交互逻辑。适合未来"Profile 管理"功能扩展时再考虑。

不推荐 D（Tab）：Tab 方案适合配置密集型工具（如 VS Code 设置），但缺乏全局概览，且 Profile 数量超过 6-8 个后 Tab 栏会拥挤。

迁移实施要点

无论选择哪个方案，以下是共性的实施步骤：

  1. 拆分单文件组件：当前 src/components/AiEnvironments/index.tsx 约 3076 行，需拆分为多个子组件（卡片、详情面板、统计栏等）
  2. 保持数据层不变：现有的 claudeProfiles、AiProvider 数据结构和 Tauri 命令调用无需修改
  3. 保留非 Claude 工具列表：Codex / Gemini / OpenCode 的 Provider 管理逻辑独立于 Claude Profile 卡片
  4. 保持 CLI 版本检测：顶部 4 列 CLI 版本卡片可以保留或移至独立页面
  5. 国际化：新增 UI 文本需在 src/i18n.ts 中添加中英文翻译
  6. 响应式适配：新布局需确保在不同窗口宽度下正常工作
