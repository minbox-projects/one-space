## 一、目标定位

OneSpace 的核心定位：

```
OneSpace = 个人知识工作者的本地智能数据中心

核心用户：程序员、内容创作者、研究者、知识密集型工作者

核心价值：
1. 找得到（语义检索）
2. 懂你（AI 带上下文）
3. 能扩展（知识库导入）
4. 省时间（自动化）
```

## 二、核心模块设计

### 1. 数据湖（Data Lake）

**目标**：统一存储所有模块数据，支持语义检索。

**架构**：
- 向量存储：LanceDB（嵌入式，随 Tauri 启动）
- 嵌入模型：通过 AI 模型中心配置 `embedding` 角色
- 支持模块：Notes、Bookmarks、Mail、Snippets 等

**核心 API**：
```typescript
interface DataLakeApi {
  semantic_search(query: string, filters?: SearchFilters): SearchResult[];
  hybrid_search(query: string): SearchResult[];
  index_document(doc: Document): void;
  reindex_module(module: string): void;
}
```

---

### 2. 知识库（Knowledge Base）

**目标**：用户主动导入的外部知识源。

**类型支持**：
- 本地文件夹导入（扫描 .md/.txt）
- Git 仓库导入（clone 后扫描）
- URL 抓取（单个页面）

**数据结构**：
```typescript
interface KnowledgeBase {
  id: string;
  name: string;
  type: "folder" | "git_repo" | "url";
  source_path: string;
  sync_interval?: number;
  chunk_strategy: "sentence" | "paragraph" | "sliding_window";
  status: {
    total_docs: number;
    total_chunks: number;
    last_sync_at: number;
    sync_status: "idle" | "syncing" | "error";
  };
}
```

---

### 3. 本体建模（Ontology）

**目标**：定义业务实体的结构化元数据，让 AI 理解用户数据。

**设计原则**：简化版，默认本体 + 用户可扩展字段，不做复杂推理引擎。

**默认实体**：
- Note（笔记）
- Bookmark（书签）
- SSHServer（SSH 服务器）
- Mail（邮件）
- Snippet（代码片段）

**数据结构**：
```typescript
interface OntologyEntity {
  id: string;
  name: string;
  attributes: OntologyAttribute[];
  relations: OntologyRelation[];
}
```

---

### 4. 工作流引擎（Workflow）

**目标**：多步骤任务编排，超越单一 Schedule。

**触发类型**：
- manual（手动触发）
- schedule（定时触发）
- event（事件触发）

**步骤类型**：
- ai_call（AI 调用）
- tool_call（工具调用）
- condition（条件分支）
- parallel（并行执行）

**数据结构**：
```typescript
interface WorkflowDefinition {
  id: string;
  name: string;
  trigger: WorkflowTrigger;
  steps: WorkflowStep[];
  output: WorkflowOutput;
}

interface WorkflowRun {
  id: string;
  workflow_id: string;
  status: "running" | "completed" | "failed" | "paused";
  step_outputs: Record<string, any>;
}
```

---

### 5. Agent 增强

**目标**：让 Agent 具备上下文感知、记忆、工具调用能力。

**新增能力**：
- memory_config：记忆存储与检索
- knowledge_bindings：绑定知识库
- ontology_context：本体上下文注入
- workflow_bindings：可触发工作流

**新增工具**：
- data_lake_search：数据湖语义搜索
- kb_search：知识库搜索
- ontology_query：本体结构查询
- workflow_trigger：触发工作流
- memory_recall：记忆检索
- memory_store：记忆存储

### 部署依赖

| 模块 | 本地化 | 外部依赖 |
|------|--------|----------|
| LLM | 云端/本地可选 | AI 模型中心配置 |
| 嵌入模型 | 云端（推荐） | AI 模型中心新增 embedding 角色 |
| 向量存储 | 完全本地 | LanceDB 嵌入式 |
| 本体建模 | 完全本地 | JSON 存储 |
| 工作流引擎 | 完全本地 | 自实现 DAG |
| Memory | 完全本地 | 共用向量存储 |
| 知识库导入 | 完全本地 | 无（URL 抓取需联网） |

**总结**：零额外部署，零额外服务，完全沿用现有架构。

## 六、应用场景详解

### 高价值场景

#### 开发者场景

1. **智能代码助手**：调试问题时 AI 搜索相关笔记 + SSH 连接查日志 + 分析定位
2. **技术债务追踪**：自动扫描 TODO/FIXME，关联已有记录，生成周报
3. **文档自动生成**：代码变更时 AI 检测 API 变动，自动更新文档

#### 内容创作场景

4. **写作助手**：搜索知识库 + 数据湖 + 书签，基于积累快速展开文章
5. **多语言内容**：产品描述一键翻译 + 多平台文案生成

#### 学习研究场景

6. **学术文献助手**：文献导入 + 关系推理（引用/反驳）+ 问答
7. **技能学习路径**：基于现有基础定制路径，全程 AI 辅助

#### 个人效率场景

8. **每日工作总结**：自动收集今日活动，生成小结
9. **会议纪要处理**：结构化提取决议、待办、责任人
10. **个人目标追踪**：日常活动自动关联目标进度

#### 信息管理场景

11. **书签智能整理**：自动分类、去重、失效检测
12. **邮件智能摘要**：AI 分类 + 摘要重要邮件
13. **信息源聚合**：RSS/GitHub Release/Newsletter 统一管理

## 七、技术选型

| 模块 | 推荐方案 | 原因 |
|------|----------|------|
| 向量数据库 | LanceDB | Rust 实现，嵌入式，与 Tauri 兼容 |
