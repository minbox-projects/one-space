# AI 路由网关账号池独立管理规格

## 问题陈述

AI 路由网关账号池当前以列表内展开行承载账号详情，与 AI 终端服务商的卡片列表和独立详情体验不一致，账号连接、认证方式和模型覆盖情况不便于扫描。API Key 账号新增也无法在一次操作中同时保存连接信息、模型映射和账号级价格，缺少跨实体原子性保证。

## 目标与成功标准

将账号池改为卡片列表和模块内 list/detail viewMode 的独立详情体验。新增 API Key 账号时，账号连接信息、模型映射和非空价格快照必须在同一 SQLite 事务中保存。

- 账号卡片主体可进入独立详情视图；新增和编辑不再使用列表内折叠详情。
- 每张卡片显示 API 地址、API Key 或 OAuth 标签及模型映射关系列表。
- API Key 新增页允许编辑模型映射以及 input、output、cache_read、cache_write 四类每百万 token美元价格。
- 默认映射为每个官方 `public_model_id` 到同名 `upstream_model_id`，且可在提交前覆盖。
- OAuth 账号详情展示已有连接、映射和价格，但映射与价格不可写。
- 既有账号更新、`mapping_save` 和 `price_save` 命令继续兼容历史调用和 API Key 编辑流程。

## 用户与用户故事

- 桌面端账号池管理员需要在列表中识别账号连接、认证方式和模型覆盖情况，并进入详情进行管理。
- 管理员需要在创建 API Key 账号时一次完成账号、模型映射与价格配置，避免出现仅部分配置已保存的账号。
- AI 路由网关前端 typed IPC 调用方需要使用稳定、显式的原子创建 DTO，同时继续可调用既有编辑接口。
- Rust/Tauri 网关账号领域层需要保证跨账号、凭据、分组、映射和价格写入的一致性，并阻止 OAuth 账号写入映射或价格。

## 功能需求

### 列表与视图

- `AiRoutingGateway` 账号列表使用独立账号卡片，保持现有账号池分组、排序、启停和删除能力。
- 卡片至少展示账号名称、认证类型标签（API Key 或 OAuth）、API 地址和模型映射关系列表。
- 点击卡片主体或编辑动作进入对应账号的独立详情视图；点击新增进入空白独立详情视图。
- 详情页提供返回和保存交互；返回及保存成功后均回到列表并刷新数据。
- 模块内部以 list/detail viewMode 管理视图，不新增 URL 路由或深链接。

### API Key 新增

- 新增表单以官方模型列表为基础，为每个官方 `public_model_id` 初始化同名且启用的 `upstream_model_id` 映射。
- 用户可修改映射的上游模型名称和启用状态。
- 用户可为每个模型填写 input、output、cache_read、cache_write 四类账号覆盖价格；价格单位为每百万 token USD。
- 提交新增时，前端只能调用新的原子创建 typed IPC facade，不得通过多个旧写入命令拼接创建流程。
- 后端在同一事务中创建账号、加密 API Key 凭据、默认分组、最终映射和全部非空价格快照。
- 未提供显式映射时，后端仍为全部官方模型生成同名映射；显式映射覆盖相应默认项。
- 显式映射不得引用未知的 `public_model_id`。

### OAuth 账号

- OAuth 账号详情展示已有连接、模型映射和价格信息。
- OAuth 账号的模型映射与价格控件为只读，不能提交映射或价格修改。
- 后端 `mapping_save` 必须拒绝 OAuth 账号写入；`price_save` 保持既有 OAuth 拒绝行为。

### 兼容接口

- 既有 `account_update` 保持其历史行为。
- 既有 `mapping_save` 和 `price_save` 对 API Key 账号编辑保持兼容。
- 新的原子创建命令仅承担 API Key 新增的组合写入，不删除或替换现有独立账号、映射或价格 IPC。

## 非功能需求

- API Key 必须继续使用现有密钥加密机制保存，前端不得回显密钥。
- 账号、凭据、默认分组、映射和价格的组合创建必须具备事务原子性；任一步骤失败均不得留下账号或凭据残留。
- 价格校验沿用现有十进制校验及历史快照语义。
- 卡片信息层级和详情页返回/保存交互应与 `ServiceProviderList`、`ServiceProviderDetail` 的既有体验一致，但不要求复用其业务组件。
- 变更限于 AI 路由网关账号池及其必要的前后端契约和测试，不修改无关模块。

## 范围

### 范围内

- `src/components/AiRoutingGateway` 的账号列表、新增和详情视图重构。
- 参考服务商卡片及 list/detail viewMode 交互的账号池专属组件。
- `src/lib/aiRoutingGateway.ts` 的原子创建 typed IPC DTO 与 facade。
- Rust command DTO、命令注册及 accounts/pricing 领域事务协作。
- API Key 新增时的批量模型映射与账号价格写入。
- OAuth 映射和价格 UI 只读，以及后端写入口的账号类型保护。
- 相关 React、TypeScript facade 与 Rust 领域测试。

### 范围外

- 改变 AI 终端服务商自身功能。
- 新增 URL 路由或深链接。
- 改变官方模型或官方价格维护方式。
- OAuth 登录或重新授权流程。
- 删除既有独立账号、映射或价格 IPC。
- 在无事实需要时新增 SQLite schema 迁移。

## 接口与数据

### 原子创建契约

新的 typed IPC 创建输入应表达 API Key 账号连接信息、可选显式模型映射和每个模型可选的四类价格。输出应遵循账号创建结果的现有返回约定，并使调用方能够刷新账号列表。

服务端收到创建请求后必须：

- 校验账号类型为 API Key 创建路径支持的类型。
- 从官方模型集合构造完整默认映射集。
- 对输入的显式映射按 `public_model_id` 覆盖默认映射，并拒绝未知官方模型标识。
- 使用现有规则校验所有提供的价格字段。
- 仅持久化非空价格字段对应的快照记录。
- 在单个 SQLite transaction 中完成全部持久化。

### 数据不变量

- 每个新建 API Key 账号在成功提交后，对所有官方模型均存在一个最终映射。
- 最终映射中的 `public_model_id` 必须属于官方模型集合。
- API Key 凭据只能以加密形式持久化，读取 DTO 不得包含可回显的明文密钥。
- 提供的价格均为有效的现有十进制格式，单位固定为每百万 token USD。
- OAuth 账号不得通过 `mapping_save` 或 `price_save` 形成新的映射或价格写入。
- 原子创建失败时，数据库中不得留下该请求产生的账号、凭据、默认分组、映射或价格记录。

## 失败模式

- 输入引用未知 `public_model_id`：拒绝整个创建请求，不写入任何数据。
- 任一价格不符合现有十进制校验：拒绝整个创建请求，不写入任何数据。
- 账号、凭据、分组、映射或价格任一持久化步骤失败：回滚整个事务并返回可识别的失败结果。
- OAuth 账号尝试保存映射：`mapping_save` 拒绝请求，前端不得提供可编辑入口。
- OAuth 账号尝试保存价格：`price_save` 延续既有拒绝行为，前端不得提供可编辑入口。
- 原子创建调用失败：详情页保留用户已输入内容以便修正或重试，列表不得显示未完整保存的账号。

## 验收标准

- 账号池列表为独立卡片，卡片可见账号名称、API Key/OAuth 标签、API 地址、模型映射关系及既有管理动作。
- 新增、卡片点击和编辑均进入独立详情视图；返回和保存成功后回到列表并刷新。
- API Key 新增页展示所有官方模型的默认同名映射，允许修改 `upstream_model_id`、启用状态和四类价格。
- API Key 新增提交仅调用新的原子创建 typed IPC。
- 成功提交在同一事务中保存账号、加密凭据、默认分组、最终映射和非空价格快照。
- 无显式映射时保存完整同名默认映射；显式映射覆盖对应默认项；未知 `public_model_id` 被拒绝。
- OAuth 详情的映射和价格不可编辑；后端拒绝 OAuth `mapping_save`，且 `price_save` 继续拒绝 OAuth。
- 既有 `account_update`、`mapping_save`、`price_save` 对 API Key 编辑的既有调用与行为保持兼容。
- React 测试覆盖列表卡片、视图切换、新增 payload 和 OAuth 只读。
- typed IPC 测试覆盖新命令名称与参数。
- Rust 测试覆盖成功提交、默认映射、价格、非法模型、非法价格和事务回滚。

## 兼容性与迁移

- 使用现有 `schema_v1` 映射表和价格表，不要求新增 schema 迁移。
- 当前迁移版本保持至 v4，除非实施阶段发现与本规格直接相关的事实性存储缺口。
- 既有账号数据和现有独立 IPC 保持可用；本变更不要求数据回填或数据迁移。
- 新增详情体验仅在 `AiRoutingGateway` 模块内部生效，不改变应用级导航契约。

## 范围外事项

- 服务商模块的视觉或业务重构。
- OAuth 的认证、登录、刷新或重新授权能力。
- 官方模型目录、官方价格规则及其管理界面。
- 对既有账号创建以外的批量导入、批量编辑或深链接能力。

## 假设

- 现有 `schema_v1` 映射表与价格表足以承载新增的原子创建数据，无需迁移。
- 账号详情是 `AiRoutingGateway` 模块内部专属视图。
- 新增表单从官方模型列表初始化同名映射；空价格按既有官方价格回退语义处理。
- OAuth 映射写入限制同时由 UI 和后端 `mapping_save` 防线落实。
- 现有 `create_api_key_account` 已具备账号、凭据、默认分组和同名映射的事务基础，可在不破坏兼容接口的前提下扩展组合创建能力。
