## Problem Statement

AI 路由网关缺少与 AI 终端服务商独立的上游 OpenAI API Key 账号管理，以及完整、安全且可审计的网关密钥管理。需要补齐账号配置、模型与价格、运行状态、密钥授权和按应用时区聚合的使用数据，同时维持 OAuth 的仅展示兼容性。

## Solution

在网关域内建立独立 SQLite 数据模型、迁移和 typed facade/IPC 边界。后端负责账号和密钥的加密存储、访问控制状态、分组即时持久化、revoke 历史及统计聚合；前端基于既有服务商卡片、详情页和运行状态模式实现账号池、账号详情、网关密钥列表与顶部状态指示。官方 OpenAI 模型与价格作为账号详情默认值，账号级覆盖单独保存。

## Goals and Success Criteria

- 管理员可新增、编辑和再次读取独立的 OpenAI API Key 账号配置，且不会影响 AI 终端服务商数据。
- 账号详情默认提供 OpenAI 官方模型、同名外部映射和官方价格，并可只覆盖当前账号的四类每百万 Token 价格。
- 网关密钥完整值仅以加密形式持久化，列表稳定脱敏，复制返回完整可用值。
- 分组变更即时保存；禁用和 revoke 删除立即影响后续可用性，同时保留审计历史。
- 列表使用应用当前时区展示今日和近 30 天请求、Token 与费用聚合；运行状态仅在网关运行时出现。

## User Stories

- 管理员创建或编辑 OpenAI API Key 账号，填写密钥、API 地址、认证方式和上游协议。
- 管理员在独立账号详情中核对模型映射、默认价格或账号级价格覆盖。
- 管理员在账号卡片上快速区分 API Key 与既有 OAuth 账号，并查看地址和模型映射。
- 管理员创建、完整复制、关联多个分组、禁用或 revoke 网关密钥，并审阅生命周期和近期使用量。

## Scope

范围包括 SQLite schema 与迁移、网关密钥的完整加密存储、独立账号 CRUD、OpenAI 模型和价格预置、账号卡片与专属详情页、顶部网关运行状态、分组权限即时更新、完整值复制、密钥状态与时区统计、禁用/revoke、typed facade/IPC 及聚焦测试。

不建立 OAuth 新建或重新授权流程，不迁移旧密钥，不增加其他上游账号类型，也不与 AI 终端服务商同步数据。

## Implementation Decisions

1. 先界定独立网关账号、模型映射、账号价格覆盖、加密网关密钥、密钥分组关联和使用记录的 SQLite schema；迁移只创建新数据结构，不读取、合并或转换 AI 终端服务商记录或旧网关密钥。
2. 将完整网关密钥使用仓库既有加密能力加密保存，并把脱敏值作为派生展示结果而非可复制来源。持久化和日志路径均不得输出完整值；复制只通过受限后端命令解密返回。
3. 按数据访问层到 typed facade/IPC 的顺序实现账号和密钥的领域操作，使前端不直接构造 SQL、密码学逻辑或统计口径。IPC 返回卡片、详情和列表所需的显式类型，并将敏感完整值限制在创建结果与复制操作的最小范围。
4. 账号 CRUD 首期仅接受 OpenAI API Key 新建和编辑字段。查询可识别并展示既有 OAuth 类型，但不暴露 OAuth 新增、授权或重新登录命令。
5. 将 OpenAI 官方模型、官方默认价格和默认同名外部映射作为详情初始化与未覆盖时的读取回退。账号价格覆盖单独按账号和模型保存，字段固定为 input、output、cache read、cache write，单位为每百万 Token。
6. 复用现有 AI 终端服务商的卡片和详情交互结构，但连接至网关账号专属 facade。卡片显示 API 地址、账号类型标签和模型映射；详情页负责连接字段、映射和价格覆盖编辑。
7. 在应用顶栏复用协议路由或 SSH 隧道的状态表达，仅根据网关实际运行状态渲染图标，停止时移除。
8. 密钥列表通过专门操作创建、脱敏读取、完整复制、分组更新、禁用和 revoke 删除。分组选择变更仅在持久化成功后提交界面状态；revoke 保留密钥和历史使用记录供审计。
9. 使用应用现有时区定义计算今日和连续近 30 天边界，在查询层聚合请求次数、Token 和费用，避免前端重新解释日期或分别计算口径。

## Implementation Changes

实施依赖顺序如下：

1. 审查现有 SQLite 迁移、加密辅助函数、密钥 revoke、使用记录、当前时区、服务商账号 facade/IPC、卡片/详情页和顶栏状态的实际边界，确认可复用行为及其网关专属隔离点。
2. 新增网关账号和网关密钥的 SQLite schema 与迁移，包含账号配置、模型映射、账号价格覆盖、加密密钥、分组关联、状态、生命周期及可关联的使用记录；定义索引以支持按密钥和时区窗口聚合。
3. 实现数据访问与领域服务：账号 CRUD、官方默认值读取与覆盖合并、密钥生成/加密/脱敏/受控解密复制、分组原子更新、禁用、revoke 和历史保留。
4. 实现网关使用统计查询，将应用时区转换为今日和近 30 天窗口后聚合请求数、Token 和费用，并在禁用或 revoke 后保持历史可查询。
5. 定义并注册 typed facade/IPC 命令、请求和响应类型，覆盖账号列表/详情/保存、密钥列表/创建/复制/分组更新/禁用/revoke 和网关运行状态；前端调用统一通过该边界。
6. 增加账号池卡片、独立账号详情页和网关密钥操作界面，复用既有交互语言，区分 OAuth 展示状态，并以服务端确认结果刷新分组、状态、时间和用量。
7. 接入顶栏网关运行状态图标，并确认其可见性与协议路由、SSH 隧道状态的一致规则。

## Public Interfaces

- 网关账号 facade/IPC：列表、详情、创建和更新 OpenAI API Key 账号；返回账号类型、API 地址、认证方式、上游协议、模型映射与有效价格视图。OAuth 仅作为可读类型返回。
- 模型与价格接口：返回官方默认模型和价格，并接受账号与模型维度的可选四字段价格覆盖，不改变默认数据或其他账号。
- 网关密钥 facade/IPC：创建返回一次完整可用值；列表只返回前后各 6 位的脱敏值、分组、创建/过期时间、状态和统计；复制接口单独返回完整值；分组、禁用和 revoke 为显式写操作。
- 运行状态接口：暴露网关实际运行状态，供顶栏决定是否显示状态图标。

## Data Flow and Failure Modes

账号保存通过 typed facade 写入网关专属表，再由详情和卡片查询读取；默认模型与价格在读取时合并，覆盖缺失时回退内置官方值。密钥创建时生成完整值、加密持久化并返回一次，后续列表仅由稳定脱敏函数生成显示值；复制请求在后端解密并失败时明确返回错误，绝不回退为脱敏值。

分组更改先写入关联表，成功后更新前端已选状态；失败则保留已持久化选择并报告失败。禁用与 revoke 均更新授权判定路径，revoke 不物理删除审计所需的密钥和使用历史。统计窗口由应用当前时区生成并在后端聚合，防止客户端本地时区导致边界不一致。网关未运行时状态接口不得使顶栏显示运行图标。

主要风险是敏感值通过响应、日志或 UI 意外泄露，迁移破坏既有数据，账号域与服务商域混用，以及时区/状态竞争造成错误的统计或权限显示。通过最小敏感响应、独立表与类型、只追加迁移、服务端时区聚合、持久化确认后更新 UI 和针对性测试降低风险。

## Testing Decisions

- 为加密存储、稳定前后各 6 位脱敏、完整值复制、复制失败、禁用/revoke 授权判定和历史保留添加后端聚焦测试。
- 为账号独立性、OpenAI API Key CRUD、OAuth 仅展示、默认模型/价格回退、账号级四字段覆盖隔离、分组即时保存及应用时区的今日/30 天聚合添加数据层和 facade/IPC 测试。
- 为账号卡片字段、详情默认值与覆盖、密钥不泄露中间值、分组保存失败状态、顶栏运行状态显隐添加前端组件或交互测试，范围限定在受影响路径。
- 使用仓库已有前端验证入口执行 `npm run test`、`npm run lint` 和 `npm run build`。对 Rust 改动，使用 `cargo test --manifest-path src-tauri/Cargo.toml` 验证相关测试与编译；只在受影响范围具备相应测试时运行。

## Rollout and Compatibility

部署时执行新增 SQLite 迁移并保留既有业务数据。旧网关密钥无需迁移或兼容，用户删除旧密钥后重新创建加密密钥。既有 OAuth 账号维持只读展示兼容性。AI 终端服务商与网关账号池始终独立，发布不引入导入、复制、同步或双向更新。

## Out of Scope

- OAuth 账号的新建、重新登录或授权。
- 账号池与 AI 终端服务商之间的数据同步、导入、复制或双向更新。
- 旧网关密钥的迁移、格式兼容或继续使用。
- OpenAI API Key 之外的新账号类型创建。
- 今日和近 30 天以外的统计周期，以及应用时区设置变更。

## Assumptions

- 现有代码存在可复用的 SQLite 迁移、加密、revoke、时区、服务商账号交互和顶栏状态模式，实施前将以仓库事实确认其具体边界。
- `src-tauri/Cargo.toml` 已声明 SQLite、加密、哈希和时区相关依赖，可优先复用而不扩展不必要依赖。
- 官方模型和价格的初始数据将作为内置默认值维护，不从其他账号复制。

## Further Notes

实施完成的验收重点是数据域隔离、完整密钥从不在常规展示或日志路径暴露、复制结果可用、分组变更持久化可见、状态与 revoke 授权一致，以及所有统计均遵循应用当前时区。任何实现发现现有加密、revoke 或时区语义与这些要求冲突时，应先保持规格定义的安全与审计行为，再在对应领域边界内解决兼容问题。
