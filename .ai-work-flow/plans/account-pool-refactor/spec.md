## 问题陈述

AI 路由网关的账号池目前以账号卡片为主，新增账号配置未能一次性持久化分组、标签和额度阈值，且缺少按分组浏览、分组管理及针对已选账号的批量操作。管理员需要在同一网关模块内高效管理上游账号、分组、模型映射和价格配置，同时保持既有账号编辑、排序和启停能力。

现状事实：

- 入口为 `src/components/AiRoutingGateway/index.tsx`；`AccountsTab` 使用 `viewMode`、`detailMode` 和 `selectedAccountId` 切换内部视图，未使用 React Router URL。
- 现有账号卡片已展示名称、认证标签、`base_url`、`model_mappings`，并支持编辑、上移、下移、启用/禁用和删除。
- `GatewayAccount` DTO 已有 `group_id`、`tags`、`base_url`、`auth_method`、`upstream_protocol`、`model_mappings`。
- 后端已有 `groups_list`、`group_create`、`group_delete`、`accounts_list`、`account_update`、`account_move`、`mapping_save`、`price_save` 等能力；分组重命名和批量命令需核对并补足。
- `src/components/AiEnvironments/ServiceProviderList.tsx`、`ServiceProviderDetail.tsx` 和 `ModelMappingTable.tsx` 是列表和详情页视觉结构参考，DTO 不兼容。
- `src/components/SshTunnels.tsx` 与 `src/components/sshTunnels/SshTunnelGroupManagerDialog.tsx` 是分组 tabs 和管理弹窗参考。

## 目标与成功标准

目标是在 AI 路由网关模块内交付可按分组管理的账号池，统一新增、编辑、映射、价格和批量维护流程。

成功标准：

1. 账号池列表采用 AI 终端服务商列表同类的纵向布局、信息层级、搜索、标签表达和空状态。
2. 新增账号在模块内全新详情视图中完成，不增加独立 URL，并一次提交完整配置。
3. 分组采用 SSH 隧道同类横向 tabs 和管理弹窗；默认分组固定首位并受保护。
4. 管理员可在当前分组中选择账号，批量禁用或二次确认后批量删除。
5. 前端和 Rust/Tauri 测试覆盖新增行为、状态变化和错误处理。

## 用户与用户故事

用户为使用桌面应用管理 AI 路由网关上游账号、分组、映射和价格配置的管理员。

- 管理员可以切换分组，只查看和搜索当前分组中的账号。
- 管理员可以建立、重命名和删除自定义分组；删除分组后其账号自动归入默认分组。
- 管理员可以进入模块内新增页，填写账号连接、认证、分组、标签、额度、备注、模型映射和价格配置后一次保存。
- 管理员可以保留对单个账号的编辑、排序、启停和删除操作。
- 管理员可以勾选当前分组中搜索结果可见的账号，批量禁用或批量删除。

## 功能需求

### 账号列表与搜索

1. 列表以纵向账号项呈现：名称、API 地址、认证方式和上游协议标签、自定义标签、模型映射标签及备注。
2. 列表保留单账号编辑、上移、下移、启用/禁用和删除操作，且现有排序与详情能力不回归。
3. 搜索仅过滤当前选中分组；空状态沿用服务商列表的同类信息层级与操作入口。
4. 只借鉴服务商组件的视觉结构和交互模式，不引入图标、历史回滚、JSON 编辑、激活或其他服务商专属数据能力。

### 模块内新增账号页

1. 点击添加账号切换至网关模块内部的独立新增视图，不创建或修改 URL 路由。
2. 新增视图采用服务商新增页的页面结构、内容分区、返回和保存语义。
3. 表单字段至少包括名称、API 地址、API Key、认证方式、上游协议、分组、标签、额度阈值、备注、模型映射和价格配置。
4. 保存必须通过一次创建请求持久化上述新增配置；成功后返回账号列表并刷新数据。
5. 返回操作不得意外保存未提交内容；保存失败时保留用户输入并展示可理解的错误状态。

### 分组 tabs 与管理

1. 分组显示在账号池顶部的横向 tabs 中，一次仅展示当前分组账号。
2. 默认分组必须固定在首位；不提供“全部账号”tab。
3. 分组管理弹窗支持新建、重命名和删除自定义分组，交互模式参考 SSH 隧道分组管理弹窗。
4. 默认分组不可重命名或删除，界面不得提供可执行的受限操作。
5. 删除自定义分组时，后端必须将该分组全部账号迁移至默认分组，再完成分组删除；成功后前端刷新分组和账号列表，并保证存在有效的当前分组。

### 批量操作

1. 每个当前分组账号项提供复选框；选择状态仅可包含当前分组账号。
2. 全选仅选择当前搜索条件下可见的账号，不选择被搜索隐藏的账号或其他分组账号。
3. 仅在存在选择时提供批量禁用和批量删除；不得提供不经选择、作用于整个分组的批量操作。
4. 批量禁用只作用于选中账号；已禁用账号包含在请求中必须按幂等成功处理，不得导致整批失败。
5. 批量删除只作用于选中账号，执行前必须二次确认并明确显示待删除账号数量。
6. 任一批量操作完成后刷新列表并清空选择状态；失败时保留选择，以便用户重试或调整。

## 非功能需求

- 仅在 AI 路由网关及相关 Tauri/Rust 持久化边界内精准修改，不重构无关模块。
- 复用项目既有 UI 组件、Tauri command、数据访问与测试模式。
- 前端状态在分组切换、搜索、保存和批量操作后保持可预测，不跨分组误操作。
- 后端批量写操作应对每个目标账号进行明确校验，并返回可供前端展示或定位失败的错误信息。

## 范围

包含账号池前端列表与模块内详情/新增视图、Tauri 命令和 Rust 持久化、分组管理、选中账号批量操作及相关测试。

不包含新增独立 URL 路由、服务商专属字段或能力、全部账号 tab、无选择的整组批量操作，以及无关模块重构。

## 接口与数据

### 现有数据契约

`GatewayAccount` 持续承载至少 `group_id`、`tags`、`base_url`、`auth_method`、`upstream_protocol` 和 `model_mappings`。列表读取须能提供渲染名称、备注、认证/协议、标签和模型映射所需数据。

### 创建契约扩展

创建账号的 Tauri/Rust 命令与持久化输入必须扩展为可一次接收并保存：名称、API 地址、API Key、认证方式、上游协议、分组、标签、额度阈值、备注、模型映射和价格配置。创建成功后返回可识别的新账号或由调用端通过刷新列表获得最终状态；不得继续依赖新增后多次补充保存来满足完整配置。

### 分组契约

分组命令需支持读取、新建、重命名和删除。重命名必须拒绝默认分组。删除自定义分组必须在同一可靠操作中将其账号迁移至默认分组，并拒绝删除默认分组。命令响应或错误必须使前端能够刷新并恢复有效分组选择。

### 批量契约

新增或补充批量禁用和批量删除命令，输入为账号 ID 集合。后端必须校验目标账号存在性及其可操作性，避免跨边界误修改。批量禁用对已禁用账号返回成功。批量删除应在成功后使目标账号不再出现在账号列表中；任一失败需返回明确错误，前端不得将失败伪装为成功。

## 失败模式

- 新增账号字段校验失败、API 地址或认证信息无效、模型映射或价格配置保存失败：停留在新增页，保留已填内容并显示失败原因。
- 分组新建或重命名冲突、默认分组受限、删除迁移失败：不更新前端本地成功状态，展示错误并重新读取必要数据。
- 当前分组被删除或刷新后不存在：切换至默认分组，清除不再有效的选择和搜索结果。
- 批量操作未选择账号：操作不可执行。
- 批量禁用或删除请求失败：展示错误、保留选择，且仅在确认成功后刷新列表和清空选择。
- 删除确认取消：不发起删除请求，保留当前选择。

## 验收标准

1. 切换分组 tab 后仅显示该组账号；默认分组固定首位，且搜索只过滤当前组。
2. 分组管理可新建、重命名和删除自定义分组；默认分组不可重命名或删除；删除后账号迁移至默认组。
3. 账号列表以服务商列表同类纵向结构展示规定字段，并保留单账号编辑、排序、启停和删除。
4. 添加账号进入模块内独立新增视图，返回语义正确；一次保存提交规定字段，成功后回列表并刷新。
5. 复选框只选择当前组账号；全选仅覆盖当前搜索结果的可见账号。
6. 批量禁用和批量删除均只作用于选中账号；删除确认包含账号数量；成功后刷新并清空选择。
7. 已禁用账号混入批量禁用请求不会使整批失败。
8. 前端测试覆盖列表数据和布局、模块内导航与保存、分组 tabs/管理以及批量选择和操作交互。
9. Rust/Tauri 测试覆盖完整创建字段持久化、分组重命名、删除分组后的账号迁移、批量禁用、批量删除及错误处理。

## 兼容性与迁移

- 保持既有网关模块内部视图状态模型，不引入 URL 迁移或 React Router 依赖。
- 既有账号和默认分组继续可读取和管理；新增字段的持久化必须兼容已有记录缺失可选值的情形。
- 删除自定义分组是数据迁移动作：账号归属迁移至默认分组，不删除账号本身。
- 对既有调用方，变更后的创建与分组命令需要保持项目既有命令调用约定，并同步更新前端调用与测试。

## 范围外事项

- AI 终端服务商的图标、历史回滚、JSON 编辑、激活及其他服务商特有能力。
- 独立账号管理 URL 或全局路由改造。
- “全部账号”分组 tab。
- 未选择账号时对整个分组执行禁用或删除。
- 与账号池目标无关的 UI、DTO 或后端架构重构。

## 假设

- 默认分组在数据层可稳定识别，且始终存在。
- 批量禁用语义为将账号设为禁用状态，对已禁用记录无副作用并视为成功。
- 批量删除仅在用户完成包含数量提示的二次确认后调用后端。
- 账号模型映射和价格配置可由创建流程接收并持久化，或在同一创建事务/请求边界内完成。
