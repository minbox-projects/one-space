## 实施方案

先收敛 Rust 数据契约，使完整创建、分组重命名和选中账号批量维护各自拥有原子且可报告错误的 Tauri 命令；再同步 TypeScript 类型和调用封装。随后将账号页状态改为以当前分组为边界，重建 tabs、搜索、纵向列表、选择及批量操作，并把创建表单独立为模块内部新增视图。最后补齐前端和 Rust 覆盖，以命令契约、状态清理和现有单账号行为为回归边界。

创建命令在同一数据库事务中写入账号、标签、模型映射及价格，并验证目标分组和阈值。分组删除继续将账号迁移至默认组后删除分组；新增重命名在数据层拒绝默认组。批量禁用和批量删除以显式账号 ID 集合为唯一作用范围：在一个事务中先校验全部目标，再执行写入；禁用对已禁用记录不报错，删除保持既有确认语义并将确认范围扩展到该集合。前端仅在收到成功结果后刷新并清理选择。

## 接口与数据流

前端加载继续以 `aiRoutingGatewayBootstrap` 获得 groups、accounts、models 和既有页面数据。账号页将 groups 按 `is_default` 固定置首，选择活动分组；可见账号由 `accounts.filter(group_id)` 后再按搜索条件派生，选择集合仅接受这些账号 ID。全选写入当前可见 ID，切换分组或搜索不将其他范围账号带入请求。

新增页提交扩展的 `ai_routing_gateway_account_create_api_key_with_configuration` 输入，包含名称、API 地址、API Key、认证方式、上游协议、分组、标签、额度阈值、备注、模型映射和价格。后端在一个事务边界内校验并写入，成功后返回账号；前端回列表并重新 bootstrap。编辑和单账号操作继续使用既有专属命令。

分组管理调用 list/create/rename/delete 命令。删除分组由后端在事务内定位默认组、迁移账号并删除目标组；前端随后刷新，若活动组不存在则切换默认组。批量禁用和删除接受显式 ID 集合，前端只从当前可见选择构造集合；删除在包含数量的确认后才请求，成功才清空选择。

## 失败处理

- 创建请求任一字段、分组、映射或价格无效时，后端回滚整个创建事务；前端停留新增页并保留表单值和错误信息。
- 分组重命名冲突、默认组受限或删除迁移失败时，不修改前端的成功状态；重新加载必要数据并显示命令错误。
- 批量命令在写入前校验所有 ID 存在且可操作；任一验证或事务失败返回明确错误，前端保留选择且不刷新为成功状态。
- 批量禁用将已禁用账号视为成功目标；批量删除仅在确认通过后执行，取消不发请求。
- 刷新后若活动分组不存在，切换默认组；选择集合与当前组/可见数据求交，删除失效选择。

## 验收标准

1. 默认分组始终位于 tabs 首位且不可重命名或删除；不存在“全部账号”tab。
2. 当前分组和搜索共同决定可见账号，搜索、全选和批量请求均不跨分组或包含隐藏账号。
3. 自定义分组可新建、重命名、删除；删除会原子迁移账号到默认组，前端恢复有效活动分组。
4. 账号以纵向服务商式信息结构显示所需字段，且单账号编辑、排序、启停和删除继续可用。
5. 新增账号在模块内部独立视图一次保存完整字段，未保存返回不写入，失败保留输入，不引入 URL 路由。
6. 批量禁用、批量删除仅对选中账号可用；删除确认展示数量；成功刷新并清空选择，失败保留选择；已禁用账号不会使禁用批次失败。
7. Rust、API 和前端测试覆盖规格中的成功与失败路径并通过既有相关回归。

## 兼容、迁移与发布

- 保持既有网关模块内部视图模型和现有账号 DTO 的兼容读取；缺失的新可选值使用既有默认/空值语义呈现。
- 不引入 React Router、独立 URL、服务商专属字段或能力、全部账号 tab，亦不增加无选择即作用整个分组的批量操作。
- 数据迁移仅为支持既有数据读取或必要约束而追加；删除分组只迁移账号归属，不删除账号数据。
- 发布前应先在含既有账号和自定义分组的数据库副本上执行迁移与分组删除验证；若出现错误，可停止发布并回退应用版本，因分组删除会迁移归属，恢复到删除前状态需依赖已验证的数据库备份而非应用代码回滚。
