# OpenCode 服务商表单紧凑布局实施计划

## 技术与代码上下文

- OpenCode 新增与编辑继续共用 `src/components/AiEnvironments/ServiceProviderDetail.tsx`。编辑路径需通过现有 `service_provider_read_opencode_config` 读取运行时 provider 配置，不能把服务商列表中的脱敏 API Key 当作真实值。
- `src/components/AiEnvironments/OpenCodeModelForm.tsx` 负责模型基础字段、成本、限制、Options 和 Variants 的动态表单及模型列表布局；配置结构、校验、解析、合并和表单/JSON 双向同步继续沿用 `opencodeModelConfig.ts` 的既有契约。
- API Key 的完整值只允许进入 OpenCode 详情页现有生命周期。服务商列表、列表接口、其他 provider 和持久化结构不扩大明文暴露范围，保存时保留脱敏占位符与 `rawJson.options.apiKey` 回填语义。
- Options 与 Variants 的折叠状态属于组件本地界面状态，数量由当前表单数据派生，不写入 OpenCode 配置，也不参与 JSON 序列化。
- 文案使用 OpenCode 区块专用翻译键提供“模型列表”，不修改其他界面复用的通用 `models` 键。

## 实施方案

1. 在 `ServiceProviderDetail` 的 OpenCode 编辑加载流程中接入现有运行时配置读取命令，按当前 provider 精确提取 `options.apiKey`，并在请求仍对应当前详情且不会覆盖用户后续输入时回填表单。读取失败、provider 缺失或 API Key 缺失时沿用现有加载错误反馈，且不以列表脱敏值兜底。
2. 将 OpenCode 详情的 API Key 控件保持为明文文本输入，在输入框右侧增加沿用现有图标体系的复制按钮。复制来源始终是表单当前值；成功后显示局部成功状态并更新无障碍标签，失败时不显示成功状态且允许重试。
3. 增加 OpenCode 模型区块专用 i18n 键及支持语言资源，并仅在 `OpenCodeModelForm` 的标题处使用该键。
4. 重排模型卡片基础字段、成本字段和限制字段为紧凑响应式网格，收紧卡片内边距、字段间距与分区间距。桌面优先并排，窄屏按语义顺序单列或降列，始终保留模型新增、删除和编辑入口。
5. 为每个模型分别维护 Options 与 Variants 的本地展开状态，初始均折叠。两个标题行独立展示名称、实时条目数、展开状态和添加入口；标题控制提供正确的可访问名称及展开属性。
6. 调整添加行为：无论区块当前是否折叠，添加 Option 或 Variant 后都展开对应区块，并让新条目立即可编辑。所有计数直接从当前模型数据计算，以覆盖表单操作和 JSON 反向同步。
7. 将 Options 内容改为紧凑行布局，保留键名、类型、值和删除操作；将 Variants 内容改为紧凑分组布局，保留名称、内部 Options 及各层新增删除操作。仅改变呈现和局部交互状态，不改变现有动态字段更新路径和配置形状。
8. 按风险分层补充测试：先覆盖运行时密钥加载与竞态保护，再覆盖复制成功/失败和可访问状态，随后覆盖专用文案、折叠、计数及动态增删，最后执行配置解析、校验、合并、JSON 同步和保存回归测试。
9. 在新增与编辑两条路径执行实际界面验收，并分别保留桌面和窄屏截图。截图检查默认卡片高度、响应式重排、控件可操作性以及文字、输入框、计数和按钮无重叠。

## 顺序执行步骤

1. 锁定现有 OpenCode 详情加载、表单状态、保存及测试入口，确认运行时读取结果与当前 provider 的匹配方式，以及已有异步请求防陈旧覆盖模式。
2. 完成编辑路径的完整 API Key 回填与失败/乱序保护，先用定向测试证明脱敏列表值不会被当作真实密钥。
3. 完成明文输入与复制交互，覆盖新增、编辑、成功、失败、清空值和无障碍标签状态。
4. 增加 OpenCode 专用“模型列表”翻译并验证通用 `models` 调用方不受影响。
5. 建立 Options/Variants 独立折叠状态、标题行、实时计数和折叠态添加后自动展开行为。
6. 分别压缩 Options 行与 Variants 分组，在每一部分完成后验证动态增删和表单/JSON 同步，再合并到模型卡片布局。
7. 重排模型基础、成本和限制字段网格，完成桌面与窄屏样式约束，确保所有操作入口在两种视口均可见可用。
8. 运行组件定向测试、配置与保存回归测试及相关完整测试集，修正只由本次改动引入的回归。
9. 启动实际界面，依次验证新增/编辑乘以桌面/窄屏的四种组合并截图；同时复查服务商列表仍为脱敏显示。

## 任务边界与依赖

1. `opencode-detail-api-key`：**OpenCode 详情密钥数据与复制交互**
   - 顺序：1
   - 概要：在共用的 OpenCode 新增与编辑详情中完成运行时 provider 配置读取、目标 provider 精确匹配和完整 API Key 安全回填，并处理读取失败、字段缺失、用户输入保护及请求乱序；同时提供明文输入、复制成功与失败状态和准确的无障碍标签。配套定向测试覆盖新增与编辑路径、完整值来源、剪贴板行为和列表脱敏安全边界，不改变列表接口、持久化结构或既有保存语义。
   - 依赖：无
   - 主要范围：`src/components/AiEnvironments/ServiceProviderDetail.tsx`；现有 ServiceProviderDetail、OpenCode 详情加载与保存相关测试；服务商列表及列表接口脱敏契约的相关回归测试。
2. `opencode-model-compact-editor`：**模型列表紧凑布局与折叠编辑**
   - 顺序：2
   - 概要：在 OpenCode 模型表单中一次性完成专用‘模型列表’文案、模型基础/成本/限制字段的响应式紧凑网格，以及 Options 和 Variants 的独立折叠、实时计数、折叠态添加后展开和紧凑编辑布局。保留全部既有字段与各层动态增删能力，并通过组件测试验证可访问状态、配置形状及表单与原始 JSON 双向同步，不触碰 API Key 数据流或配置持久化契约。
   - 依赖：无
   - 主要范围：`src/components/AiEnvironments/OpenCodeModelForm.tsx`；OpenCode 支持语言的现有翻译资源；现有 OpenCodeModelForm、动态表单与 JSON 同步相关测试。
3. `opencode-form-integrated-validation`：**综合回归与桌面窄屏验收**
   - 顺序：3
   - 概要：在密钥详情和模型表单两个工作包完成后，统一执行详情与模型定向测试、配置解析/校验/合并/保存回归和列表脱敏复查，并完成新增与编辑路径在桌面和窄屏下的实际界面截图验收。验收覆盖完整密钥与复制状态、默认折叠和展开编辑、卡片紧凑度、响应式重排及控件无重叠，仅修正本需求引入的回归。
   - 依赖：`opencode-detail-api-key`、`opencode-model-compact-editor`
   - 主要范围：现有 OpenCode 详情、模型表单、配置同步与保存回归测试；新增和编辑路径的桌面及窄屏界面验证与截图产物；前两个任务涉及文件中由综合验收发现且归属于本需求的回归修正。

以上任务文件是依赖、scope、实施与验收细节的权威来源。

## 具体改动

- `src/components/AiEnvironments/ServiceProviderDetail.tsx`
  - 在 OpenCode 编辑初始化中读取完整运行时配置并安全回填当前 provider 的 API Key。
  - 明确区分运行时完整值、列表脱敏值和用户当前输入，避免失败或迟到响应覆盖有效编辑。
  - 将 API Key 作为明文文本输入展示，并增加复制图标按钮、局部成功状态、失败恢复和无障碍标签。
- `src/components/AiEnvironments/OpenCodeModelForm.tsx`
  - 使用 OpenCode 专用标题文案。
  - 收紧模型卡片间距并将基础、成本、限制字段组织为响应式网格。
  - 增加每模型、每区块的折叠状态与派生计数，标题行承载展开控制和添加入口。
  - 分别实现 Options 紧凑行和 Variants 紧凑分组，复用既有更新、添加、删除及 JSON 同步处理函数。
- OpenCode 支持的语言资源
  - 增加语义一致的“模型列表”专用键值，不改动通用 `models` 键。
- 现有相关测试位置
  - 扩展详情组件、模型表单、配置同步及保存行为测试；仅在现有测试组织无法覆盖时新增紧邻目标模块的测试文件。

## 接口与数据流

1. 用户进入 OpenCode 编辑详情，入口继续渲染共享的 `ServiceProviderDetail`，列表数据仅用于非敏感详情初始化，脱敏 API Key 不作为最终表单密钥。
2. 详情调用 `service_provider_read_opencode_config`，从返回配置按当前 provider 定位 `options.apiKey`；仅当请求仍属于当前详情且未被更新输入取代时写入表单 API Key。
3. 用户输入、清空或获得运行时回填后，复制按钮直接读取同一表单字段并调用剪贴板 API；复制状态不进入 provider 配置。
4. 模型表单继续操作既有模型数据。Options/Variants 数量从当前集合长度派生，折叠状态只控制渲染可见性；新增、编辑、删除仍通过既有路径更新表单并同步原始 JSON。
5. 保存继续消费既有 OpenCode provider 配置形状，执行原有校验、合并、脱敏占位符保留与 `rawJson.options.apiKey` 回填，不增加持久化字段。

## 失败处理

- 运行时配置读取失败时，保留可编辑状态并使用现有错误反馈；不得回填脱敏占位符，不得静默伪造空值，也不得覆盖用户已输入内容。
- 返回配置找不到当前 provider 或 `options.apiKey` 时，不制造密钥；保存路径继续按既有缺失值规则处理。
- provider 快速切换或请求乱序时，使用现有生命周期取消、请求标识或等价保护，阻止旧响应写入新详情。
- 剪贴板写入拒绝或异常时，不切换为成功图标或成功标签，恢复可重试状态，并沿用详情页现有可感知错误方式。
- 动态条目增删后立即从最新表单数据重算计数；空集合仍保留标题行和添加入口。
- 紧凑布局不得以隐藏字段或删除按钮处理空间不足；窄屏通过网格降列、换行和稳定控件尺寸解决。

## 测试与验证

- 详情加载测试：编辑已有 provider 时使用运行时 `options.apiKey`，不使用列表脱敏值；覆盖读取失败、provider/API Key 缺失、用户输入后迟到响应及快速切换 provider。
- 复制测试：新增和编辑路径分别断言剪贴板得到表单完整值；覆盖成功状态、失败不误报、清空值、默认/成功无障碍标签和键盘激活。
- 安全边界测试：验证服务商列表及列表接口相关既有测试仍断言脱敏输出，其他 provider 数据不因详情读取而获得明文值。
- 文案测试：断言 OpenCode 区块显示专用“模型列表”，并确认通用 `models` 键内容和其他调用行为未改变。
- 折叠测试：Options 与 Variants 初始独立折叠，可分别展开/收起，`aria-expanded` 等状态准确；折叠态添加后自动展开且新增项可编辑。
- 动态表单测试：覆盖 Options 键名、类型、值和删除，Variants 名称、内部 Options 及各层增删；每步断言计数、表单数据和原始 JSON 一致。
- 回归测试：执行现有配置解析、校验、合并、表单/JSON 双向同步、脱敏占位符及保存顺序测试，不修改其既有语义。
- 视觉验收：在仓库现有桌面与窄屏基准视口检查新增、编辑两条路径，共保留四组关键截图；截图须展示完整 API Key 详情控件、默认折叠模型卡片及至少一个展开编辑状态。
- 截图判定：桌面下相关字段形成紧凑并排网格，窄屏下顺序清楚；文字不截断到不可辨识，输入框、计数、折叠按钮、添加/删除按钮不重叠且可操作，默认卡片纵向占用较现状明显降低。

## 验收标准

1. 编辑已有 OpenCode provider 时，详情 API Key 与运行时配置对应 `options.apiKey` 完全一致；读取异常或乱序不会把列表脱敏值或旧 provider 密钥写入当前表单。
2. 新增与编辑详情均明文显示表单当前 API Key；复制成功时剪贴板值完全一致并有可感知状态，失败时不误报成功，按钮具备准确的无障碍名称。
3. 服务商列表界面与后端列表接口继续保持 API Key 脱敏，完整密钥只存在于 OpenCode 详情读取权限和生命周期内。
4. OpenCode 模型区块显示专用“模型列表”，其他通用模型文案保持不变。
5. Options 与 Variants 初始折叠并显示准确数量，可独立展开和收起；折叠态添加后对应区块展开，新条目可立即编辑且计数同步。
6. Options 和 Variants 的全部既有字段与各层增删操作可用，修改结果继续与表单数据和原始 JSON 双向同步。
7. 模型基础、成本、限制字段及展开内容在桌面和窄屏均无文字、输入框或操作按钮重叠，必要操作不被隐藏，默认模型卡片明显更紧凑。
8. 新增与编辑路径均完成桌面和窄屏实际截图验收，截图覆盖默认折叠及展开编辑状态。
9. 完整密钥、复制、专用文案、折叠、计数和动态增删的自动化测试通过，既有配置解析、校验、合并、JSON 同步和保存测试无回归。

## 兼容、迁移与发布

- 不修改 OpenCode provider 或模型配置的持久化字段，无数据迁移、配置重写或后端新接口。
- 不改变服务商列表脱敏契约、通用 `models` 翻译键、其他 provider 详情及全局复制交互。
- 不引入新的运行时依赖，复用现有命令、图标、表单控件、错误反馈和测试工具。
- 发布前以定向测试、相关回归测试和四种路径/视口组合截图作为门槛；若密钥安全边界、保存语义或窄屏可操作性任一项不满足，则阻止合入。
