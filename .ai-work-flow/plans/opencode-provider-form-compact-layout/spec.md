# OpenCode 服务商表单紧凑布局与 API Key 明文复制规格

## 问题陈述

OpenCode 服务商新增与编辑共用的详情界面当前存在三类问题：编辑已有服务商时，详情数据来自已脱敏的服务商列表，无法展示运行时配置中的完整 API Key；模型区块复用通用“个模型”文案，不能准确表达该区块用途；模型卡片及其 Options、Variants 编辑区占用过多纵向空间，默认视图不利于快速浏览和连续编辑多个模型。

本次调整应在不改变服务商列表脱敏契约、不改变 OpenCode 配置解析与保存语义的前提下，让详情表单能够读取、展示并复制完整 API Key，同时重构模型卡片为紧凑、响应式且可继续完成全部既有编辑操作的布局。

## 目标与成功标准

- OpenCode 新增与编辑详情中的 API Key 始终以完整明文显示；编辑已有服务商时，其值与运行时 OpenCode 配置的 `options.apiKey` 一致。
- 用户可通过输入框右侧的复制图标按钮复制当前完整 API Key，并能感知复制成功状态。
- OpenCode 模型区块使用专用“模型列表”文案，不改变其他位置复用的通用模型文案。
- 模型卡片默认高度相较现状明显降低；Options 与 Variants 默认折叠，标题行可见条目数量和添加入口。
- 展开折叠区块后，所有既有模型字段、Option 和 Variant 的增删改能力保持可用。
- 桌面和窄屏下文字、输入框及操作按钮均不重叠，控件保持可操作。
- 现有配置解析、校验、JSON 与表单双向同步、脱敏占位符保留及保存行为不回归。

## 用户与用户故事

- 作为配置 OpenCode 服务商的用户，我希望编辑已有服务商时看到运行时配置中的完整 API Key，以便确认和复用真实凭据。
- 作为配置 OpenCode 服务商的用户，我希望一键复制当前 API Key，并明确知道复制是否成功。
- 作为维护多个 OpenCode 模型的用户，我希望默认页面更紧凑，以便快速浏览更多模型。
- 作为需要维护高级模型参数的用户，我希望按需展开 Options 与 Variants，并继续完成条目的新增、编辑和删除。
- 作为窄屏设备用户，我希望字段和操作入口按可读顺序重排，不出现遮挡或重叠。

## 功能需求

1. OpenCode 服务商新增和编辑流程继续共用 `ServiceProviderDetail` 详情界面，不拆分为两套行为不同的表单。
2. API Key 输入框必须使用明文文本显示完整值，不得截断、掩码或替换为脱敏占位符。
3. 编辑已有 OpenCode 服务商时，详情界面必须调用现有 `service_provider_read_opencode_config` 能力读取完整运行时 provider 配置，并将对应 provider 的 `options.apiKey` 同步为详情表单当前 API Key。
4. 完整运行时 API Key 的同步仅作用于 OpenCode 新增/编辑详情。服务商列表展示及后端列表接口继续返回脱敏值，不得扩大明文密钥的暴露范围。
5. 新增服务商时，API Key 输入框应允许正常输入、修改和清空，并以当前输入值作为复制来源。
6. API Key 输入框右侧必须提供复制图标按钮。激活按钮时复制输入框当前完整值，并提供可感知的成功状态；按钮必须具有描述复制动作及成功状态的无障碍标签。
7. 复制交互应沿用详情页已有的局部复制状态和图标按钮风格，不要求新增全局 `CopyButton` 抽象。
8. OpenCode 模型区块标题必须显示“模型列表”，并使用 OpenCode 区块专用翻译键，不得直接修改可能被其他界面复用的通用 `models` 键。
9. 每个模型卡片应缩小外层内边距、字段间距和分区间距，在保留清晰分组与可编辑性的同时压缩默认纵向高度。
10. 模型基础字段、成本字段与限制字段应采用紧凑的响应式网格。桌面宽度下优先并排展示相关字段，窄屏下按可读顺序重排。
11. 每个模型卡片中的 Options 与 Variants 必须改为两个独立的可折叠区块，初始状态均为折叠。
12. Options 与 Variants 的折叠标题行必须分别显示当前条目数量、展开状态和醒目的添加入口。用户可从标题行展开或折叠对应区块。
13. 从折叠状态执行添加操作时，应新增对应条目并展开该区块，使新增内容可以立即编辑。
14. Options 展开后采用紧凑行布局，保留键名、类型、值和删除操作。类型切换、值编辑及删除结果必须继续同步到模型配置。
15. Variants 展开后采用紧凑分组布局，保留 Variant 名称、内部 Options 的编辑能力，以及 Variant 和内部 Option 的新增与删除操作。
16. Options 与 Variants 的数量必须随新增、删除及 JSON 同步结果及时更新，不得显示过期计数。
17. 模型的新增、删除、基础字段编辑、成本与限制字段编辑，以及动态 Option/Variant 操作必须保持现有配置结构和校验规则。
18. 表单编辑与原始 JSON 的双向同步必须保持现有语义；从任一侧产生的有效修改均应正确反映到另一侧。
19. 保存流程必须保持现有脱敏占位符保留和从 `rawJson.options.apiKey` 回填配置的行为，不得因详情页完整密钥同步而改变其他 provider 或无关配置。
20. 测试必须覆盖编辑时完整密钥回填、新增与编辑路径的复制操作、专用标题文案、默认折叠、展开与收起、数量展示，以及 Option/Variant 的动态添加和删除。

## 非功能需求

- 安全性：完整 API Key 仅在现有 OpenCode 详情读取权限和生命周期内使用；列表接口、列表界面及无关服务商不得获得明文值。
- 可访问性：复制按钮、折叠控制、添加和删除操作应具备可识别名称；键盘用户能够触发这些操作，并能感知展开状态和复制成功状态。
- 响应式：桌面和窄屏视口均不得出现文本、表单控件或操作按钮重叠；输入控件和操作入口不得因压缩布局而不可用。
- 一致性：复用现有详情页的组件风格、图标库、交互状态和表单控件，不引入仅服务于本需求的新设计体系。
- 可维护性：专用文案与 OpenCode 区块绑定；运行时密钥同步应复用现有读取命令和数据结构，避免新增重复后端契约。
- 回归约束：配置解析、校验、合并、JSON 同步和保存顺序的现有测试应继续通过。

## 范围

- `src/components/AiEnvironments/ServiceProviderDetail.tsx` 中 OpenCode 新增/编辑详情的 API Key 展示、运行时回填和复制交互。
- `src/components/AiEnvironments/OpenCodeModelForm.tsx` 中模型列表标题、模型卡片、响应式字段网格，以及 Options/Variants 折叠编辑布局。
- OpenCode 专用翻译文案及其支持的语言资源。
- 与详情加载、运行时配置读取、动态表单操作和响应式布局相关的自动化测试及界面验证。
- 为保持既有类型、解析、校验和合并契约所必需的最小关联调整。

## 接口与数据

- 详情入口继续由 `src/components/AiEnvironments/index.tsx` 进入并渲染 `ServiceProviderDetail`。
- 编辑路径通过现有后端命令 `service_provider_read_opencode_config` 获取完整运行时 OpenCode 配置；从目标 provider 的 `options.apiKey` 读取真实密钥并同步至详情表单的 API Key 字段。
- 服务商列表接口继续对 `api_key`/`apiKey` 执行统一脱敏。详情页不得将列表中的脱敏值视为完整运行时密钥。
- 保存仍使用既有 OpenCode provider 配置结构，并保留从 `rawJson.options.apiKey` 回填及脱敏占位符处理逻辑。
- 模型配置继续遵循 `opencodeModelConfig.ts` 中现有类型、解析、校验和合并规则；本需求不新增或改名持久化字段。
- Options 数量取当前模型 Option 条目数；Variants 数量取当前模型 Variant 条目数。显示计数仅为界面派生状态，不写入配置。
- 折叠状态为界面本地状态，不写入 OpenCode 配置，也不影响 JSON 序列化结果。
- “模型列表”通过 OpenCode 区块专用 i18n 键提供；通用 `models` 键及其现有调用方保持不变。

## 失败模式

- 运行时 OpenCode 配置读取失败时，不得把列表中的脱敏占位符当作真实 API Key，也不得静默覆盖用户已经输入的值；界面按现有详情加载错误模式提供可感知反馈。
- 运行时配置中不存在目标 provider 或 `options.apiKey` 时，详情页应保持可编辑，不生成伪造密钥；保存继续遵守现有缺失值和脱敏占位符处理规则。
- 剪贴板写入失败时不得显示复制成功状态；复制按钮应恢复为可重试状态，并按现有界面错误反馈方式让用户感知失败。
- 快速切换服务商或详情加载乱序时，较早请求的结果不得覆盖当前正在编辑的 provider 数据。
- Option 或 Variant 删除后，计数、表单状态和原始 JSON 必须保持一致，不得残留不可见条目。
- 从 JSON 同步得到空集合或新增首个条目时，折叠区块必须保持可操作，且计数正确显示为 `0` 或更新后的数量。
- 窄屏布局不得通过隐藏必要字段或删除操作来避免重叠。

## 验收标准

1. 打开已有 OpenCode 服务商的编辑详情后，API Key 输入框显示的完整明文与运行时配置中该 provider 的 `options.apiKey` 完全一致，且不是列表脱敏值。
2. 在新增 OpenCode 服务商详情中输入 API Key 后，输入框显示完整当前值；点击复制图标按钮，剪贴板得到完全相同的值，并出现可感知的成功状态。
3. 在编辑详情中点击复制图标按钮，剪贴板得到运行时回填的完整 API Key；按钮具备明确的默认和成功无障碍标签。
4. 服务商列表界面和后端列表接口仍只显示或返回脱敏 API Key，不因详情功能而暴露完整密钥。
5. OpenCode 模型区块标题显示“模型列表”；其他使用通用 `models` 翻译键的界面文案不变。
6. 初次渲染模型卡片时，Options 和 Variants 均为折叠状态，标题行分别显示准确数量及添加按钮。
7. 用户能够展开和收起 Options 与 Variants；从折叠状态添加条目后，对应区块展开，计数更新，新增条目可立即编辑。
8. Options 展开后可编辑键名、类型和值并删除条目；Variants 展开后可编辑名称和内部 Options，并可新增或删除 Variant 及其内部 Option。
9. 模型基础、成本和限制字段在桌面形成紧凑网格，在窄屏按可读顺序重排；经实际界面检查不存在文字、输入框或操作按钮重叠。
10. 默认折叠视图下，每个模型卡片相较现有布局显著减少纵向占用，同时模型级新增、删除和字段编辑入口仍清晰可用。
11. 表单修改能继续同步至原始 JSON，合法 JSON 修改能继续同步回表单；既有解析、校验、合并和保存测试全部通过。
12. 自动化测试覆盖完整密钥回填、复制成功与失败状态、专用标题、折叠初始状态、展开收起、数量变化，以及 Option/Variant 的动态增删。
13. 新增与编辑两条路径均完成界面验证，并分别检查桌面和窄屏视口。

## 兼容性与迁移

- 不修改 OpenCode provider 和模型配置的持久化结构，不需要数据迁移。
- 不修改服务商列表接口的脱敏契约，不改变现有调用方对列表数据的安全预期。
- 不改写通用 `models` 翻译键，避免其他界面文案发生非预期变化。
- 保持现有保存顺序、脱敏占位符处理和 `rawJson.options.apiKey` 回填行为，已有配置无需重新保存即可继续使用。
- 布局调整应兼容当前支持的桌面与窄屏断点，并沿用仓库现有前端依赖，不因本需求引入新的运行时依赖。

## 范围外事项

- 修改所有服务商类型或全局列表的 API Key 脱敏策略。
- 为整个应用建立统一复制按钮组件或统一剪贴板服务。
- 重构 `opencodeModelConfig.ts` 的配置模型、校验规则或合并算法。
- 修改 OpenCode 之外服务商的详情表单布局或文案。
- 新增模型字段、Option 类型、Variant 语义或后端持久化字段。
- 对模型列表进行虚拟化、排序、搜索、批量编辑或拖拽重排。

## 假设

- `service_provider_read_opencode_config` 在现有权限边界内可返回目标 provider 的完整运行时 `options.apiKey`。
- OpenCode 新增与编辑入口能够可靠区分当前 provider，并可在详情生命周期内触发现有运行时配置读取。
- 仓库当前图标库包含适用的复制与折叠状态图标，且现有测试环境可模拟剪贴板 API。
- 现有模型配置类型和 JSON 同步机制已经支持本需求要求保留的全部 Option 与 Variant 操作。
