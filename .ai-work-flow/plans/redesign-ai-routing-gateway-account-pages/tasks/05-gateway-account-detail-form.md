## 预期结果
提供 API Key 新增/编辑共用的完整受控详情表单和 OAuth 只读详情视图，覆盖现有字段、连接、固定模型映射、四类价格、继承恢复、脏状态及字段错误定位。

## 实施清单
- [ ] 新建详情骨架、API Key 表单、OAuth 只读视图和固定官方模型行组件。
- [ ] API Key 表单覆盖现有账号字段、连接配置、完整明文 Key、标签、映射开关/名称及四类价格覆盖。
- [ ] 固定模型行不可新增或删除；禁用映射不清除名称或价格草稿。
- [ ] 展示官方值、覆盖值、有效值与继承状态，并支持按模型恢复官方价格，将覆盖字段设为 `null`。
- [ ] OAuth 详情只展示公开元数据、完整映射、官方/有效价格和 `-` 地址，不渲染连接、编辑或保存控件。
- [ ] 通过初始快照与受控草稿计算脏状态；保存中冻结重复提交和冲突操作。
- [ ] 实现顶部错误汇总、字段级标记及首个错误控件的滚动聚焦，不把草稿密钥拼入错误状态。
- [ ] 增加 API Key 新增/编辑、OAuth 只读、价格恢复、禁用映射保值、脏状态、保存禁用和错误聚焦测试。

## 验收标准
- [ ] API Key 新增与编辑使用同一表单，且编辑时完整明文 Key 仅存在详情 props/受控草稿中。
- [ ] 每个官方模型固定一行，包含映射状态、上游名称及输入、输出、缓存读、缓存写四类价格。
- [ ] 恢复操作只清空账号覆盖并显示官方有效值；禁用映射后名称和价格仍保留。
- [ ] OAuth 详情不能编辑或保存任何连接、映射或价格数据，也不显示 API Key。
- [ ] 修改任一可编辑字段会产生脏状态；校验错误有汇总、字段标记并聚焦首个错误。
- [ ] 保存期间不会重复提交、返回、删除或触发其他冲突操作。

- [ ] 运行相关 TypeScript 编译检查，确认详情组件使用 facade 类型且无直接 `invoke`。
