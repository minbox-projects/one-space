# 新增 MD5 加密文本工具实施计划

## Plan Metadata
- plan-id: `add-md5-encryption-tool`
- status: `ready-for-implementation`

## Problem Statement

当前应用缺少可在 More Tools 中直接使用的 MD5 文本计算工具，同时设置页内已有 MD5 实现被封装在 `SettingsView` 中，无法被其他前端功能复用，也缺少算法标准向量和设置页现有随机密码生成流程的回归覆盖。

本次需要新增独立的“MD5 加密”工具。虽然沿用产品文案中的“加密”名称，但界面必须明确说明 MD5 是不可逆哈希，不是加密算法，不适合密码存储或安全加密。工具必须严格按浏览器字符串的 UTF-8 字节计算，保留空格、制表符、换行和 Unicode 原始序列，不执行 `trim`、换行转换或 Unicode 规范化，并同时给出四种常用展示格式。

工具还必须接入 More Tools、Launcher、应用内直接导航、可见性配置和中英文 i18n，并保持既有设置页随机 MD5 密码生成契约不变。整个方案不得增加 npm 依赖、后端能力、Tauri command、网络调用或系统托盘入口。

## Solution

将 `SettingsView` 中现有 MD5 常量和算法辅助函数提取为前端共享模块 `src/lib/md5.ts`，对内导出 `md5Hex(input: string): string`。该函数把输入按 UTF-8 编码并返回固定 32 位小写十六进制摘要；若标准向量证明现有实现存在错误，则在共享实现中修正，但保持设置页消费方式和输出格式契约不变。

新增 `Md5EncryptionTool` 组件，沿用现有 More Tools 详情页的布局、Tailwind、`section` 语义、Toast、Clipboard 和 i18n 模式。组件使用受控文本输入和独立的“已提交结果”状态：输入变化不触发计算且不清除旧结果；点击“加密”时基于当时输入一次性生成并替换四项结果；点击“清空”时同时清除输入与结果并恢复输入焦点。

以统一内部工具 ID `md5-encryption` 完成 More Tools、Launcher、直接导航、展示元数据和可见性配置注册。新增可见性字段 `md5Encryption`，默认值为 `true`，并在读取旧 localStorage 配置时逐字段补全，保留用户对其他工具的显式偏好。托盘导航保持现状，不增加 MD5 专属入口。

## Goals and Success Criteria

- `md5Hex` 对空串、ASCII、中文、空格、制表符和换行标准向量均返回正确的 32 位小写 MD5；空字符串结果必须为 `d41d8cd98f00b204e9800998ecf8427e`。
- 任意浏览器字符串均按 UTF-8 原样计算，不裁剪首尾空白、不改写换行、不做 Unicode 规范化。
- 一次计算同时展示 32 位小写、32 位大写、16 位小写、16 位大写；16 位值严格取 32 位小写结果索引 `[8, 24)`，大写值仅由对应小写值转换得到。
- 未计算状态与“已计算空字符串”状态可区分；未计算时无可复制空值，空字符串计算后可正常展示并复制其摘要。
- 输入变化只更新输入并保留旧结果；再次点击“加密”后四项结果在同一次状态提交中整体替换，不出现新旧结果混合。
- 四个结果各有独立 Lucide 复制图标按钮和明确的可访问名称；复制成功和失败均显示对应 Toast，复制失败不清除输入、结果或其他界面状态。
- “清空”同时清除输入和全部结果，并在操作完成后将焦点恢复到输入控件。
- 四个结果行尺寸稳定，在窄屏、长文本场景和中英文界面中不溢出、不重叠，图标按钮保持可操作。
- 工具可从 More Tools 卡片、Launcher 快捷工具和应用内 `md5-encryption` 导航别名进入，并复用现有 More Tools 详情返回流程。
- 旧可见性配置缺少 `md5Encryption` 时按 `true` 补全，其他已有显式布尔偏好保持不变。
- 设置页 `generateRandomMd5String` 继续使用 `crypto.randomUUID`、`Date.now` 和两次 `Math.random` 组成随机种子，继续输出 UUID 分段格式并按现有流程填充设置页字段。
- 中英文均具备标题、描述、安全说明、输入标签、操作按钮、四种结果标签、空状态及复制成功/失败反馈，且 key 命名稳定并遵循现有 i18n 结构。
- 相关 Vitest、全量 `npm run test`、`npm run lint` 和 `npm run build` 全部通过；开发环境中的桌面与窄屏截图验收覆盖规定状态。

## User Stories

- 作为普通用户，我可以粘贴或输入任意文本并显式点击“加密”，获得四种 MD5 展示格式。
- 作为需要精确摘要的用户，我输入的空格、制表符、换行和中文会按原始 UTF-8 内容计算，不会被界面静默修改。
- 作为反复比较输入的用户，我修改文本时仍可查看上一次结果，直到主动重新计算。
- 作为键盘或辅助技术用户，我可以识别并操作每一个复制按钮，获知复制成功或失败，并在清空后继续从输入框操作。
- 作为安全意识不足的用户，我能在工具内看到 MD5 不可逆且不适合密码存储或安全加密的明确提示。
- 作为 Launcher 用户，我可以按现有偏好控制 MD5 工具是否显示；升级后即使旧配置没有该字段，也能默认看到该工具且不会丢失其他偏好。
- 作为设置页用户，我升级后仍能按原有流程生成并填充 UUID 分段格式的随机 MD5 密码。

## Implementation Decisions

- 共享模块固定为 `src/lib/md5.ts`，内部保留从 `SettingsView` 提取的 `MD5_SHIFT_AMOUNTS`、`MD5_K`、`leftRotate`、`toHexLE` 等实现细节，仅公开 `md5Hex(input: string): string`，避免扩大可依赖表面。
- UTF-8 转换使用浏览器和当前测试环境已有的标准编码能力，算法在前端同步执行；不使用 Web Crypto MD5、npm 包、Rust/Tauri command、网络服务或异步后端通道。
- 结果状态使用可辨别的未生成值，例如 `null`，而不是用空字符串表示未计算；一次计算构造包含四项值的完整结果对象并单次更新。
- 32 位小写是唯一基础摘要；32 位大写由其 `toUpperCase()` 得到，16 位小写由 `lower32.slice(8, 24)` 得到，16 位大写再由 16 位小写转换，防止四种格式各自计算造成偏差。
- 输入为受控普通文本输入区域，不进行预处理。输入状态和结果状态彼此独立，因此允许输入暂时与旧结果不对应，这是已确认的产品行为。
- 复制按钮使用项目现有 Lucide 图标和 Clipboard 封装，每项传入自己的结果值；按钮在无结果时禁用或不呈现可执行复制行为，并提供与结果类型对应的 `aria-label`。
- 清空处理先同步重置输入和结果，再通过保存的输入引用恢复焦点；复制失败只触发失败 Toast，不修改业务状态。
- 结果区域采用稳定的行高、明确的弹性收缩边界和可换行或横向容纳摘要的文本策略，复制按钮使用固定尺寸且不被压缩，确保窄屏不产生页面级横向溢出。
- 内部规范 ID 固定为 `md5-encryption`，Launcher 可见性字段固定为 `md5Encryption`。所有注册点复用该 ID，不派生第二套别名或字段名。
- 展示图标从现有 Lucide 集合选择语义一致的哈希/二进制类图标，颜色从 `moreToolPresentation` 现有可用色系中分配，保持当前工具卡片风格，不新增设计系统能力。
- i18n key 归入现有 More Tools 稳定命名层级，以 `md5Encryption` 作为功能段名；英文与中文同批增加，组件内不写硬编码可见文案。
- `generateRandomMd5String` 只改为导入共享 `md5Hex`，其随机种子组成、调用次数、UUID 分段和字段填充流程均不重写。
- 不注册系统托盘菜单项，不修改 `src-tauri/src/app_runtime/shortcuts_tray.rs`；托盘仍只导航到既有主入口。

## Public Interfaces

本次没有外部公共 API 变化。新增或变化的接口仅限应用内部：

- 内部 TypeScript 函数：`md5Hex(input: string): string`，输入 JavaScript 字符串，按 UTF-8 原样计算，输出固定 32 位小写十六进制 MD5。

## Data Flow and Failure Modes

1. 用户输入只写入组件的 `input` 状态，不触发摘要计算，也不修改当前 `results`。
2. 用户点击“加密”后，事件处理器读取该时刻完整输入，调用一次 `md5Hex` 得到 32 位小写值，派生其余三项，并以一个完整对象单次替换 `results`。
3. 渲染层根据 `results === null` 展示未生成空状态；一旦存在结果对象，即使原输入为空字符串，也展示四项有效摘要。
4. 用户点击某一复制按钮时，只把该行值交给现有 Clipboard 能力。成功显示成功 Toast；Promise 拒绝、权限拒绝或 Clipboard 不可用时显示失败 Toast，输入与四项结果保持不变。
5. 用户点击“清空”后，输入和结果一并重置，随后输入控件获得焦点；清空不写入剪贴板，也不触发重新计算。
6. 导航入口统一解析 `md5-encryption`，由 App 进入 More Tools 详情分发；返回操作沿既有详情返回路径回到 More Tools 上下文。
7. Launcher 可见性读取以当前默认值为基底逐字段吸收旧配置。配置不存在、JSON 无效或新字段缺失时，MD5 使用默认可见；其他可识别的显式偏好继续保留并由现有错误处理策略处理损坏数据。

算法为同步纯函数，正常文本输入不引入网络、权限或运行时失败分支。超大文本可能占用主线程计算时间，但本工具范围仅为普通文本，不为文件或流式大数据增加并发、分块或后台任务。Clipboard 失败是预期可恢复错误，必须通过 Toast 明示且不得丢失状态。

## Testing Decisions

- **共享算法单元测试**：覆盖空串、`a`、`abc`、中文、仅空格、制表符和换行的固定标准向量；额外断言输出始终为 32 位小写十六进制。空格、制表符、LF 以及包含 CRLF 的用例分别构造，证明无裁剪和无换行改写；包含可规范化 Unicode 序列的用例证明不做 Unicode 规范化。
- **设置页回归测试**：对 `crypto.randomUUID`、`Date.now` 和两次 `Math.random` 提供确定性桩，断言各随机源仍参与种子且调用约束不变；断言生成值符合 UUID 的 `8-4-4-4-12` 十六进制分段格式，并验证现有设置页字段填充流程得到该值。该覆盖用于补足现有 SettingsView 测试未覆盖 MD5 的缺口。
- **工具组件测试**：断言输入不会自动计算，点击后一次出现四项；验证 `[8, 24)` 截取和大小写派生；修改输入时旧结果保留，再次点击后四项同步替换；覆盖空字符串、首尾空白、空格、制表符、换行、中文 UTF-8 及不规范化序列。
- **复制与失败测试**：分别触发四项复制并断言传入各自准确值、成功 Toast 和可访问名称；对每项覆盖或参数化 Clipboard 拒绝，断言失败 Toast 出现且输入、结果和其他按钮状态不丢失；未生成时断言复制按钮不可执行空值复制。
- **清空与可访问性测试**：断言清空同步移除输入和全部结果并恢复输入焦点；检查输入标签关联、`section` 语义、四个图标按钮的可访问名称、禁用状态和键盘可达性。
- **More Tools 测试**：断言 Hub 显示 MD5 卡片，选择后分发正确详情；当 `md5Encryption` 为 `false` 时按现有规则隐藏相应入口，为 `true` 时显示。
- **导航测试**：覆盖 App 与 Launcher 通过统一 ID 进入详情、应用内直接导航别名、详情返回 More Tools 的流程，并确认不存在托盘专属行为断言或改动需求。
- **持久化兼容测试**：用缺少 `md5Encryption` 的旧 localStorage 对象验证其补全为 `true`；同时设置其他工具为显式 `true`/`false`，断言升级读取后这些偏好保持；沿用现有策略覆盖空配置和损坏配置。
- **i18n 与布局静态检查**：测试中确认英文和中文关键文案 key 均可解析，四种结果标签不依赖硬编码文本；对结果容器和按钮的关键响应式类进行必要断言，但不以类名断言替代实际视觉验收。

验收命令按以下顺序执行：

1. 使用仓库现有 Vitest 调用方式运行本次涉及的算法、SettingsView、Md5EncryptionTool、MoreToolsHub、Launcher、App、导航与可见性相关测试文件。
2. 运行 `npm run test`。
3. 运行 `npm run lint`。
4. 运行 `npm run build`。
5. 运行 `npm run dev` 启动前端；需要验证桌面壳集成时运行仓库现有 Tauri 开发脚本启动开发环境。分别在桌面宽度和窄屏宽度检查并保存截图，覆盖初始空状态、四项结果、四个图标按钮、长输入、空白输入、清空后焦点以及中英文界面，确认无重叠、裁切或页面级横向溢出。

仓库没有既有 Playwright、Cypress 或截图 harness，因此截图检查属于明确的实施验收步骤，不声称新增自动化截图能力。若实施时使用浏览器自动化，必须先取得当次运行时授权，并优先采用获准的无头方式；未获授权时使用开发环境进行人工截图验收并记录结果。

## Rollout and Compatibility

功能随现有前端/Tauri 应用版本发布，无服务端部署、数据迁移、feature flag、新依赖、新权限或协议协商。共享 MD5 模块是纯前端内部代码，设置页和新工具随同一构建产物发布。

旧版本 Launcher 可见性 localStorage 对象不包含 `md5Encryption`，新版本读取时以默认 `true` 补齐，并保留其他字段的显式偏好；新字段不会改变既有工具行为。导航新增别名只扩展内部解析能力，不改变现有别名和托盘主入口。

如需回滚，可移除 MD5 工具组件、More Tools/Launcher/导航/展示注册、可见性字段和新增 i18n 文案；设置页可以继续使用已验证的共享 `md5Hex`。只有在共享提取本身造成设置页回归时，才进一步把实现回退到设置页，同时保持原随机种子和 UUID 分段契约。回滚不涉及服务端、数据迁移或用户内容恢复。

## Out of Scope

- 文件哈希、文件拖放、目录处理和流式大文件计算。
- 批量计算、导入导出、结果历史或持久化。
- SHA 系列、HMAC 或其他摘要算法。
- MD5 解密、彩虹表查询、碰撞利用或密码破解。
- 密码存储、安全签名或任何把 MD5 描述为安全加密的能力。
- 与本功能无关的设置页、导航、状态管理或前端框架重构。
- 独立系统托盘入口及 `src-tauri/src/app_runtime/shortcuts_tray.rs` 修改。

## Assumptions

- “16 位 MD5”固定定义为 32 位小写摘要索引 `[8, 24)` 的 16 个字符，不提供其他截取规则。
- 输入变化后可以暂时与屏幕上的旧结果不对应，只有再次点击“加密”才更新结果；无需增加“结果已过期”提示。
- 输入范围为浏览器中的普通文本字符串，不包括文件、二进制缓冲区或流。
- JavaScript 字符串按标准 UTF-8 编码能力转换；不执行 `trim`、换行标准化或 Unicode 规范化。
- 若标准向量暴露现有 MD5 算法缺陷，实施者应修正共享实现并用测试锁定正确行为，但不得擅自引入依赖，也不得改变设置页 32 位小写摘要到 UUID 分段输出的契约。
- `md5-encryption` 是所有导航、详情分发和展示注册点的唯一工具 ID，`md5Encryption` 是唯一 Launcher 可见性字段。
- 项目现有 Toast、Clipboard、Lucide、i18n、More Tools 和导航基础设施足以承载本功能，不需要新增全局框架能力。

## Further Notes

界面名称沿用需求中的“MD5 加密”以便用户发现，但描述和安全说明必须避免误导：明确 MD5 是不可逆哈希，不能用于密码存储或安全加密。测试和实现命名可使用 `md5`、`hash` 或现有产品命名，但不得在安全语义上声称可解密或具备密码学安全性。

实施应严格遵循阶段依赖：先以标准向量稳定共享算法与设置页兼容性，再实现组件行为，随后注册导航和可见性，最后补齐跨入口回归、索引与视觉验收。任何视觉自动化仅在运行时明确授权后执行；无授权不影响通过人工桌面与窄屏截图完成验收。
