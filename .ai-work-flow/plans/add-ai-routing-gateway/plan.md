# 新增 AI 路由网关

## Plan Metadata

- plan-id: `add-ai-routing-gateway`
- status: `ready-for-implementation`

## Problem Statement

当前 OneSpace 只有面向既有场景的 Protocol Router，缺少一个能够向 Codex、OpenCode 等客户端提供 OpenAI-compatible 本地接口的独立 AI 路由网关。Protocol Router 的配置模型、内部状态、监听器、命令命名空间和统计口径均不适合承载新的账号池、网关密钥、模型授权、额度感知路由和双协议转换需求；直接扩展或重命名该模块会引入状态耦合、兼容风险及迁移歧义。

现有应用数据分散在 JSON/app_store 和各模块自己的持久化边界中，尚无供未来子系统共享的 SQLite bootstrap、连接和事务迁移机制。若继续为新网关创建孤立存储，将无法稳定支持账号、分组、标签、加密凭据、模型映射、动态额度窗口、请求尝试、长期聚合及价格快照之间的关系，也会增加后续共享数据库迁移冲突的概率。

产品层面还缺少以下闭环能力：

- 管理 ChatGPT OAuth 与第三方 API Key 两类上游账号，并根据显式排序、模型映射、健康状态和额度窗口选择账号。
- 通过受控的官方 Codex OAuth 兼容流程登录、刷新令牌、去重账号，并在不抓取网页或导入 Cookie 的前提下获取额度。
- 为本机客户端签发不可反查、可授权和可撤销的网关 API Key。
- 同时提供 Responses 与 Chat Completions 协议，并在协议不一致时进行可验证的双向转换。
- 在不记录提示词、正文或敏感凭据的前提下，保留请求与尝试级日志，生成 Token、费用和额度趋势。
- 在应用启动、Keychain、数据库、端口冲突、流式中断和上游故障等条件下提供明确且可恢复的行为。

## Solution

新增与 Protocol Router 完全并存的“AI 路由网关”模块。前端在主侧边栏提供独立入口，模块内固定包含“首页、账号池、网关密钥、请求日志、设置”五个页签，账号详情负责额度窗口与模型映射编辑。后端在 `src-tauri/src/ai_routing_gateway/` 建立独立的命令、存储、运行时、OAuth、路由、协议、额度、价格、类型和测试边界，不引用 `protocol_router` 的内部状态、监听器、配置类型或命令命名空间。

网关作为 OneSpace 后台进程中的独立本地服务运行，默认监听 `127.0.0.1:17688`，只接受 loopback 连接。它使用网关 API Key 鉴权，按 Key 的分组和公开模型权限筛选账号，再结合启用状态、凭据、映射、健康、额度阈值及用户排序选择上游。网关对外实现 OpenAI-compatible Responses、Chat Completions 和 Models 接口；请求与上游协议不一致时执行严格双向转换，不能无损表达的字段以稳定机器码返回 `400`，不静默丢弃。

在 `~/.config/onespace/data/onespace.sqlite3` 建立全应用未来共享的 SQLite bootstrap、连接和迁移边界，本次仅创建 `ai_gateway_` 前缀的数据结构及全局 `app_schema_migrations`。敏感凭据逐记录使用 AES-256-GCM 加密，根数据加密密钥通过与当前 Rust/Tauri 工具链兼容的 `keyring` 接入 macOS Keychain，不复用 `.local_key`。请求完成后写入脱敏日志、尝试记录和本机时区每日聚合，并按请求发生时的价格快照固化预估费用。

## Goals and Success Criteria

1. 独立模块边界可验证：主侧边栏可进入 AI 路由网关五页签；Protocol Router 的名称、入口、配置、统计和运行行为不变；新代码不接入其状态、监听器、类型或命令空间。
2. 本地服务生命周期可验证：数据库和 Keychain 就绪时，应用后台进程自动启动网关并默认绑定 `127.0.0.1:17688`；端口修改先检查占用并受控重启；端口冲突、数据库失败或 Keychain 锁定时服务保持停止、展示稳定错误且不循环抢占；完全退出时停止接收新请求、完成在途日志写入后退出。
3. HTTP 契约可验证：`POST /v1/responses`、`POST /v1/chat/completions` 和 `GET /v1/models` 必须通过有效网关 Key 鉴权，`GET /health` 无需鉴权且只返回状态与版本；错误均使用 OpenAI-compatible envelope、稳定机器错误码且不泄露账号信息。
4. 协议能力可验证：流式与非流式、工具调用、reasoning 参数与推理强度、用量和结束原因在同协议透传及 Responses 与 Chat Completions 双向转换中均有测试；无法无损转换的输入明确返回 `400`。
5. 账号池规则可验证：支持 OAuth 与第三方 API Key 账号、单分组、多标签、组和账号排序、备注、启停、健康状态；默认分组不可删除，删除非空组会将账号移入默认组；标签不参与路由，Key 只绑定组；删除账号永久移除凭据、额度快照和映射但保留带账号快照的历史日志。
6. OAuth 安全流程可验证：只使用受控的 OpenAI 官方 Codex 登录兼容端点、PKCE、固定 scope 和官方刷新语义；loopback 与手动完整回调 URL 均校验 state；Device Code 严格处理轮询间隔、pending、slow_down 和 expired；临时授权材料不持久化且失败后清理；稳定账号 ID 再授权只更新凭据。
7. 额度路由可验证：OAuth 账号支持动态全局、模型、端点和能力窗口；标准基础窗口、附加窗口和未知窗口按确定规则影响候选；全局阈值默认 `10%` 且账号可继承或覆盖；阈值修改立即重算但不终止在途请求；过期快照只降级、不直接停用。
8. 路由与恢复可验证：候选过滤和排序完全遵循授权、映射、健康、适用额度、用户排序、最低剩余比例和最近使用规则；每请求最多尝试三个账号；只有尚未向客户端输出时允许切换；`401/403`、明确耗尽、`429`、网络错误及 `5xx` 分别触发规定的刷新、暂停、冷却或熔断行为。
9. 密钥与数据安全可验证：网关 Key 明文只在创建时返回一次，数据库只保存加盐哈希或等效验证材料；OAuth token 和第三方 API Key 以带随机 nonce、版本和 AAD 的 AES-256-GCM 记录密文保存；Keychain 项丢失不会生成新根密钥覆盖旧密文；日志中不存在请求/响应正文、提示词、工具参数、Authorization、Cookie、Token 或 API Key 明文。
10. 存储可靠性可验证：共享数据库启用 WAL、foreign keys 和 busy timeout；迁移由 `app_schema_migrations` 的 subsystem 与 version 在事务中管理；首建、升级、失败回滚和并发初始化测试通过，不以单一 `PRAGMA user_version` 作为唯一迁移标识，也不修改其他数据源。
11. 日志统计可验证：每个逻辑请求和每次账号尝试均有结构化记录；默认明细保留 90 天且支持 7/30/90/180 天或永久；每日聚合按本机时区实时增量更新、缺日补零，并可重建和校验；价格或用量缺失时费用为不可计算而不是 `0`。
12. 首页数据可验证：首页完整展示账号数量、可用与不可用进度、5 小时/7 日及附加窗口、今日 Token 分项、K/M 格式总量、预估美元费用和 7/15/30 日趋势；趋势支持账号、分组和公开模型筛选，Token 与费用使用独立视图且不使用双 Y 轴。
13. 工程门禁可验证：TypeScript 检查、ESLint、Vitest/Testing Library、Rust 单元与 loopback 集成测试、`cargo test`、`cargo check` 和项目构建类检查通过；测试不依赖公网，不把 Playwright、可见浏览器或未授权 E2E 作为本次必做验收。

## User Stories

- 作为 OneSpace 用户，我可以从主侧边栏进入独立 AI 路由网关，并在固定五页签内完成监控和管理，而不会影响 Protocol Router。
- 作为账号管理员，我可以通过系统浏览器 loopback、手动粘贴完整回调 URL 或 Device Code 登录官方 Codex 兼容 OAuth，并在同一账号再授权时更新凭据而不产生重复账号。
- 作为账号管理员，我可以录入第三方 Base URL、API Key、鉴权方式、上游协议和明确的公开模型映射，未映射模型不会被透传。
- 作为账号管理员，我可以维护分组、标签、账号排序、备注、启用状态、额度阈值和模型映射，并依赖确定的删除及默认分组规则保护日常运维。
- 作为本机 API 客户端使用者，我可以持有权限受限的网关 Key，通过 Responses 或 Chat Completions 端点发起流式、非流式、工具调用和 reasoning 请求。
- 作为安全管理员，我可以创建、重新生成、禁用和撤销网关 Key；明文只显示一次，立即失效行为不会依赖服务重启。
- 作为运维用户，我可以看到账号健康、动态额度、冷却和熔断状态，并理解为什么当前没有候选或服务未启动。
- 作为成本观察者，我可以按 7/15/30 日、账号、分组和公开模型查看 Token 与独立费用趋势，并确认费用是基于请求时价格快照的等效预估。
- 作为审计用户，我可以筛选和分页查看脱敏的逻辑请求及账号尝试，手动清空日志或设置保留期限，同时在账号删除后继续读取账号名称和标识快照。

## Scope

本计划包含：

- 新增独立导航入口、模块壳、五个固定页签、账号详情、加载/空/错误/锁定状态以及中英文 i18n 文案。
- 新增共享 SQLite bootstrap、连接池或受控连接、事务迁移协调器及本次网关 schema。
- 新增 macOS Keychain 根密钥管理、AES-256-GCM 逐记录凭据加解密和不可反查的网关 Key 验证材料。
- 新增 OAuth 浏览器 loopback、手动完整回调、Device Code、刷新、账号去重及临时会话清理。
- 新增账号、分组、标签、模型目录、账号模型映射、动态额度窗口、阈值、健康和排序管理。
- 新增 loopback HTTP 服务、四个端点、Bearer 鉴权、Key 权限、协议转换、流式转发、候选路由、失败切换、冷却和熔断。
- 新增请求与尝试日志、保留和清理、模型价格、费用快照、每日聚合、趋势查询及聚合维护路径。
- 新增 Tauri invoke/event 接口、运行时启动停止接线及覆盖关键规则的 Rust 和前端测试。

## Implementation Decisions

### 模块隔离与前端状态

- 决定新增 AI 路由网关，与 Protocol Router 并存。理由是两者的协议目标、配置生命周期、账号模型和统计口径不同。明确不采用重命名、合并或迁移 Protocol Router 的方案，也不复用其内部状态、监听器、配置类型或命令命名空间。
- 决定使用现有 React、Tailwind、Radix、Lucide、i18next 和测试惯例，以页面级查询状态、组件局部状态及 typed invoke facade 管理数据。不引入全局状态库，避免为单一模块扩大应用级依赖和状态耦合。
- 决定主侧边栏提供独立入口，模块内部固定五页签；额度窗口与模型映射位于账号详情，避免再增加顶层页签。

### 账号、分组与模型

- 决定每个账号只属于一个分组、可拥有多个标签。分组和账号都可排序，账号排序是路由首要优先级；标签仅用于识别和筛选，不参与路由，网关 Key 绑定分组而不绑定标签。
- 决定创建不可删除的默认分组。删除非空分组时在同一事务中将账号迁入默认分组。新 OAuth 或第三方账号都进入默认分组。
- 决定常规退出路由使用禁用状态。永久删除账号必须二次确认，并删除凭据、额度快照和模型映射；请求日志与每日聚合不级联删除，依靠已固化的账号名称和稳定标识快照继续展示。
- 决定维护统一公开模型目录和每账号独立映射。OAuth 账号从官方模型目录生成默认映射并允许逐项禁用；第三方账号手动维护“公开模型 -> 上游模型”映射。未映射模型不得透传。`/v1/models` 只返回当前 Key 已授权且至少有一个可路由账号支持的公开模型。
- 决定第三方账号显式保存 Base URL、加密 API Key、鉴权方式和上游协议类型；上游协议只允许 OpenAI-compatible Responses 或 Chat Completions。

### OAuth 与额度来源

- 决定只实现 OpenAI 官方 Codex 登录兼容流程，使用受控授权端点、PKCE、固定 scope 和官方 token 刷新语义。明确不开放自定义 issuer、client ID 或 scope，不导入 Cookie，不抓取网页；若官方政策或流程不允许第三方桌面客户端接入，该能力和整体发布被阻塞，不以 Cookie 模拟绕过。
- 决定浏览器授权使用本机 loopback 回调并打开系统默认浏览器，同时保留手动粘贴完整回调 URL。两条路径使用同一内存授权会话并校验 state、解析 code/error；自动回调失败不会使会话失效。
- 决定 Device Code 按服务端返回的间隔轮询，`slow_down` 时增加间隔，并显式处理 pending、expired、取消和成功状态。UI 展示代码、验证地址和过期倒计时，并提供复制、打开和取消动作。
- 决定以官方返回的稳定账号 ID 去重；再授权原子替换该账号凭据和元数据，不新建账号。授权 code、device code、PKCE verifier 和 state 只存在内存，完成、失败、取消或过期时清理。
- 决定额度只适用于 OAuth 账号，来源仅为 OAuth 可访问的额度接口和上游响应中的限额元数据，不解析 `chatgpt.com` 网页。登录后、手动操作、请求完成后和后台默认每 5 分钟触发刷新；同账号并发刷新合并，失败采用有上限的指数退避。

### 动态额度与可用性

- 决定持久化动态额度窗口的名称、上游标识、剩余和已用百分比、重置时间、时长及适用范围。范围是全局、模型、端点或能力，可表达标准 5 小时与 7 日窗口、仅 7 日账号、Code Review、Spark 和未知窗口。
- 决定任一适用的标准基础窗口耗尽时暂停普通请求；附加窗口只限制对应能力；未知窗口有明确适用范围时执行相同门禁，无范围时仅展示。
- 决定全局最低剩余额度阈值默认为 `10%`，允许 `0-100`，其中 `0` 只在完全耗尽时停用。账号保存“继承全局”或具体覆盖值。当前请求适用窗口任一低于阈值时，该账号仅对该请求暂时不可用；达到或高于阈值自动恢复。
- 决定额度刷新失败保留最后成功快照并标记过期。过期本身不触发阈值停用，但在候选排序中降级。修改全局或账号阈值后立即重算后续请求，不终止在途请求。
- 决定首页 5 小时和 7 日百分比只对拥有对应窗口且当前可参与路由的 OAuth 账号做算术平均；缺窗口账号不进入分母，仅 7 日账号只参与 7 日统计，第三方账号只参与账号数量统计。附加窗口按规范化名称分别聚合，不混为一个比例。

### 网关、鉴权与协议

- 决定网关仅绑定 IPv4 loopback `127.0.0.1`，默认端口 `17688`，不接受 LAN 或 public 地址。保存端口前检测占用；运行中变更执行停止接入、等待受控排空、重新绑定的受控重启。
- 决定网关随 OneSpace 后台进程自动启动。数据库、Keychain 或端口任一未就绪时保持停止并向前端发布明确状态，不循环抢占端口。完全退出时先停止新连接，再等待在途请求和日志提交完成，最后关闭数据库资源。
- 决定对 Responses、Chat Completions 和 Models 强制网关 Key 鉴权，至少接受 `Authorization: Bearer <key>`；Health 无需鉴权且只泄露状态和版本。所有外部错误使用 OpenAI-compatible envelope 与稳定机器码，不返回账号名称、上游凭据或内部堆栈。
- 决定客户端协议与账号上游协议一致时进行受控透传；不一致时转换请求、非流式响应、SSE 流事件、工具调用、reasoning/推理强度、用量、结束原因和错误。协议能力矩阵中不能无损表达的字段在请求上游前返回 `400`，明确不采用静默删除字段或猜测语义。

### 网关 Key 与路由

- 决定支持多个网关 Key，每个 Key 有名称、可见前缀、创建时间、最后使用时间、启用状态、失效时间、一个或多个分组授权和公开模型授权。
- 决定使用密码学安全随机源生成高熵 Key。明文只在创建或重新生成成功响应中展示一次；数据库只保存唯一内部 ID、可见前缀、加盐哈希或等效验证材料。重新生成原子撤销旧材料，禁用、撤销和过期立即影响新请求；日志只保存 Key 内部 ID与名称快照。
- 决定候选依次过滤 Key 的分组和模型授权、账号启用状态、凭据有效性、公开模型映射、健康状态及当前请求适用额度窗口。过滤后先按账号用户排序升序；排序值相同则按适用窗口最低剩余百分比降序，再按最近使用时间升序，额度快照过期账号排在新鲜账号之后但仍可尝试。
- 决定每个逻辑请求最多尝试三个不同账号。只有尚未向客户端输出任何字节时才允许切换；流式响应一旦输出就固定账号，后续失败只结束流并记录结果。每次尝试及最终逻辑结果都落库。
- 决定 OAuth 上游 `401/403` 只自动刷新一次，重试仍失败则标记授权失效；第三方 `401/403` 直接标记授权失效。请求或模型语义导致的其他 `4xx` 不降低健康度且不切换账号。
- 决定明确额度耗尽时暂停账号对应范围至重置时间并触发额度刷新。`429` 优先遵循 `Retry-After`；缺失时从 60 秒冷却开始指数增加，最长 15 分钟。网络错误或 `5xx` 连续三次后熔断 60 秒，后续指数增加至最长 15 分钟；熔断结束只允许单个探测请求，成功后清零。
- 决定全部候选不可用时返回统一 OpenAI-compatible 错误和稳定的 `no_available_upstream` 机器码，不泄露过滤细节中的账号信息。

### SQLite、加密与日志

- 决定共享数据库固定为 `~/.config/onespace/data/onespace.sqlite3`。本次只迁入新网关数据；现有 JSON/app_store 和 Protocol Router 数据保持原位且行为不变。
- 决定共享 bootstrap 启用 WAL、`foreign_keys=ON` 和明确的 `busy_timeout`，通过全局 `app_schema_migrations(subsystem, version)` 在事务中协调迁移。明确不把单一 `PRAGMA user_version` 作为唯一迁移标识，以免未来模块发生版本冲突。
- 决定所有网关业务表使用 `ai_gateway_` 前缀。敏感值按记录使用 AES-256-GCM、随机 nonce、密文版本和绑定记录类型及 ID 的 AAD 加密。根数据加密密钥通过 `keyring` 存放在 macOS Keychain，不复用 `.local_key`。
- 决定 Keychain 项缺失但数据库已有密文时进入锁定状态，停止网关和敏感操作并引导重新授权或重新录入；不得静默生成新根密钥覆盖可解密性。仅在全新、无既有网关密文的初始化中创建根密钥。
- 决定日志只保存结构化元数据，不保存请求/响应正文、提示词、工具参数、Authorization、Cookie、Token 或 API Key。日志中的账号和网关 Key 使用内部 ID加名称/标识快照，确保实体删除后仍可审计。
- 决定明细默认保留 90 天，并支持 7、30、90、180 天或永久。后台批量清理和适度 SQLite 维护不进入请求链路；手动清空使用后台事务任务。每日聚合长期保留，完成请求后实时增量更新，并提供按明细重建及校验的维护命令。
- 决定按公开模型维护每百万输入、输出、缓存读和缓存写 Token 单价。内置官方价格快照可随应用更新，第三方账号可覆盖；请求日志固化当时的单价和计算结果，后续改价不追溯。OAuth 费用明确标为公开 API 单价的等效预估，不代表订阅扣款；用量或价格缺失时保存不可计算状态，不写 `0`。

## Implementation Changes

### 1. 建立共享 SQLite 与安全基座

- 在 Tauri 后端建立应用级 SQLite bootstrap、连接管理和迁移执行器，由 `src-tauri/src/lib.rs` 与 `src-tauri/src/app_runtime/run_app.rs` 在网关运行时之前初始化。
- 初始化 `~/.config/onespace/data/onespace.sqlite3` 的父目录和数据库，统一设置 WAL、foreign keys、busy timeout，并创建以 `(subsystem, version)` 唯一标识的 `app_schema_migrations`。每版迁移在单事务内执行，失败不写版本记录并保持前一版本可用；并发初始化通过数据库锁和幂等检查收敛到一个结果。
- 建立 `src-tauri/src/ai_routing_gateway/` 独立 Rust 模块。模块按 `commands`、`storage`、`runtime`、`oauth`、`router`、`protocol`、`usage`、`pricing`、`types` 和 `tests` 分责；额度刷新作为 `usage` 内的明确子边界。任何代码不得落入或依赖 `protocol_router` 的内部实现。
- 使用 `keyring` 管理网关根数据加密密钥，封装 AES-256-GCM 逐记录加密。参考 `src-tauri/src/secrets.rs` 和 `src-tauri/src/crypto.rs` 的错误处理与敏感值习惯，但建立独立 key service、版本、AAD 和锁定状态，不复用 `.local_key`。

建议的数据实体与关系固定如下：

- `ai_gateway_settings`：单例网关设置，包括端口、全局额度阈值、日志保留策略和运行开关；端口值只允许 loopback 服务使用。
- `ai_gateway_groups`：分组名称、排序和默认组标识；数据库约束保证仅一个默认组且默认组不可通过业务命令删除。
- `ai_gateway_accounts`：稳定账号 ID、类型、名称、所属分组、排序、备注、启用状态、健康状态、最近使用时间及账号阈值覆盖；分组为必需外键。
- `ai_gateway_tags` 与 `ai_gateway_account_tags`：标签及账号多对多关联；无路由权限语义。
- `ai_gateway_credentials`：账号一对一的凭据密文、nonce、加密版本和元数据；OAuth 与第三方字段使用带类型的加密载荷。
- `ai_gateway_models`：统一公开模型目录、显示信息、能力和启用状态。
- `ai_gateway_account_model_mappings`：账号、公开模型、实际上游模型、上游协议和启用状态的唯一关联。
- `ai_gateway_quota_windows`：账号动态额度窗口、名称、上游标识、百分比、重置时间、时长、范围、最后成功刷新时间和过期状态；账号删除时级联删除。
- `ai_gateway_api_keys`：Key 内部 ID、名称、前缀、哈希验证材料、创建/最后使用时间、启用、失效和撤销时间。
- `ai_gateway_api_key_groups` 与 `ai_gateway_api_key_models`：Key 对多个分组及多个公开模型的授权关联。
- `ai_gateway_request_logs`：逻辑请求、时间、Key ID和名称快照、账号名称/标识快照、公开/上游模型、推理强度、端点、最终状态、耗时、Token 分项、价格快照、费用或不可计算原因及错误类别。
- `ai_gateway_request_attempts`：请求一对多的账号尝试、顺序、账号快照、起止时间、上游状态、错误分类、是否输出流字节、冷却/熔断影响和最终结果。
- `ai_gateway_model_prices`：公开模型及第三方覆盖范围下的输入、输出、缓存读、缓存写单价、币种、来源和生效时间。
- `ai_gateway_daily_aggregates`：本机日期、时区标识、账号/分组/公开模型维度及 Token、请求状态和可计算费用汇总；保留必要快照维度以承受账号删除。

为请求日志、尝试和每日聚合建立时间索引，并建立账号、公开模型、上游模型、最终状态、错误类别和 API Key 维度的组合索引；为账号分组/排序、模型映射、额度作用域与重置时间、Key 哈希查找和授权关联建立查询索引。外键删除行为必须与“账号业务数据删除、历史日志和聚合保留快照”的规则一致。

### 2. 实现账号、OAuth、额度与价格领域

- 实现分组、标签、账号和模型目录的事务命令。创建账号自动关联默认分组；删除组时批量迁移账号；账号永久删除要求前端二次确认令牌并由后端事务校验后删除凭据、额度和映射，避免仅靠 UI 防护。
- 实现第三方账号录入与更新，校验 Base URL、鉴权方式、上游协议和模型映射；API Key 在离开 invoke 边界后立即加密，任何读取接口只返回“已配置”和可安全展示的元数据。
- 实现 OAuth 内存授权会话管理。loopback 监听只绑定本机随机可用回调端口并打开系统浏览器；手动回调复用会话；Device Code 按服务端间隔驱动状态机。成功后用稳定账号 ID 原子 upsert 账号和凭据，失败、取消、过期及应用退出统一清理临时材料。
- 实现 OAuth token 刷新互斥，确保同账号并发请求只发生一次刷新；刷新结果原子替换密文，失败按授权错误类型更新健康状态。
- 实现额度抓取、上游限额元数据合并、动态窗口规范化和作用域匹配。调度器在登录、手动刷新、请求完成及默认五分钟周期触发，同账号并发合并，失败指数退避并保留最后成功快照。
- 实现全局阈值与账号继承/覆盖计算、窗口恢复、未知窗口展示和首页聚合口径。阈值保存事务提交后发布状态事件，使前端刷新且路由器下一请求立即采用新值。
- 初始化官方价格快照并提供模型价格维护命令；第三方覆盖与默认价格按明确优先级解析，请求开始时取得不可变价格快照供完成日志使用。

### 3. 实现网关 Key、路由和协议服务

- 实现网关 Key 创建、一次性明文响应、验证、重新生成、禁用、撤销、过期及分组/模型授权事务。鉴权中使用恒定时间比较或库提供的安全验证，认证成功后异步更新最后使用时间。
- 实现独立 runtime，持有数据库、安全状态、HTTP server、OAuth 会话、额度调度器和路由健康状态。runtime 提供幂等启动、优雅停止、端口预检和受控重启；运行状态通过独立 Tauri 事件发布。
- 实现 `/health`、`/v1/models`、`/v1/responses` 和 `/v1/chat/completions` 路由。服务只绑定 `127.0.0.1`，限制请求头与结构化 JSON 的合理大小，且任何诊断都先脱敏。
- 实现候选快照、作用域额度判断、稳定排序、最近使用更新、每请求最多三个账号和切换门禁。健康状态机分别管理授权失效、额度暂停、`429` 冷却、网络/5xx 连续失败、熔断和单探测。
- 建立 Responses 与 Chat Completions 的内部规范化请求/事件/响应模型。先做能力校验，再选择同协议透传或双向转换；SSE 输出在首字节前保留切换能力，首字节后将账号固定。错误分类同时映射外部兼容 envelope、路由健康影响和内部尝试日志。

### 4. 实现日志、聚合和维护任务

- 在逻辑请求入口生成请求 ID并记录不可变的 Key、模型、端点和价格上下文。每次账号调用写独立尝试；最终完成、上游失败、客户端取消和流式中断均写逻辑结果。
- Token 统一为输入、输出、缓存及总量；无法从上游取得的字段保持缺失语义。价格计算使用请求上下文快照，固化输入、输出、缓存读和缓存写单价及结果；任一必要数据缺失即记录不可计算原因。
- 请求完成事务同时写最终日志并增量更新本机时区的每日聚合。查询层为 7/15/30 日序列补齐缺失日期零值，但费用不可计算状态不被补成已知零费用。
- 实现按时间、账号快照、分组、公开/上游模型、状态、错误类别和 Key 的筛选及稳定游标分页。手动清空、保留期清理、适度维护、聚合重建与校验在后台批处理执行，不占用请求热路径。

## Public Interfaces

### HTTP 接口

- `GET /health`：无需认证，仅返回服务状态和应用/网关版本；不返回账号数量、端口以外配置、数据库路径或错误堆栈。
- `GET /v1/models`：要求 Bearer 网关 Key；返回该 Key 的分组与模型授权交集内，且当前至少存在一个可路由账号映射的公开模型。
- `POST /v1/responses`：要求 Bearer 网关 Key；接受受支持的 OpenAI Responses 请求，支持流式/非流式、工具、reasoning 和用量语义。
- `POST /v1/chat/completions`：要求 Bearer 网关 Key；接受受支持的 OpenAI Chat Completions 请求，支持流式/非流式、工具、推理强度和用量语义。
- 认证至少支持 `Authorization: Bearer <gateway-key>`。无效、禁用、撤销、过期或权限不足分别返回稳定机器码；所有错误使用 OpenAI-compatible `error` envelope。
- 稳定错误类别至少覆盖认证失败、权限不足、模型不可用、无可用上游、不支持的无损转换、请求无效、上游限流、上游授权失效、上游暂时不可用和网关未就绪。错误消息不得包含账号、凭据或内部存储信息。

### Tauri IPC 与事件

- IPC 命令按独立 `ai_routing_gateway_*` 命名空间分为：运行状态与设置；账号/分组/标签；OAuth 授权会话与 Device Code；额度刷新与阈值；模型目录与映射；网关 Key 与授权；请求日志与尝试；价格；统计与维护。
- 所有写命令使用明确输入 DTO、后端校验和事务；所有输出 DTO 只含前端所需的非敏感字段。凭据读取永不返回明文，网关 Key 明文只存在于创建或重新生成的一次性成功 DTO。
- 事件至少分为运行状态变化、OAuth 会话状态、额度/账号状态变化和后台维护进度。事件负载携带稳定实体 ID和状态，不携带 token、code、PKCE verifier、API Key 或请求正文。
- `src/lib/aiRoutingGateway.ts` 是前端唯一命令字符串和事件名入口，为五页签提供带类型的 facade。

### SQLite 与配置契约

- 共享数据库位置固定为 `~/.config/onespace/data/onespace.sqlite3`；`app_schema_migrations` 以 subsystem+version 管理全局迁移，网关 subsystem 使用稳定名称 `ai_routing_gateway`。
- 所有网关业务表以 `ai_gateway_` 开头；其他子系统不得依赖网关私有表，网关迁移不得修改未知表或现有独立数据源。
- 网关设置的持久化权威来源是 `ai_gateway_settings`。默认端口为 `17688`、绑定地址固定为 `127.0.0.1`、默认阈值为 `10%`、默认日志保留期为 90 天。
- 加密载荷契约包含算法版本、随机 nonce、密文和 AAD 所需实体上下文；Keychain 中的根密钥与数据库密文必须成对存在。已有密文但根密钥缺失时状态为锁定。

### UI 导航契约

- 主导航目的地名称为“AI 路由网关”，与 Protocol Router 同级并保留各自入口。
- 模块内页签顺序固定为：首页、账号池、网关密钥、请求日志、设置。
- 账号详情是额度窗口和模型映射的唯一编辑入口；首页只展示聚合，设置页管理全局阈值、端口、保留和价格。
- 导航、页签、状态、错误和确认文案全部通过 i18next；组件使用现有 Tailwind/Radix/Lucide 约定。

## Data Flow and Failure Modes

### 启动与停止

1. 应用后台进程初始化共享 SQLite，设置连接参数并执行事务迁移。
2. 安全层读取 Keychain 根密钥；全新且无网关密文时创建，已有密文却缺失密钥时进入锁定。
3. runtime 读取设置、检查 `127.0.0.1:<port>` 占用并启动 HTTP 服务、额度调度器和维护调度器。
4. 数据库失败、Keychain 锁定或端口冲突时不启动服务，向 UI 发布稳定错误且不循环抢占。
5. 完全退出或端口变更时先停止接收新请求，等待在途请求和日志事务排空，再释放监听器；端口变更随后绑定新端口。

### 请求鉴权、候选与上游

1. HTTP 层生成请求 ID，限制输入大小，解析 Bearer Key，并用存储的加盐哈希/验证材料完成安全验证。
2. 鉴权层检查 Key 的启用、撤销和失效时间，再取得授权分组及公开模型；失败直接返回兼容错误，日志只引用 Key 内部 ID与名称快照。
3. 协议层解析端点请求并执行能力校验；不能无损表达的字段在访问上游前返回 `400`。
4. 路由层按 Key 权限、账号启用、凭据有效、模型映射、健康和适用窗口阈值过滤候选，再按用户排序、额度新鲜度、最低剩余比例和最近使用排序。
5. 协议层按账号上游类型透传或转换请求；响应按客户端协议转换。日志同时保留公开模型与实际上游模型。
6. 非流式调用或尚未输出的流式调用可依据错误分类切换账号，最多三个；首个流字节发出后不再切换。
7. 全部候选被过滤或尝试失败时返回统一 `no_available_upstream` 或对应稳定兼容错误，不暴露候选清单。

### 流式、健康与失败切换

- SSE 转换器必须保持事件顺序、工具调用增量、reasoning、用量和结束原因；客户端断开会取消上游并记录取消，不将其计入上游健康失败。
- OAuth `401/403` 触发一次互斥刷新并重试；再次失败标记授权失效。第三方 `401/403` 直接授权失效。请求或模型类 `4xx` 返回客户端，不降健康度、不换号。
- 明确额度耗尽写入对应窗口暂停至重置并触发刷新。`429` 按 `Retry-After` 或 60 秒起始指数冷却，最长 15 分钟。
- 网络和 `5xx` 连续三次触发 60 秒熔断，后续最长 15 分钟；到期只放行一个探测，成功清零，失败重新熔断。
- 每次尝试均记录是否已输出流字节、错误分类和健康影响，最终逻辑请求记录统一状态。

### OAuth 与额度刷新

- 浏览器授权的 state、PKCE verifier 和回调状态保存在内存会话中。loopback 自动回调与手动完整 URL 进入同一校验函数；state 不匹配、过期、取消或上游 error 会终止并清理会话。
- 自动回调监听失败不会立即销毁会话，用户仍可在有效期内粘贴完整回调 URL。成功兑换 token 后按稳定账号 ID upsert，并立即触发额度刷新。
- Device Code 按服务端间隔轮询；pending 保持，slow_down 增加后续间隔，expired/取消终止并清理，应用退出清理所有会话。
- 登录、手动请求、上游请求完成和默认五分钟调度进入同账号刷新合并器。失败保留最后成功窗口、标记过期并指数退避；过期只降低排序。
- 上游返回未知窗口时保存原始标识和规范化名称；有范围时进入路由判断，无范围时仅展示。重置或刷新达到阈值后自动恢复后续候选资格。

### 日志、费用与聚合

1. 请求开始时固化 Key 名称、账号选择上下文、公开模型、价格和本机时区信息，不保存正文。
2. 每次账号调用写尝试记录；请求完成后写逻辑请求的最终账号快照、上游模型、状态、耗时、Token、费用和错误类别。
3. 同一完成事务增量更新每日聚合；聚合键覆盖本机日期、账号/分组快照和公开模型。查询 7/15/30 日时生成连续日期并补零。
4. 价格或用量缺失时费用状态为不可计算；已有可计算零用量才可显示零费用。改价只影响后续请求。
5. 保留期清理、手动清空、聚合重建和校验在后台批次执行。清理失败回滚当前批次并报告，不阻断网关请求。

### 存储与安全故障

- 迁移失败时整版事务回滚，不写 schema version，网关保持停止；并发迁移由锁和版本检查防止重复执行。
- SQLite busy 超过 timeout 时返回可分类的暂时存储错误；请求日志提交失败必须被诊断，不能伪报已记录，退出排空会等待或明确超时。
- Keychain 暂时不可访问时网关保持停止或锁定，不缓存到磁盘；Keychain 项永久丢失时不得生成新密钥覆盖旧密文，UI 引导对各账号重新授权或重新录入。
- 解密认证失败、AAD 不匹配或未知加密版本会将对应凭据标记不可用并阻止路由，错误日志只记录安全类别和实体 ID。
- 任何 tracing、IPC、HTTP 错误、请求日志和测试 fixture 都必须通过敏感字段审查，禁止记录正文和凭据。

## Testing Decisions

### Rust 存储与安全测试

- 使用临时 SQLite 覆盖全新首建、逐版本升级、迁移中途失败原子回滚、重复执行、两个初始化器并发竞争、WAL/foreign_keys/busy_timeout 生效及未知未来表不受影响。
- 验证默认组唯一且不可删除、删除非空组迁移账号、账号永久删除级联凭据/额度/映射但保留日志与聚合快照，以及时间、账号、模型、状态和 API Key 查询索引被实际查询使用。
- 使用隔离 keyring 测试替身覆盖根密钥首建、加载、暂时不可访问、已有密文时密钥丢失、禁止覆盖和重新录入恢复路径。
- 对 AES-256-GCM 验证随机 nonce、相同明文不同密文、AAD 绑定、篡改失败、版本解析和敏感错误脱敏；验证不复用 `.local_key`。
- 验证网关 Key 熵、明文只返回一次、加盐哈希验证、错误 Key、重新生成、禁用、撤销、过期、权限关系和日志无明文。

### OAuth 与额度测试

- 使用本机 mock server 和 fixture 覆盖授权 URL 的受控端点、PKCE challenge、固定 scope、state 成功/失败、code/error 解析、loopback 回调、自动回调失败后的手动完整 URL 及会话清理。
- 覆盖 Device Code 的代码与地址、倒计时、服务端轮询间隔、pending、slow_down、expired、取消、成功、应用退出和临时材料不落库。
- 覆盖 token 刷新并发合并、成功替换、一次重试、失败授权失效，以及同一稳定账号 ID再授权更新且不重复建号。
- 使用 fixture 覆盖标准 5 小时+7 日、仅 7 日、Code Review、Spark、已知范围与无范围未知窗口；验证登录、手动、请求完成和五分钟刷新触发、并发合并、指数退避、最后成功快照及过期降级。
- 对 `0`、`10`、`100` 阈值、继承和覆盖、等于阈值、低于阈值、自动恢复、基础窗口耗尽、附加能力限制、阈值即时重算和不终止在途请求做边界测试。
- 验证首页 5 小时/7 日算术平均的分母规则、仅 7 日账号、缺窗口 OAuth、第三方账号及按名称独立的附加窗口聚合。

### 路由、HTTP 与协议测试

- 使用不依赖公网的 Rust loopback mock upstream 覆盖 Key 分组/模型授权、账号启用、凭据、映射、健康和适用窗口过滤，以及用户排序、同序额度最低值、过期降级和最近使用的稳定排序。
- 覆盖 OAuth 与第三方 `401/403`、明确额度耗尽、带/不带 `Retry-After` 的 `429`、连续网络/`5xx`、熔断递增、最长 15 分钟、单探测恢复、请求/模型 `4xx` 不降级。
- 验证首字节前切换、首字节后禁止切换、客户端取消、每请求最多三个账号、每次尝试与最终结果记录，以及候选耗尽的统一错误。
- 对 `/health` 的最小匿名响应、三个受保护端点、Bearer 认证、权限不足、Key 立即失效、`/v1/models` 权限与可路由交集做 loopback 集成测试。
- 建立 Responses 与 Chat Completions 双向 fixture 矩阵，覆盖非流式、SSE 事件顺序、工具调用增量、reasoning/推理强度、输入/输出/缓存/总用量、结束原因、上游错误和兼容 envelope。
- 对能力矩阵中的不可无损字段验证请求在上游调用前返回明确 `400`，并验证同协议路径不发生不必要的语义重写。

### 日志、统计与费用测试

- 验证每个逻辑请求和每个账号尝试的字段、账号删除后快照可读、公开/上游模型并存、推理强度、耗时、错误类别及 Key 仅存内部 ID/名称快照。
- 使用敏感标记 fixture 扫描数据库、tracing 和 IPC 输出，确认请求/响应正文、提示词、工具参数、Authorization、Cookie、OAuth token 和 API Key 明文均不存在。
- 覆盖 7/30/90/180 天与永久保留、默认 90 天、后台批量清理、手动清空、事务失败回滚及请求链路不执行清理。
- 冻结本机时区和跨日/夏令时边界，验证实时增量、7/15/30 日查询、缺失日期补零、账号/分组/模型筛选、聚合重建和校验。
- 覆盖输入、输出、缓存读、缓存写价格，官方默认与第三方覆盖优先级，请求时快照、改价不追溯、OAuth 等效预估标签，以及价格/用量缺失为不可计算而非零。

- 使用 Tauri mock 验证 typed invoke facade 的命令输入、输出、错误映射和事件订阅清理；验证一次性 Key 明文不会进入持久前端状态或日志。
- 使用 Vitest 与 Testing Library 覆盖主导航独立入口、固定五页签、账号详情、分组/标签/排序、删除确认、OAuth 三种交互路径、额度与阈值、Key 权限和失效、日志筛选分页及设置状态。
- 覆盖首页账号总数、可用/不可用进度、额度聚合、今日 Token K/M 格式、不可计算费用、7/15/30 分段、Token 四视图、独立费用视图、账号/分组/公开模型筛选和缺日补零。
- 验证 i18next 中英文键完整、导航状态可恢复、加载/空/错误/Keychain 锁定/端口冲突/受控重启状态均有明确文案，Protocol Router 导航与页面行为不变。
- 使用 Rust 生命周期测试覆盖数据库先于服务、Keychain 未就绪、端口冲突不重试抢占、自动启动、运行中改端口受控重启、完全退出拒绝新请求并完成在途日志。
- 执行项目现有 TypeScript 类型检查、ESLint、Vitest、`cargo test`、`cargo check` 和构建类命令。当前未授权浏览器自动化、E2E 或视觉验证，因此 Playwright 和可见浏览器不作为必做验收；发布前人工/视觉验证必须另行获得明确授权。

## Rollout and Compatibility

实施与发布按以下依赖顺序推进，每阶段保持新导航和服务运行开关可控：

1. 共享 schema 与 security：落地 SQLite bootstrap、事务迁移、网关表、Keychain 和加密，并先通过存储/安全测试；此时服务与入口保持关闭。
2. 账号、OAuth 与额度：开放内部 IPC 测试账号、官方 OAuth、第三方账号、模型映射和额度状态；官方 Codex OAuth 合法接入条件不满足时停止发布，不启用替代抓取方案。
3. 路由与 protocol：启用 loopback HTTP 服务、Key 鉴权、候选健康状态机和 Responses/Chat 双向转换，先使用 mock upstream 完成协议及故障矩阵。
4. 日志统计与 UI：接入请求/尝试日志、费用快照、每日聚合、首页和五页签，完成导航/i18n 和前端测试。
5. 生命周期与回归：启用随应用自动启动，验证端口冲突、Keychain/数据库故障、受控重启、优雅退出、现有模块回归和构建门禁后发布。

兼容与迁移规则：

- 不存在旧 AI 路由网关数据迁移。现有 JSON/app_store 和 Protocol Router 数据不读取、不写入、不迁移。
- 新共享数据库只增加 `app_schema_migrations` 和 `ai_gateway_` 表，不删除或修改未知未来模块表；后续 schema 只使用前向兼容事务迁移。
- 默认只监听 `127.0.0.1:17688`，不会扩大现有网络暴露面；已有端口占用只导致新网关停止，不影响应用其他功能。
- 数据库备份单独迁移到另一台设备时，因 macOS Keychain 根密钥不随数据库迁移，原凭据不可解密；用户必须重新授权 OAuth 和重新录入第三方 API Key。历史非敏感日志和聚合在 schema 兼容时仍可读取。
- 发布阻塞条件包括官方政策/流程不允许第三方桌面客户端使用 Codex OAuth、关键协议转换矩阵未通过、敏感数据落日志、Keychain 丢失会覆盖旧密文或生命周期无法保证 loopback-only。

回滚规则：

- 运行时回滚先通过开关停止网关并隐藏 AI 路由网关入口，不影响 Protocol Router 和其他模块。
- 代码回滚不得删除 `onespace.sqlite3`、`app_schema_migrations`、`ai_gateway_` 表或任何未知未来模块表；保留网关数据以便修复后恢复。
- schema 不实现破坏性逆向迁移。若新版本不可用，旧代码忽略未知前向表/列，服务保持关闭，并通过后续前向迁移修复。
- 回滚或退出时仍执行优雅停止并提交已完成请求日志；未完成流按取消或中断记录。

## Out of Scope

- 改造、重命名、合并现有 Protocol Router，或迁移其配置、统计和运行状态。
- 将其他 OneSpace JSON/app_store 或模块数据迁入共享 SQLite。
- LAN/public 监听、TLS、CORS、远程访问和多用户服务。
- Anthropic 或 Gemini 原生协议；本次只提供 OpenAI-compatible Responses 与 Chat Completions。
- Cookie 导入、网页抓取、`chatgpt.com` 页面解析或以浏览器会话模拟 OAuth。
- 自定义 OAuth issuer、client ID、scope 或非官方 Codex 登录流程。
- 保存完整请求/响应正文、提示词、工具参数或任何认证凭据。
- WebSocket 协议。
- 核对真实 ChatGPT 订阅账单；OAuth 费用只提供公开 API 单价的等效预估。
- 未明确要求的数据导入或导出。
- 未经另行明确授权的浏览器自动化、E2E 和视觉验证。

## Assumptions

- 首发平台为 macOS，使用 macOS Keychain；实现仍保持 Rust 安全边界清晰，但本计划不承诺其他平台的凭据存储支持。
- 应用运行于本机单用户桌面环境，网关只服务 loopback 客户端，不承担远程多租户隔离。
- OpenAI 官方 Codex OAuth 对第三方桌面客户端的合法、政策和技术接入许可是发布前提；不满足时阻塞发布。
- OneSpace 后台进程在应用启动期间持续存在，并能提供 Tauri invoke/event、HTTP runtime 和优雅退出生命周期。
- 上游 OAuth 额度接口或响应元数据可能出现新增窗口；动态窗口与作用域模型用于兼容新增数据，但无作用域未知窗口只展示、不影响路由。
- 本机时区是每日统计的权威分桶时区；历史请求保存当时的时区/日期归属，之后修改系统时区不重写既有聚合。
- 官方价格快照代表公开 API 定价，第三方覆盖由用户维护；二者都不是实际订阅账单。
