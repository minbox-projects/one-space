## Outcome

OAuth 账号具备动态额度窗口、范围门禁、继承或覆盖阈值和可靠刷新状态，且每个请求可取得不可变的模型价格快照。

## Implementation Checklist

- [ ] 实现全局、模型、端点和能力额度窗口的解析、规范化、存储和适用范围匹配。
- [ ] 覆盖 5 小时、7 日、Code Review、Spark 及已知或未知范围窗口的确定性规则。
- [ ] 实现登录后、手动、请求完成后和默认每五分钟触发的刷新合并器及有上限指数退避。
- [ ] 实现全局 `0-100%` 阈值和账号继承/覆盖，保存后立即影响后续候选但不终止在途请求。
- [ ] 实现额度过期、耗尽、重置自动恢复和首页额度聚合口径。
- [ ] 初始化官方价格快照，实现第三方覆盖优先级和请求开始时的不可变价格解析。

## Acceptance Criteria

- [ ] 基础窗口任一适用窗口耗尽会暂停普通请求；附加窗口只限制对应能力。
- [ ] 未知窗口有范围时参与门禁，无范围时仅展示；过期快照只降低排序、不直接停用账号。
- [ ] `0`、`10`、`100`、等于阈值、低于阈值、继承、覆盖和自动恢复边界均有测试。
- [ ] 同账号并发刷新被合并，失败保留最后成功快照并标记过期，退避时间有明确上限。
- [ ] 首页 5 小时和 7 日平均值严格遵循分母规则，附加窗口按规范化名称分别聚合。
- [ ] 官方默认与第三方价格覆盖按确定优先级解析；后续改价不会改变已取得的请求价格快照。
- [ ] 用量或必要价格缺失时费用状态为不可计算，不得写为 `0`。

## Verification Steps

- [ ] 执行额度 fixture 和阈值边界测试，覆盖刷新触发、并发合并、退避和恢复。
- [ ] 执行首页额度聚合口径测试。
- [ ] 执行价格优先级、快照和不可计算语义测试。

## Out of Scope

不解析 `chatgpt.com` 页面，不核对订阅账单，也不实现请求日志和费用聚合。
